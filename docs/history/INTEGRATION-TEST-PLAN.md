## 2. The example: "Marketplace Trust & Payments"

One project that exercises every feature, with enough data that charts, filters and pagination are meaningful. Build it **through the UI** wherever a UI exists; seed only what has no UI (bulk historical runs).

**Backend (3 modules, ~12 routes)**
- `refunds.py` (hand-written, from the CRUD template then edited): list/get/create/update/approve/stats; `approve` rejects amounts over a threshold with 422; `stats` calls an external balance API through `studio.nodes.http_request` with `studio.secret("PAYMENTS_TOKEN")`.
- `disputes.py` — **generated by the real LLM** from a prompt ("Ingest Stripe-style dispute webhooks idempotently by event id, store them, list open disputes, and close one with a reason"), then **refined** ("add GET /disputes/summary with counts by status and total disputed amount"). Exercise the inline AI flow: step log, streamed explanation, diff, **Keep**, then **Undo** once and redo.
- `customers.py`: lookup by id/email, a risk score that calls an external host (exercises the **egress allowlist**: one allowed host, one blocked → readable error and a run with a stack trace).

**Data (4 tables)**: `customers` (~200 rows via **CSV import** with column mapping), `refunds` (~60 rows created through routes), `disputes` (via webhook route), `events` (audit, written by the workflow).

**Secrets**: `PAYMENTS_TOKEN` set in dev only (prod missing → release blocker), `STRIPE_WEBHOOK_SECRET` in both, `RISK_API_KEY` project scope with an allowed host.

**Apps (2, built with the real LLM in the app builder)**
- "Refunds console": refunds table with filters, approve action, stats tiles; uses `refunds.*` routes.
- "Disputes board": open disputes with close action and summary; uses `disputes.*`.
- Pick routes with the **route picker**, try calls in the **API tester**, iterate in chat at least twice, **publish** both; the published apps must render real data and reflect a backend change after Refresh.

**Workflow**: "Refund triage" — webhook trigger → AI classify node (real Gemini: label + confidence) → if/else → call `refunds.create` route → insert into `events`; else branch → leave "needs review". Run it from the editor (test run), via its webhook (curl) and on a schedule if supported. One deliberately failing input produces a failed run with a traceback.

**Releases & settings**: add a `staging` environment; Release sheet: **Check code → Secrets (fix PAYMENTS_TOKEN inline) → Review routes → Promote** to prod; verify prod serves the release; create v2, then **roll back** to v1. Create an **API key**, call an `api_key` route with it, revoke it, confirm 401.

**History**: ~300 historical runs across 30 days (script against the run/test endpoints, mixed success/failure, both envs) so the 24h timeline, 30-day grid, filters, range presets and "Load older" are exercised.

## 3. Test layers

### A. Deterministic regression (fake LLM, isolated stack) — must be green before anything else
- Run the existing 10 specs (51 tests) and `capture.spec.ts`.
- **Fix the known flake:** `10-code-map.spec.ts:94` ("native map: drafts…") failed twice in two days and passed on rerun. Find the race (likely analysis debounce vs. assertion) and make it deterministic; run it 20× (`--repeat-each=20`).
- **Add `11-design-features.spec.ts`** covering what the redesign added and no spec checks yet:
  - Data: CSV import (dropzone/file → preview → mapping → progress → rows exist via API); delete with **Undo** restores rows; Columns menu hides a column and persists across reload; filter chips update total/profile; relative "created" time with exact time on hover (`data-ts`).
  - Runs: inline expand (click/↵), j/k selection, ⇧↵ opens `run-sheet`, range presets, status segment counts, stack trace frame click navigates to `/backend/<module>?line=N` and the editor shows that line.
  - Backend: AI flow Keep then Undo restores the previous source (`composer-applied-undo`); route picker search filters and keeps `test-route-option-*`; request-path art shows a call after Send.
  - Shell: ⌘K palette footer and navigation; ⌘P project switcher search; ⇧R opens release (ignored while typing); sidebar active item follows navigation (`[data-active]`); Workflows list renders inside the workspace (sidebar present, `tab-workflows` active).
  - Overview: Snippet URL/curl/Python copy (clipboard permission), stat tiles navigate, 30-day grid cells carry `data-date/count/failed`.
  - Projects home: template creates project **and its table** (`items` exists, CRUD routes return 200); "Describe it instead" navigates to `~new?generate=1&prompt=…`; sticky top bar gets `data-scrolled` after scrolling; HomeSky exists only on `/projects` and `/` (no `home-sky` on project pages).
  - Release sheet: stepper states (`data-state`), inline secret fix moves Secrets to done, beam visible only while promoting.
  - Liquid glass: in Chromium with motion on, `[data-liquid]` exists on the segmented thumb and the sidebar lens and the backdrop filter is `url(#lg-…)`; with `reducedMotion: 'reduce'` it is absent and the plain fill is used.
  - Theme: both themes for every scenario above (parametrise), body/canvas colours from tokens (`rgb(8, 9, 10)` dark, white light).
- Keep the policies: no console errors/warnings, no unexpected 4xx/5xx, layout clipping at 1440/1280/1024.

### B. Live scenario (real Gemini, opt-in, billable)
- Add `apps/workflow-engine/tests/live/run_marketplace.py` + `marketplace.cjs`, following `run_banking_app.py` (isolated DB, real sandbox, strict console policy, artifacts under `screenshots/marketplace/`, not committed).
- Drive §2 end to end in the browser; after each step **assert backend state through the API** (routes, tables, row counts, secrets presence without values, releases, app definitions, run records), never just UI text.
- Retries: provider errors (quota, high demand, malformed tool output) get at most 2 retries per step and are reported, not hidden; a step that only passes on a retry is flagged.
- Check secret values never appear in generated source, app bundles, run logs or responses.
- Record per step: duration, LLM calls, tokens if available, pass/fail, screenshot (both themes for the final state of each page).

### C. Visual review
- Capture every page and key state in both themes at 1440×900 with motion on (liquid glass rendered) using the Marketplace project: Projects home (scrolled and not), Overview, Backend (all three modes, AI flow mid-run and applied), Data (selection, columns, import sheet), Runs (expanded failed row, sheet), Secrets, Workflows list, editor (idle, running, node details), App builder (chat, API tester, version history, publish), Release (each step), Settings (each section), ⌘K, menus, switcher, toasts, landing.
- Review against `DESIGN-STANDARD.md` and the owner's taste notes: neutral Linear-style greys, no navy, blue only for meaning, flat charts with crossed-line fills, stars only on the top band of Projects home and landing, glass only on floating layers.
- Publish a gallery artifact; list every defect with page, theme, severity.

### D. Non-functional
- **Cross-browser smoke:** run A's shell + data + runs scenarios in Firefox and WebKit if Playwright browsers are available locally (liquid glass must fall back cleanly; no console errors).
- **Reduced motion / reduced transparency:** no liquid glass, no rolling digits, no packets; everything still readable.
- **Performance:** first load of `/p/<slug>` and `/projects` (LCP), liquid-glass map build time (log `glassMap` ms; budget < 15 ms per size on a typical laptop), Runs page with 300 runs scrolls smoothly, no long tasks > 200 ms on navigation.
- **Accessibility smoke:** keyboard-only pass of sidebar, tabs, segmented controls, menus, dialogs, sheets; visible focus everywhere; tooltips reachable; `aria-label`s on icon buttons. Optional: `@axe-core/playwright` if the owner allows a dev dependency.
- **Lint:** bring `npm run lint` back to the pre-rollout count (96) or below; most new findings are fast-refresh advisories (move helpers out of component files).

### E. Fix loop and exit criteria
- Every failure becomes an issue with repro steps; fix, add or adjust a test, rerun the affected layer, then the full A suite.
- **Exit when:** A is fully green 3 runs in a row; B passes end to end once without any retried step (or with retried steps explained as provider-side); C has no high-severity defects; D has no errors in any browser tested; lint ≤ 96; `design:check` clean; E2E.md updated with the new spec counts and the live results; MAPPING.md and HANDOFF notes updated.
