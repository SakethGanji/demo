## What works

**Backend**
- `POST /api/runs/{id}/ensemble` `{models}` → 201. Wraps `predictor.fit_weighted_ensemble(base_models=…)` in its own
  process (`app/engine/custom_ensemble.py`, `python -m app.engine.custom_ensemble <run_dir> <request.json>`) because it
  writes a model into the predictor folder; the API then drops its cached predictor. One per run at a time (a lock).
  Returns the weights, `scores` (val and holdout, natural units, fit time, predict time per row), `best_single`,
  `best_chosen_single`, `run_best` and `vs_best_single` / `vs_run_best` = `{beats, delta, delta_natural}` on validation
  and holdout. The run's `model_best` is **not** changed (AutoGluon would switch to the new ensemble if it scored higher
  on validation; we restore it). The new ensemble is appended to the run's leaderboard (`custom: true`, re-ranked by
  validation) and to `custom_ensembles`. Names: `WeightedEnsemble_L2_Custom1`, `_Custom2`, …
  - Refit presets (good/high quality keep only `_FULL` copies that can predict): the ensemble is fit with
    `refit_full=True`; validation comes from the bagged model, holdout from its `_FULL` copy, and `predict_model` names
    the copy to predict with. `_FULL` and `WeightedEnsemble*` base models are refused with a 400 and a reason.
- `GET /api/runs/{id}/holdout-predictions`: row, y_true, y_pred and per-class probabilities of the best model on the
  holdout (from `holdout_predictions.csv`). The UI recomputes metrics from it (bootstrap CIs, residuals).
- `column_types` on `POST /api/runs` (`{col: number|category|text}`): the worker casts the columns and passes AutoGluon a
  `FeatureMetadata` built from the data with the overrides (text → special type `text`). Recorded in
  `resolved.fit_kwargs.feature_metadata` as JSON plus a note. `fit_kwargs.feature_metadata` may also be given as JSON
  (`{type_map_raw, type_group_map_special}`) and is turned into a `FeatureMetadata`. Bad column, the label, or both forms
  at once → 400.
- **`make dev` keeps running fits across reloads.** uvicorn watches only `backend/app` and `backend/ensemble_models`.
  With `ENSEMBLE_DEV_RELOAD=1` (set by `make dev` and `make api`): workers watch the reloader's pid (the API process's
  parent) instead of the API; on shutdown the API leaves running workers and queued runs alone; on start it adopts live
  workers (watches the pid, cancel works) and re-queues queued runs. Verified by hand with real `uvicorn --reload`
  (touch a file mid-fit → "adopting worker …", the run succeeds, one `run_started`, no `run_failed`; Ctrl+C on the
  reloader → the worker exits within a second) and by `tests/test_dev_reload.py`. Without the variable, S2's behaviour
  (in-flight runs failed on restart) is unchanged and still tested.

**UI: New Model (route `#/quick-train`, title "New Model"; Quick Train's old recipe flow is gone)**
1. **Dataset**: unchanged from S1 (samples or upload, profiled by the API), plus regression labels shown with ȳ, σ_y and
   range. Continue works for regression now.
2. **Target**: label picker (any non-text, non-ID column); problem type inferred (`profile.task` for the dataset's
   target; otherwise number with > 50 values → regression, 2 values → binary, else multiclass) with an override limited
   to what the column allows; y ∈ {c₁…c_K}, p̂ ∈ Δᴷ⁻¹ or y ∈ ℝ with every symbol defined; class shares with ρ = n_max/n_min
   or the label's range bar (ȳ ± σ, median). Every column's type is editable (number / category / text / ignore) with the
   AutoGluon raw type and special type it maps to, and a live preview of the `FeatureMetadata(...)` / `drop_columns` sent.
3. **Goal**: metrics for the task, each with its formula, direction and definitions (ROC AUC recommended for an
   imbalanced binary label, ρ ≥ 4); the preset ladder medium → good → high → best with speed/accuracy dots, k (bag folds),
   L (stack layers), refit and what AutoGluon does under each; τ on a log fret slider (30 s … 60 min); an Advanced fold-out
   with raw `fit_kwargs` JSON (validated; snippets for bagging, stacking, trees only, excluding NNs) and the resolved
   `TabularPredictor(...).fit(...)` call.
4. **Train (the race)**: the navy stage. One Harmonic Thread string per model: it rings while fitting and is plucked when
   it finishes, settling taut from the left pin to its validation score on a shared axis (right = better, ticks in the
   metric's units), fold scores as beads, μ ± σ as a band, readout `μ ± σ n = k` ("out-of-fold" for bagged models with a single out-of-bag child such as random forests, and for
   ensembles; "val split" without bagging), fit
   time. Layers per stack level (L₁ base learners with n and d, L₂ stackers, the weighted ensemble), skipped configurations
   counted per layer. When the `ensemble` event arrives the strings merge into one (thickness ∝ wₘ; zero-weight models
   stay apart, dashed) and ŷ(x) = Σ wₘ fₘ(x) is written with the real weights and a where-list. Clock t / τ with an
   over-budget segment; best so far; models done / started; a stage line (fitting, ranking, scoring). Beside it: the fit
   as AutoGluon sees it (n, n_h, d, k, metric, dropped columns, notes) and AutoGluon's own log.
   - **Readable pace**: each model stays "fitting" on screen ≥ 1.4 s (≥ 0.47 s at 3×). Events from before the page
     connected are applied at once, so a resumed run catches up instantly and then plays live.
   - **Resume**: the URL becomes `#/quick-train?run=<id>`; a reload or a link reopens the run (race if running, results if
     done) and replays its events from 0. `followRun` now reopens the stream from the next unseen seq if EventSource gives
     up (API down → proxy 503), and drops duplicates; the stage shows "stream lost · resuming by replay" meanwhile.
   - Cancel Run calls the API.
5. **Results**: a navy hero (holdout metric, problem type, n, models, fit time, predict time per row, the stack equation);
   four metric cards in the maths style (formula, definitions, and a 95% percentile-bootstrap CI recomputed in the browser
   from the holdout predictions, B = 300, seeded; the point value is the API's); the leaderboard (rank, model, family, L,
   validation μ ± σ with n, holdout, fit, predict per row, ensemble weights; the run's best highlighted with ★, the best
   holdout score in bold, custom ensembles tagged "yours"); validation-vs-holdout scatter with y = x; the selected model's
   family objective and symbols from `GET /api/models` plus its hyperparameters; the confusion matrix with recall and
   precision per class, or residuals (histogram with the 90% band, ŷ vs y scatter, quantiles, largest misses); top words
   per class for the TF-IDF models (model switch); **Build my own ensemble** (pick base models → weights, equation,
   a val/holdout comparison table against the best single model and the run's own best, Δ, and a plain verdict that says
   when the gain only holds on validation); **Try a prediction** (a form from the run's features: number inputs, category
   selects from the profile's top values, a text area for text; prefilled with the profile's examples; choose any model,
   including your ensemble's predict copy; class with probability bars and Σ p̂ = 1, or the value with ŷ ± 1.96·σᵣ from
   the holdout residuals, labelled as such; missing columns listed).
- **Mock mode** plays a simulated AutoGluon run (`race/mockRun.ts`) through the same race and results; the stage says
  SIMULATED; custom ensemble and prediction say they need the live API.
- Home's toolkit and button say New Model.

## What doesn't / not done

- The ensemble merge draws the run's last `ensemble` event (the best one). Runs with several weighted ensembles (multi-
  level stacking) show only that one merging; the others appear as rows in their layer.
- Bagged runs show fold beads and μ ± σ only where S2's events carry `fold_scores` (bagged models). The ensemble row has
  no folds.
- DyStack (`best_quality`) sub-fit events are ignored by the race (they're a rehearsal); during that phase the stage just
  shows the clock and the wave. `best_quality` overshoots τ by DyStack's share; the clock turns amber past τ.
- With many skipped configurations (`best_quality`, zero-shot portfolio) they're collapsed into "+ N skipped" per layer.
- The preset ladder's speed/accuracy dots are ordinal guidance, not measured numbers. k and L read "(auto)" because
  AutoGluon sets them from the data.
- Prediction intervals for regression are ± 1.96·σᵣ from the holdout residuals (normal approximation), labelled as such;
  no quantile regression yet.
- Mock mode: no custom ensemble, no prediction (no fitted models in the browser), no TF-IDF top words.
- The Vela sidecar still shows its old mock patches on this page.

## Notes for S4 (Understand)

- `GET /api/runs/{id}/holdout-predictions` gives y_true, y_pred and probabilities: ROC/PR/calibration and the threshold
  slider can be computed from it (see `results/stats.ts` for the metric code that matches AutoGluon's evaluate(): AUC
  by ranks, balanced accuracy, F1 with `run.positive_class`, RMSE/MAE/R²). The e2e tests already assert RMSE equality.
- The Results step (`src/features/quick-train/results/`) is where S4's Explain tab can hang off, or S4 can reuse its
  pieces from Experiments (`Leaderboard`, `ScoreScatter`, `ModelCard`, `ClassReport`, `Residuals`, `TopWords` are
  self-contained; move them to `shared/` when a second page uses them, per the folder rules).
- Runs are started with `feature_importance: false` from the wizard to keep the end of the race snappy;
  `GET /api/runs/{id}/feature-importance` computes it on demand (≤ 60 s).
- Custom ensembles live in `run.custom_ensembles` and on the leaderboard with `custom: true`; predict with
  `predict_model` (the `_FULL` copy on refit presets).
- Open a run in the wizard with `#/quick-train?run=<id>` (e.g. from Experiments).
