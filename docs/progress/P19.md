## What was built

| Piece | Where | What it does |
|---|---|---|
| **Identity** | `authz/identity.py` | `Principal`, the `IdentityProvider` protocol and an ordered chain (`ENSEMBLE_IDP`, default `typed`).<br>**`TypedNameProvider`**: `X-Ensemble-Actor`, upserted into `principals` by identity key (P18's `ensure_principal`). When the header is missing, a body/query `by` (`actor`, `created_by`, `requested_by`) stands in: both are unverified typed names.<br>**`AgentProvider`** (always first, not configurable): `X-Ensemble-Internal: <hex name>.<HMAC>` signed with a per-process secret. Only the in-process client can produce it. A forged signature is ignored (→ 401 in enforce). |
| **Scope** | `authz/scope.py` | object → `(team, project)`: dataset version, run, project, team, model version, model name, batch, champion, dataset / version request, upload, autopilot, lineage node (`/annotations/{kind}/{id}`). An unknown id records no decision; the route answers its own 404. |
| **Policy** | `authz/policy.py` | `ACTIONS`: C §1.3 plus `data.match_confirm` / `data.purge` (§6.1), one `Rule(min, rr, admin, shared, anyone, self_ok)` per action key, 52 keys.<br>`decide()` returns `{allow, action, team, needed, role, reason}`. Roles rank viewer < member < maintainer < owner; risk_reviewer only where a row allows it; `principals.is_admin` where `admin`; `model.review` for maintainers if the team policy has `maintainer_can_review`; `team.create` for anyone only if tm_default's policy has `self_service_teams`.<br>`FOUR_EYES` + `decide_check()` (C §1.5) are there (see deviations). |
| **`require()` / `public()`** | `authz/deps.py` | One FastAPI dependency per route: `require(action, path(…)\|body(…)\|query(…), also=[…], when=variant(field, {value: action}), default=…)`.<br>The object is the first spec with a value. With no spec it is a platform action. A spec with no value scopes to tm_default (or to the platform, `default="global"`). `when` picks a stricter key from the body: `stage: Production` → `model.promote_production`, `role: owner\|maintainer` → `team.settings`.<br>**Modes** (`ENSEMBLE_AUTHZ`, **default `audit`**):<br>• `off`: nothing computed;<br>• `audit`: a denial writes `authz_would_deny` (team-scoped, hash-chained, decision JSON) and the request goes on with `X-Ensemble-Authz: would-deny <action>`;<br>• `enforce`: 401 without credentials, 403 `{code:'forbidden', action, team, needed, message}`, and a body `by` that is not the principal gives 409 "You are signed in as X". Each denial is audited as `authz_denied`.<br>Allowed decisions are not audited. |
| Middleware | `authz/middleware.py`, `authz/context.py` | Plain ASGI, outermost. It sets the request context in a contextvar (request id, headers, decisions) and adds `X-Request-Id` and the would-deny header. The principal is resolved lazily by the first `require()`, so a GET without a check never touches the DB for identity. |
| **Coverage gate** | `authz/coverage.py`, `GET /api/authz/coverage` | Walks the routes, including FastAPI 0.163's nested included routers. **Must carry a marker:** every non-GET route, plus every row-returning GET (`rows`, `grid`, `export`, `download`, `holdout-predictions`, `oof`, `shap`, `explain`, `top`, `scores`, `pool`, `stats`, `audit`, `diff`, `*.csv`).<br>Logged at start. `enforce` refuses to start if anything is uncovered. `?all=true` lists every route. |
| `POST /api/authz/check` | `authz/api.py` | `{action, object_kind?, object_id?, principal?}` → the decision, for the UI to grey out buttons. Asking on someone else's behalf needs an admin; in enforce mode a non-admin who asks gets 403. Marked `public()`. |
| **Team audit + chain** | `catalog/schema.py` (`audit()`, `audit_row_hash`, `verify_audit_chain`, `audit_link`), `authz/api.py` | **Every** `audit_log` insert now goes through `schema.audit()`: the catalog's own calls, the team rows (`teams_api._audit`) and the registry's (`RegistryStore.audit`).<br>**Filled on every row:**<br>• `team_id` / `project_id` / `object_kind` / `object_id`: from explicit columns, else from `details` (dataset → run → model version → project); a row that names no object (a refusal) takes the object this request was authorised against; else tm_default;<br>• `principal_id` / `auth` / `request_id`: from the request context, the agent's rows included.<br>**Chain:** per team. `row_hash = sha256(prev_hash + "\n" + canonical JSON of the 21 chained columns)`. The head is `catalog_meta['audit_head:<team>']`. The write lock is taken first, with a write to the head row, so two writers never chain onto one head.<br>**`GET /teams/{t}/audit`** (`action, object_kind, object_id, actor, from, to, format=csv, cursor, limit`; `audit.read`).<br>**`GET /teams/{t}/audit/verify`** → `{ok, rows, legacy_rows, head}` or `first_break`. It finds an edited row (it no longer re-hashes), a missing or inserted row (the `prev_hash` link breaks), an unhashed row after the chain starts, and a deleted tail (the last row ≠ the head). Rows from before P19 count as `legacy_rows`. |
| **Split check 3** (P09) | `lake/splitstore.py` (4 lines) | The `split_created` row's chain link is now verified with `schema.audit_link`. The row must re-hash, and the team's next row (or the head) must link to it. A broken link fails check 3. Before P19 it was reported only as "not written yet". |
| **Lists** (P18 hand-off) | `authz/lists.py`; one `return` per handler | `with_team(request, data, which)` in the handlers of these lists:<br>• `/datasets` (`main.py`);<br>• `/data/search`;<br>• `/runs` (light and full);<br>• `/registry`, `/registry/versions`, `/registry/summary`;<br>• `/projects`.<br>In `off` / `audit`, every row carries `team_id` + `team`, unfiltered. In `enforce`, rows outside `visible_teams()` (own teams + teams sharing to them; admins see all) are dropped, and `total` follows.<br>**`LIST_ROWS`, `annotate` and the `team_rows` middleware are deleted.** `DatasetSummary` declares `team_id` / `team`, so the response model keeps them (P18's OpenAPI gap). |
| **Agent principal** | `agent/tools.py` (`principal_headers`, used by `call`) | Every agent tool call carries the session owner's principal: "Vela agent on behalf of X" → X, signed. `require()` therefore applies unchanged: the agent can do exactly what its user can. Its audit rows get the user's `principal_id` and `auth='agent'`. |
| Decorators | 29 router files + `main.py` | **158 markers**: 157 `require()` and one `public()` (`/authz/check`). Every data, registry, champion, retention and admin route is covered, plus teams, runs and their analyses, the agent, LLM settings and the lake admin. The full map is `GET /api/authz/coverage?all=true`. |
| `teams_api.py` | P18's file | `require()` on create team (`team.create`), patch team (`team.settings`), members (`team.manage`, or `team.settings` for owner/maintainer roles) and `PATCH /principals/{p}` (`principal.manage`: self or admin). `authz_mode()` now reports `authz.mode()`, which is `audit` by default. |

## Deviations and notes for dependants

- **Router edits are decorators plus one import line.**
  - **The list handlers have one more change:** their `return` is wrapped in `with_team(...)`. That is the P18 hand-off,
    in `main.py`, `catalog/datasets_api.search`, `engine/api.list_runs` (2 returns), `registry/api` (3 lists) and
    `catalog/api.list_projects`.
  - **Files of running lanes**, with decorators only:
    - P22: `engine/api.py` (also the `list_runs` returns), `engine/active_learning_api.py`,
      `engine/learning_curve_api.py`, `featurelab_api.py`, `vela/api.py`;
    - P11: none of its files was touched (`engine/worker.py`, `lake/frame.py`, `engine/serving.py`, `vela/doctor.py`).
  - **New routes need a marker.** Any route P22 or later lanes add must carry `require()` or `public()`. `enforce` will
    not start otherwise, and `/authz/coverage` shows it.
- **Outside the P19 file list:**
  - `registry/store.py`: `audit()` now goes through `schema.audit()`;
  - `lake/splitstore.py`: check 3 (the P09 hand-off);
  - `schemas.py`: `team_id` / `team` on `DatasetSummary`. The dataset detail now shows `team_id: null`; only lists
    fill it;
  - `main.py`: `authz_api.install(app)` replaces the `team_rows` middleware.
- **Four eyes.** `authz.policy.decide_check` / `FOUR_EYES` exist. The existing decide paths (dataset requests, version
  requests, champions, admin reset, review, promote) still use `governance.same_person`, which is as strict, and were not
  rewired: their bodies belong to other lanes. Rewire them when each file is next touched, or in X4.
- **`/uploads` streams its body**, so its `require()` reads only the query (`parent_version_id`, `root_id`,
  `project_id`). A `project_id` sent as a multipart field scopes to tm_default for the decision. The handler still puts
  the dataset where the field says. **U lane:** send `project_id` in the query.
- **`team.create` is would-deny for non-admins** unless tm_default's policy sets `self_service_teams` (C §1.3). In enforce
  it is 403. **U lane:** grey out "New team" with `/authz/check`.
- **Member removal.** `DELETE /teams/{t}/members/{p}` needs `team.manage` (maintainer) at the route, whatever the
  target's role; owner and maintainer *grants* need `team.settings` (owner). The handler's last-owner rule still applies.
  Gating the removal of an owner by owners only needs the target's role, which a route-level variant cannot see.
- **Shares (P21).** `visible_teams()` and the `shared` rule read `shares` (active, grantee = one of the caller's teams)
  at the team level. P21 narrows this to the shared object and its scope (`certified` / `default` / `pinned`).
- **Audit volume in audit mode.** Every denied request writes one row: for example, every grid read by a non-member, and
  every anonymous write. Allowed decisions are not audited.
- **P23 (Postgres).**
  - The hash covers the stored **text** of `details` / `decision`. Keep them TEXT on `audit_log` (not `jsonb`, which
    reorders keys), or the copied rows stop verifying.
  - Copy `prev_hash` / `row_hash` and `catalog_meta.audit_head:*` verbatim.
  - Replace the write-first head lock with `SELECT … FOR UPDATE` on the head row (C §1.7).
- **Pre-P19 rows** are `legacy_rows`; the chain starts at the first P19 row per team. Old rows that P01 left with
  `team_id NULL` are in no team's chain. Every row written from P19 on has a team and a hash (`final_verify.txt`: 0
  without).
- **P20** can use `require("data.read_unmasked", …)` and `"data.export_unmasked"`; both keys exist. **T3** adds
  providers to `PROVIDERS` in `authz/identity.py`.
- **Scratch:** the data dirs, the venv, the old-head worktree and the API processes were in the session scratchpad and
  are removed.
