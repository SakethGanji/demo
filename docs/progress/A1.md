## A. The product is wrong (ranked)

### 1. CRITICAL: one click on "Apply N fixes" silently drops the strongest legitimate features

**What happened**
- On cc_fraud_200k, the Data Report flags V14, V12, V4, V3, V10 and V11 as "Leakage suspects … may be known only after the outcome" (medium). The only reason is that each has AUC ≥ 0.90 alone; these are the real fraud signal.
- Their decision-time boxes start unticked, which means "not known".
- The reviewer clicked the only primary button, "Apply 1 fix →" (meant to drop 1,866 duplicates).
- DataReport.tsx `apply()` calls `saveAnswers()` first. Afterwards:
  - GET /decision-time returns `known` false for all six;
  - the next run has `config.decision_time.dropped = [V14, V12, V4, V3, V10, V11]`.
- The only warning is a grey line: "Applying the fixes saves them too."

**What should happen**
- An AUC-only suspect is not leakage evidence.
- Don't pre-answer "not known".
- Don't save unanswered questions as a side effect of another action.

**Repro**
1. Upload cc_fraud_200k (target Class).
2. GET …/data-doctor.
3. Click dr-apply in the UI.
4. GET …/decision-time.
5. POST /api/runs on the fixed version, then read `config.decision_time.dropped`.

### 2. CRITICAL: a strong post-outcome column becomes "At the data's limit: tuning will not help"

**What happened** (telco_leak, run_b5cd4b4b, 120 s, the UI's run body)
- The Data Doctor says medium "Leakage suspect: plan_code". That part is good.
- Holdout AUC is 0.973, against 0.843 on clean telco.
- The Model Doctor's leakage check is "clear":
  - "No feature dominates … with a leak hint, none alone has AUC ≥ 0.97".
  - Headline: "At the data's limit (minor) … Tuning will not help".
- What's Missing:
  - "Irreducible error between 0.156 and 0.264 against a model error of 0.065: at least 100 % of the error is beyond these columns".
  - A model error below the lower bound of the irreducible error is only possible with a leak or train/holdout overlap.
  - Gap #4 is "Collect information that separates outcomes for plan_code = 3", the leak itself.
- Also: "train–holdout gap is within noise (z = 5.3)".

**What should happen**
- An open Data Doctor leak suspect that nobody has answered must count as a leak hint in the Model Doctor.
- A model error below the R* lower bound should raise leakage.
- No ceiling headline while a leak is open.

**Repro**
1. Upload telco_leak (target Churn).
2. POST /api/runs with `{drop_columns: [customerID], time_limit: 120}`.
3. GET /api/runs/{id}/doctor and read the headline, `checks[leakage]` and `missing_info.irreducible`.

### 3. CRITICAL: "clean the labels" cannot detect real label noise, and reports the opposite

**What happened** (562 flips planted, concentrated in Mailed check)
- Data Doctor label quality is low, "mostly where classes overlap": the same wording as on clean data.
- The Model Doctor lever is −0.0098 [−0.0176, −0.0025] AUC.
- The review's clean_labels step gives −0.0119 [−0.0184, −0.0056], "worse beyond noise", rejected.
- The plan concludes "the gain must come from new information".

**Independent check** (LightGBM, 5 splits)
- Dropping exactly the flipped training rows:
  - −0.041 AUC on the noisy holdout, which is what the product measures;
  - +0.035 AUC on the true labels.
- The holdout carries the same noise, so the gain can never show.

**What should happen**
- Report cleaning as unmeasurable on a noisy holdout, or measure it on reviewed holdout labels.
- Turn the concentrated error segment into a label-review hypothesis. The Doctor did find it: Mailed check, error 0.412 vs 0.230.

**Repro**
- GET /api/runs/run_39984f15/doctor
- GET /api/runs/run_39984f15/review/rv_19874614 (journal step 3)

### 4. CRITICAL: the review loop rejects Claude's correct leak hypotheses and leaves them out of the plan

**What happened**
- The review was POST /api/runs/run_39984f15/review with `{max_experiments: 3, max_minutes: 35}`.
- Claude's perceive and propose roles named exactly the plants:
  - svc_ticket_days and segment_score as possibly post-outcome;
  - customerID repeats that "could leak across the split";
  - TotalCharges as "really a number".
- The platform ablated four columns as one experiment: 0.8504 → 0.7991, Δ −0.0512.
- The verdict was "rejected: worse beyond noise". Removing a leak always lowers the score.
- "kept-honest" exists only for Doctor-named suspects, so a suspect raised by the LLM can only be rejected.
- The plan has no "confirm decision time" action.
- The duplicate-customer concern became "drop customerID":
  - that is a no-op, since the column is already ignored;
  - it was rejected as within noise, which reads as clearing the concern;
  - there is no group-split experiment.
- Reproduced with a single column (rv_1d370662 on run_b5cd4b4b):
  - "Ablate suspected leak plan_code" gives Δ −0.1297, rejected;
  - Claude also proposed "Segment by plan_code";
  - step 1, "serve Scorecard", came out equivalent, so the plan recommends a cheaper model of a leaky table.

**What should happen**
- A leak-test ablation yields a "confirm decision time" action whatever its Δ. A big drop is evidence for the leak.
- One column per ablation.
- Add a typed group_split experiment.

## Majors

### 5. Mostly-numeric columns with a few bad cells are typed "row ID" and dropped
- telco TotalCharges has 11 blanks. It is profiled as a category with 6,531 levels, and the Data Doctor says "Not features: TotalCharges (a row ID)", with the drop pre-selected.
- In telco_planted the same column instead comes out as a "proxy for gender, V = 0.966". That is a Cramér's V artefact, and it fed the LLM's reasoning.
- In mixed_types.csv, income has "n/a", "1e5" and "$12,000" in 5 % of its cells, and is typed as an ID and ignored. The result:
  - 298 "exact duplicates" (49.7 %);
  - 123 conflicting groups (81 % of rows);
  - a pre-selected "Apply 2 fixes →" that deletes half the table.
- **Should:** coerce mostly-numeric columns to numbers, with a coded-missing finding, and compute duplicates on all columns.

### 6. Subtle planted problems on real data are not found
- **telco_planted** (holdout AUC 0.850 vs 0.843 clean, despite 7 % flipped labels). Not reported:
  - svc_ticket_days;
  - segment_score (only as a "collect information" gap);
  - the 700 duplicated customers: no near-duplicate or entity finding, and train 0.973 vs holdout 0.850 is read as "overfitting, minor";
  - MonthlyCharges = −1;
  - acct_ref, which is used as a feature;
  - the label noise, other than as an error concentration.
- **house_planted:**
  - tax_assessment (ρ 0.89) is not called a leak, because the rule needs |ρ| ≥ 0.95;
  - the m² unit change is not found.
- **Fraud:**
  - the pence unit change is not found;
  - the time finding is "info", p = 3e-13, with no column named.
- There is no check for a column changing over time, even though both files have a date.

### 7. A "recalibrated" production version serves uncalibrated probabilities
- The recalibrate change is "better" on log loss (+0.0329 [+0.0225, +0.0439]), but its cost Δ is +18.9 [−9.5, +47.8], within noise. It was requested by Bob, approved by Carol and promoted.
- The new version (mv_bb8b9dd2) returns the same probability as v1 (0.78225). Only the threshold moved (0.251 → 0.160), and that is the same move the threshold change had just been refused for as noise (+20.9 [−9.5, +53.3] per 1,000).
- The description and audit claim log loss 0.4609 → 0.4281, which the served model does not achieve.
- **Should:** serve calibrated probabilities, or judge the request on the deployed threshold's cost and label it "threshold only".

### 8. What's Missing gains mostly measure segment size

| Oracle on | ΔAUC |
|---|---|
| Contract = Month-to-month (55 % of rows) | +0.082 (product: +0.098) |
| A random 55 % of rows | +0.047 |
| A random 44 % | +0.028 |
| Contract = Two year (24 %) | +0.010 |

- About 60 % of the headline gain is what any segment of that size would get.
- The requests are generic ("Collect information that separates outcomes for DeviceProtection = No …").
- Fraud: an 8k-row segment with 29 excess errors is "worth up to +0.255 AUC".
- Regression uses the top 20 % absolute errors, so the gaps are just the expensive houses.
- **Should:**
  - show each gain against a random segment of the same size;
  - use relative error for skewed targets;
  - drop gaps that are within noise of that baseline.

## Top 5 fixes (reviewer)

1. **Decision time**
   - Don't save unanswered suspects as a side effect of Apply, and don't pre-untick AUC-only suspects.
   - Treat an open Data Doctor suspect as a leak hint in the Model Doctor.
   - Raise leakage or overlap when the model error is below the R* lower bound.
2. **Leak ablations**
   - Don't judge them by "did AUC go up".
   - One column per ablation.
   - A drop beyond noise confirms the leak and becomes a confirm-or-drop plan action.
   - Add a typed group_split experiment, plus duplicate-entity and near-duplicate detection.
3. **Label noise**
   - Don't score cleaning on a holdout that carries the same noise; report it as unmeasurable, or use reviewed holdout labels.
   - Turn concentrated error plus cleanlab overlap into a label-review hypothesis.
4. **Type inference**
   - Coerce mostly-numeric columns to numbers, with a coded-missing finding.
   - Compute duplicates on all columns.
   - Read cp1252 and UTF-16.
   - Make the API drop the profile's ignored IDs.
5. **What's Missing calibration**
   - Show each gain against a random segment of the same size.
   - Use relative error for skewed regression.
   - Add a check for a column changing over time (unit changes).
   - Recalibration must deploy calibrated probabilities, or be judged on the deployed threshold's cost.
