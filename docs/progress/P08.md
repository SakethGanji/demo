## What was built

| Piece | Where | What it does |
|---|---|---|
| **Keyset pages** (R5) | `lake/pages.py` (new), `GET /datasets/{id}/rows` (`main.py`) | **The query.** `WHERE __row_id > :after [AND search/filter] ORDER BY __row_id LIMIT n` over the table's parts. Tables are sorted by `__row_id`, so DuckDB prunes row groups: 30–45 ms at 10M.<br>**With a search or filter**, two steps: the ids of the first n hits (only the searched columns are read), then those rows by `__row_id IN (…)`.<br>**Other modes.** `offset` jumps to a row position and reads only the part file that holds it (`file_row_number`), with no OFFSET scan. `sort` (+`desc`) is refused above 1M rows with `400 sort_refused` "filter first"; below that it is allowed. `columns=` narrows the columns.<br>**Response.** Rows carry `_row_id`; `next_after` pages on.<br>**G10 lookup.** `value=` (+`column`) keeps the old shape, now in DuckDB. |
| **Search** | `pages.search_where` | Case-insensitive "contains" (`ILIKE`, with `%`/`_` escaped). **`table_stats` narrows the columns:**<br>• a column with ≤ 20 distinct values (all known) is matched in Python and becomes an `IN`, or is dropped;<br>• an all-digit text column is skipped for a query with a non-digit;<br>• a query longer than a column's longest value skips that column;<br>• number / date / bool columns are searched only for number-, date- or bool-like text.<br>`q=st7` on the seed searches `note` only. `searched_columns` is returned. |
| **Count** (R5) | `GET /datasets/{id}/rows/count?q=&filter=` | Its own call with a 3 s budget (interrupt); `{count: null, timed_out: true}` when that runs out. The grid's `matching` uses the same budget. |
| **Filter preview** | `POST /datasets/{id}/rows/preview {filter, q?, limit, by}` | The edit compiler's whitelisted filter AST (`dataset_edit._C.where`, so §4.4 value checks apply: `1e30` on a BIGINT is `400 value_out_of_range`). Returns the first rows, how many match (3 s budget) and their share. Writes nothing; audited as `filter_preview`. |
| **Grid** | `GET /datasets/{id}/grid` (`datasets_api.py`) | Same response shape as before (`_row` = position, plus `_row_id`, `total`, `matching`), now from `pages`. New query params: `after`, `filter`, `sort`, `desc`, `table`. Column kinds come from the schema (`type` is added). |
| **`table_stats`** + profile job | `lake/stats.py` (new), `GET /datasets/{id}/stats` | **Keyed on `table_sha256`**, shared by every version that carries the table (a CSV-era table: `csv:<sha256>`).<br>**Per column:** n, nulls, missing, approximate distinct. Numbers add min / max / mean / std, 21 quantiles, median, a 20-bin histogram and the non-finite count. Text adds min / max length and `digits_only`. Dates add min / max. Text, bool, date and ≤ 50-distinct numbers add the top 20 values with `top_complete`.<br>**Cost:** one aggregate pass, one GROUP BY per low-cardinality column, one histogram pass per number column: 9.4 s at 10M × 13.<br>**The profile job:** a background thread (one at a time, job DuckDB limits), deduplicated by content.<br>• Every `VersionWriter.commit` schedules its new tables (`stats.after_commit`; one hook in `writer.py`).<br>• A read that finds no stats schedules them.<br>• `GET …/stats` returns `status: running` until they are ready; `wait=` (≤ 30 s) waits for them. |
| **Two-pass diff** (R6) + `diff_cache` | `lake/diff.py` (new), `dsets.diff`, `GET /datasets/diff?a=&b=&key=` (`main.py`), `GET /datasets/{a}/diff/{b}` | **Tables.** Compared by name: equal sha → unchanged; a removed and an added table with the same sha → renamed.<br>**Primary tables** (`method`):<br>• same root → `__row_id`;<br>• `key=col[,col]` → a confirmed business key (cross-root, CSV vs Parquet), which must be unique and non-null on both sides, else `400 key_invalid` with the first 10 repeated values;<br>• otherwise a **multiset row-hash** diff: added / removed only, "no key: changes appear as remove + add".<br>**Pass 1:** one ephemeral `hash()` per row, FULL JOIN on the key; only differing keys go to a temp table. **Pass 2:** `count(*) FILTER (… IS DISTINCT FROM …)` per column over the changed rows only.<br>**Equal table sha → "identical", no scan.**<br>**Cache.** `diff_cache(a_sha, b_sha, key)` (+ renamed columns in the key). Column statistics (missing, mean / median, top values, PSI) come from `table_stats` at read time, so a cached diff fills them in once the profile job is done (`columns_pending` until then).<br>**PSI:** numbers use a's deciles with both sides' CDFs read from their 21 quantiles; categories use a's top 20 + missing + other.<br>**Contract checks** reuse P06's `Matcher.contract` in SQL. **Samples:** up to 50 added / removed rows and changed ids by keyset, plus 5 changed rows cell by cell. The DL3 `edit` block is kept. |
| **dtype changes in the diff** (P07's note) | `diff._pair`, `schema.dtype_changes` | Every type change is listed in `schema.dtype_changes`; a family change is also in `type_changes`. **These columns are compared, not skipped:**<br>• the same family compares as that family (BIGINT→DOUBLE as numbers);<br>• text ↔ bool compares as yes/no (`"No"` = false);<br>• text ↔ number compares as numbers (`TRY_CAST`);<br>• anything else compares as text.<br>`compare` says how each column was compared. |
| **Light, paginated lists** | `db.list_datasets_page`, `GET /datasets?limit=&after=&project_id=&root_id=` | **Keyset by an opaque cursor** in the list's order: pinned samples first, then `created_at, id`.<br>A new covering index `ix_datasets_list (state, created_at, id)` serves the order and the count. It matters because `state` is a late column stored after the ~10 KB profile JSON, so filtering on it read every row.<br>Only the page's rows are read, with `n_cols` / `n_classes` taken by `json_extract`.<br>Without `limit` the old full list is returned, now from light columns. `/health` counts with `count(*)`. |
| **Lineage by `root_id`** (§7 risk 2) | `catalog/lineage.py` | **Tree:** the CTE is seeded with every version of the root (`WHERE id = root OR root_id = root`, at depth `version_no − 1`), so a version chain has no depth cap. Recursion continues only from those nodes, to runs, branches, registered versions and other roots.<br>**`root_of`** walks up only to the first dataset (`trained_on`, `branched_from`, `built_from`), then takes `root_id`. A cross-root `derived_from` edge on a root continues to that dataset's root. |
| **History** | `dsets.history`, `dsets.lineage_meta` | Versions were already listed by `root_id`. **`lineage.json` at 10M is 178 MB** (`root_rows` + `parent_rows`), and history and diff parsed it per version.<br>`lineage_meta` cuts those arrays out of the bytes before parsing and caches by size + mtime, so history at 10M takes 58 ms and a cached diff 21 ms (it was 1.8–2.4 s). |
| **Data Doctor** (task item 1) | `data_doctor.py`, `data_doctor_api.py` | P07's follow-up (97d7152) landed the same fix with the same signatures while this phase ran, so I took theirs in the merge:<br>• `label_key` / `label_state` / `start_labels` are keyed on the version id → `table_sha256`;<br>• the rows are read through `frames.read_version`.<br>Verified below on a fresh Parquet upload. |
| **10M request paths** (task item 3) | `datasets.split_options`, `main._intake`, `lake/stats.sample_frame`, `stats.split_columns` | `grid` and `rows` are covered above.<br>**`split-options`:**<br>• date columns are found on a deterministic 20k sample by `__row_id` arithmetic (`((id mod p)·7919) mod p < k`, engine-independent); their range and distinct count come from the whole table for DATE columns;<br>• entity columns come from whole-table counts (approximate distinct, then exact `count / max rows per value` in DuckDB for the candidates only);<br>• it takes 2.0 s (was 42 s).<br>**`intake`** runs on a deterministic 200k sample, marked `sampled` (3.6 s, was 17 s / 5.2 GB).<br>**`POST …/splits`** reads only the target column. |
| DuckDB runtime | `lake/duck.py` | `Interactive.query(bind=…)` registers a CSV-era Arrow table on the query's own cursor. `job()` fetches its setup result fully: DuckDB 2 refuses `register()` while a result is open. The progress bar is off, and the DuckDB 2 "Arrow output on a DB-API result" warning is silenced; the result is a page of at most 500 rows. |
| Small additions | `frames.data_identity`, `schemas.DatasetList` | `data_identity(version)`: `table_sha256`, or `csv:<sha256>`. `DatasetList` gets the optional `next_after` / `total`. |

## Deviations and notes for dependants

- **Files outside the row (small, all lane D):**
  - `lake/pages.py`, `lake/diff.py`: new;
  - `lake/writer.py`: the 3-line `after_commit` hook;
  - `lake/duck.py`: `bind`, the `job()` fetch fix, no progress bar;
  - `frames.py`: `data_identity`;
  - `datasets.py`: `split_options` only;
  - `schemas.py`: two optional list fields.

  **Not touched (P09's):** `splits.py`, `ensure_splits`, `verify`, `restore-splits`, `compare.py`. `split_columns` re-implements `date_and_group_columns`' group rule on whole-table counts rather than editing `splits.py`.
- **The profile job runs on an in-process thread**, not on the `jobs` table. P22 owns the queue: `stats.run(version_id, table)` is the job body, and `stats.after_commit` is where a `profile` job would be enqueued. §5.1 asks for stats in the commit job at ≤ 5M rows. Here every commit schedules them in the background instead, which takes about 9 s at 10M. `ensure(wait_s)` lets a caller wait for tables up to 5M rows.
- **Search at 10M is 0.40–0.43 s** with the interactive connection's 2 threads (B §5.1). The cost is a no-hit full scan of one text column. With `ENSEMBLE_DUCK_INTERACTIVE_THREADS=4` it measured 0.20–0.31 s in-process. I left the default as B set it.
- **Diff deviations:**
  - The DL2 (B5) step that paired leftover identical rows across sibling uploads is gone: on `__row_id` a row's identity is its id.
  - Cross-root diffs need `key=`; without one the diff is the multiset row-hash, as §5.4 says.
  - Samples are not masked: masking is P20's (`frames.scan(mask_for)`). The diff still audits `diff_rows` reads.
- **CSV-era versions** (samples, older uploads) are read through `frames.read_version` and bound as Arrow, bounded by the CSV store's sizes. Their `__row_id`:
  - pages: the position;
  - diff: `root_rows`, else the position for a root.

  P10's migration removes this branch.
- **Still a full pandas read on a request path, outside P08's files:**
  - `GET …/data-doctor` and Data Doctor apply (`data_doctor_api.py`, P07);
  - `POST …/edit` preview (P07);
  - Feature Lab;
  - `dsets._freeze_holdout` (a delete option).

  P11's training budget / sampling is the place for the Doctor's and Feature Lab's frames. The edit at 10M took 99 s end to end here; that is P07's path.
- **Old full list:** `GET /datasets` without `limit` still returns every version (1.15 s at 20k). The UI's `client.ts` calls it, so **U-lane: switch to `?limit=50&after=`** (the response has `next_after` and `total`).
- **For U-lane:**
  - the grid can page with `after` (its rows carry `_row_id`), filter with `filter=`, and show `matching_timed_out`;
  - the diff screen can show `tables`, `schema.dtype_changes`, `compare`, `changed_by_column`, `samples` and `columns_pending`;
  - `GET /datasets/diff?a=&b=&key=` is the new form.
- `ix_datasets_list` is created in `Database.__init__` (`CREATE INDEX IF NOT EXISTS`). P23 should carry it into the Postgres DDL.
- **Scratch:** the data dirs (including the 20k seeded rows and the chain), the seeded CSVs, the venv and the API process are deleted after the run.
