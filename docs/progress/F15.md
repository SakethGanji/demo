## What changed

**Engine (`backend/app/engine/shift.py`, new; its own process, `python -m app.engine.shift <job_dir>`).**
- R (o = 0) and N (o = 1) are stacked, and `TabularPredictor(label='__shift_origin', problem_type='binary',
  eval_metric='roc_auc').fit(num_bag_folds=5, num_bag_sets=1, num_stack_levels=0, hyperparameters={'GBM': {}},
  fit_weighted_ensemble=False, **fit_kwargs)` is fitted. Request `fit_kwargs` override all of these and nothing is capped.
  Text columns keep their type (`feature_metadata`).
- **AUC from `predict_proba_oof`** (every row scored by the fold model that did not see it), with DeLong's variance
  (midrank structural components) and a 95% CI.
- **Nulls:**
  - label permutation: B shuffles of o against the fixed OOF scores, two-sided p = (1 + #{|AUC₀ − ½| ≥ |AUC − ½|})/(B + 1);
  - refit null: the whole fit repeated R times on shuffled origins.
- **Verdict (fixed rule, for F17):** no shift if p ≥ 0.05 or |AUC − ½| < 0.02; otherwise slight < 0.60 ≤ moderate < 0.70 ≤ strong.
- **Shifting columns:** AutoGluon's `feature_importance(data=None, feature_stage='transformed_model')` on the bagged
  model, which scores each fold model on its own OOF rows. (`'transformed'` raises for bagged models in 1.6.3.) Results are
  mapped back to raw columns through `feature_generator.get_feature_links()` and get a 95% t-interval. A column is flagged
  "shifts" only when the verdict is a shift and its interval is above 0. Each column also gets its PSI
  (`registry/drift.feature_psi`) and its means in R and N.
- **Weights:** w = ŝ/(1 − ŝ) · n_R/n_N for each reference row, clipped at the 1st / 99th percentiles of w and normalised to
  mean 1. Reported: ESS = (Σw)²/Σw² (clipped and unclipped), a log₁₀ histogram, and the reweighted means of the top numeric
  columns (balance check).
- Files: `state.json`, `scores.csv` (set, origin, row, OOF p), `weights.csv`. The predictors are deleted after the job.

**API (`backend/app/engine/shift_api.py`, new router).**
- `POST /api/runs/{id}/shift`:
  - `{source: holdout | time | batch, batch_id, time_column, cutoff, include, exclude, null_refits (3), permutations (2,000),
    shuffle_sets (5), clip (0.01), time_limit, fit_kwargs}`;
  - one check at a time across the workbench (409 otherwise); 400 for bad sources, columns or cut-offs, the label in
    `include`, or < 20 rows a side;
  - the key is `holdout`, `time-<hash>` or `batch-<id>`, and a new check of the same pair replaces the old one.
- `GET /api/runs/{id}/shift` (checks + options: date columns, the default τ, this run's scored batches);
  `GET …/shift/{key}` (state, result, summary, actions); `GET …/shift/{key}/rows`; `POST …/shift/{key}/cancel`.
- `POST …/shift/{key}/weights-version`: the run's dataset with column `shift_weight` (w on the reference rows, 1
  elsewhere) as a dataset version with the same split and lineage (`add_column`), plus a Gym patch (`dataset_id` →
  version, `predictor_kwargs.sample_weight = 'shift_weight'`).
- `POST/GET /api/registry/batches/{bid}/shift`: the same check for a batch, against the training rows of the version's run.
- **Sources:**
  - holdout: R = every non-holdout labelled row (the drift reference), N = the labelled holdout;
  - time: R = rows before τ, N = rows on or after τ. τ defaults to the run's F6 out-of-time cut-off, else the date at the
    80th row percentile; undated rows are dropped;
  - batch: R = the drift reference, N = the batch's input file.
- **Columns left out, each with its reason in the response:**
  - the label;
  - the run's `drop_columns`;
  - profile `id` columns;
  - F6 entity columns;
  - every date column, and in a time check the cut-on date always;
  - columns that are only on one side.

  `include` can put any of these back except the label.
- **Actions:**
  - out-of-time: an F6 `split_spec` for `POST /runs/{id}/split-twin`;
  - drop: a Vela-style `make_patch` on the run's body, for the top 3 flagged columns;
  - weights: the endpoint above, with the ESS.
- The run payload carries `shift` (`shift/1`, the latest check). `admin/reset` refuses while a check runs.

## Open problems

- **Covariate shift only.** Credit-default's built-in drift is mostly in p(y | x) (base rate, weaker credit-score
  separation), so the period check says "slight" (0.525) while out-of-time validation costs 0.058 ROC AUC. F17 should read
  both: this check and F6's random vs out-of-time gap.
- **The importance interval is narrow.** It treats 5 shuffles × 5 fold models as 25 independent scores. Without a shift,
  some intervals lie above 0 (income_usd on train vs holdout). They are only flagged when the verdict is a shift.
- **The weights are partial.** On the ×2 batch, the reweighted training mean of debt_to_income moves from 0.271 to 0.393
  of the batch's 0.536: clipping and the LightGBM probabilities, which are not recalibrated, limit it. The weighted run's
  holdout ROC AUC (0.7679 vs 0.7720) is on the old holdout, not on the batch: there is no labelled shifted set to score
  it on.
- **Out of scope:**
  - "transform the feature" is described in the drop action but not generated as a patch;
  - no checks on forecast, anomaly or imported runs;
  - one check at a time (409 otherwise), and it is not queued with fits;
  - an API restart marks a running check failed.
- The smoke registers a version and scores two batches each time it runs, which adds registry entries to the workbench.
