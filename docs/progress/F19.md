## What changed

**(a) The default smoke runs everything.** `Makefile` `SMOKE_ONLY` and `scripts/smoke.py --only` now default to
`core,samples,autopilot,forecast,anomaly,import,fresh,latency,targets,splits,cost,monotone,quantile,reasons,scorecard,learning,active,annotators,shift,slices,doctor,monitor,llm,reset`
(added: active, annotators, shift, slices, doctor, monitor). Every section in `sections` is in the default.

**(b) Stale fast-tier tests updated to current behaviour** (no new tests):
- `test_runs.py`: the run payload's added keys (kind, split, forecast/anomaly/import, monotone, quantile, scorecard,
  F12–F17 summaries); a binary run now trains F11's `Scorecard` (leaderboard, SSE order, families, ranks 1–4,
  ensemble members, resolved `hyperparameters` + `SCORECARD`).
- `test_gym.py`: `SCORECARD` added by default for binary labels (resolved call, estimate families).
- `test_registry.py`: the build's `distill` step (F3); batch output adds `adverse` + reason-code columns (F10); the
  latency profile's size check compares the ensemble with its own members (the scorecard is not one).
- `test_samples.py` / `test_upload.py`: dataset `flows` and profile `target_source` (F4).
- `test_concurrency.py`: progress compared after rounding (0.85 arrived as 0.8500000000000001 then 0.85).

**(c) F3's latency checks test behaviour, not ratios.**
- "text: one-row latency + serve a faster model": the model to serve is one measured faster than the best, **or** one
  that needs fewer member models (an ensemble runs every member), or else the fastest other model. Then it asserts
  that Register serves exactly that model. Before: it failed when the best was a 1–2 model ensemble and the one-row
  p95s swapped under load ("no model faster than …", F10/F12 notes).
- "latency: register infer_limit 10 ms": the cross-measurement check (the version's 200-call τ₉₅ < the profile's
  ensemble τ₉₅, measured minutes apart) is replaced by checks within the register job's own candidate table (one
  measurement session): the chosen model is no slower than the run's best or a strict subset of it, and within λ when
  `met`. The served-version numbers are still reported.

**(d) The Model Doctor's latency prescription preselects `serve_model`.** `DoctorPanel` passes the prescription's
`serve_model` as `#/registry?register=<run>&serve=<model>`; `RegisterPanel` takes `initialServe` and selects it once
the run's latency profile has loaded (only for that run, only if the model is in the profile). Checked headless:
`…&serve=CatBoost` opens Register serving CatBoost (τ₉₅ 14.1 → 5.65 ms, ΔROC AUC −0.0023), screenshot `27`.
