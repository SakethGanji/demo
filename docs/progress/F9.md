## Cause

Round 1 listed `quantile` as a problem type, but nothing downstream handled its output. A quantile `predict()`
returns an n × L DataFrame, one column per level τ. Checked against the round-1 code with a real quantile predictor:
- `worker.save_holdout_predictions` raises `ValueError: Expected a 1D array, got an array with shape (n, 3)`. So
  **every quantile run failed** at the end of its fit.
- `serving.predict` raises `AttributeError: 'DataFrame' object has no attribute 'tolist'`.
- The same pattern sits in OOF, SHAP (`f` returns a 2-D array), the registry build (holdout predictions and bootstrap
  metrics), Try It, `/score` and batch scoring.

Nothing in the UI could ask for a range.

## What changed

**Engine (`backend/app/engine/quantile.py`, new).**
- Normalises the levels: sorted, distinct, each 0 < τ < 1. The default is [0.1, 0.5, 0.9].
- The centre level is 0.5, or the level closest to it. It is the point prediction ŷ wherever one number is needed.
- The intervals are the central pairs [τ, 1 − τ], plus [min τ, max τ] when that pair is not one of them.
- `evaluate(y, Q, levels)` returns:
  - per level: the pinball loss ρ̄_τ and F̂(τ) = share of y ≤ q̂_τ, with a Wilson interval;
  - per interval: coverage with a Wilson interval, the shares below and above, and the mean and median width;
  - the crossing share.
- `conformal(predictor)` returns AutoGluon's CQR offsets c_τ:
  - when AutoGluon applied them, `model.conformalize`;
  - otherwise, the offsets `trainer.calibrate_model()` would compute, using AutoGluon's own
    `compute_conformity_score` on the same rows (the validation split, or OOF when bagged).
  - **Check.** The offsets computed for the un-calibrated run (−34.26, 0, 589.08) equal the ones AutoGluon applied in
    the conformal run, to the last digit.
- `report()` reads the holdout three ways: served, raw (c = 0) and calibrated (+c). It adds every model's pinball and
  coverage, and the fan chart (holdout rows sorted by q̂₀.₅, at most 400 points).

**API.**
- `POST /api/runs` takes `quantile_levels` and `conformal`.
  - Levels make an `auto` problem type `quantile`. They are also accepted in `predictor_kwargs.quantile_levels`.
  - `conformal` is AutoGluon's `fit(calibrate=…)`, which is opt-in. Null leaves AutoGluon's `'auto'`, which turns
    calibration on only with ≥ 1,000 validation rows.
- `/gym/validate` resolves the same request and shows `quantile_levels=[…]` and `calibrate=…` in the fit call.
- These requests are refused with a 400 and a reason (13 cases in smoke):
  - a non-numeric label;
  - bad levels;
  - a non-quantile metric;
  - a cost;
  - a threshold metric;
  - distill;
  - pseudo-labels;
  - monotone constraints;
  - `conformal` on a non-quantile run;
  - `conformal` together with `fit_kwargs.calibrate`.

**Worker.**
- Passes `quantile_levels` and `calibrate`, with a note in `resolved`.
- Saves `holdout_predictions.csv` with y_pred = q̂₀.₅ and one `q_τ` column per level.
- Stores `result.quantile` (the report) and `quantile_levels`, and emits a `quantile` event.
- `export.py` reproduces a quantile run: 9 models, max |Δ score| = 0.

**Every path that assumed binary / multiclass / regression.**

| path | quantile |
| --- | --- |
| `/predict`, `/oof`, `/holdout-predictions` | `quantiles` (one value per level), `predictions` = centre level |
| Explain (`/explain`) | the regression report on q̂₀.₅, plus the quantile summary |
| SHAP (`/shap?target=0.9`) | explains any one level, f(x) = q̂_τ(x); an unknown level → 400 |
| Fairness | regression metrics on q̂₀.₅, plus **coverage and width per group** (by purpose: 0.76–0.82) |

**UI.**
- **New Model → Target.** For a regression label: "Predict: one value ŷ | a range [q̂_lo, q̂_hi]".
  - Guided: 80% / 90% / 50% ranges.
  - Advanced: any levels, and conformal recalibration (auto / on / off).
  - A formula panel defines q̂_τ, the nominal coverage and ρ_τ.
- **Goal.** The metric is fixed to the pinball loss. The code preview shows `problem_type='quantile'`,
  `quantile_levels=[…]` and `calibrate=…`.
- **Results.**
  - Range Coverage: the coverage as a big number, the formula with the run's counts, and a table of raw against
    calibrated coverage with the offsets.
  - Per Level: the pinball loss, F̂(τ) with its CI, and an F̂(τ) − τ bar.
  - The fan chart: bands, the q̂₀.₅ line, actuals inside and ✕ outside, and a hover tooltip.
  - Every model's range.
  - Try A Prediction returns the range.
  - The stack equation describes quantiles.
- **Registry.** Try It shows the range and every level. The model card has its section.
- **Experiments.** A `quantile` type filter, and the problem column reads "quantile · τ = … · cov …".

How to read the numbers:
- Raw coverage is 0.788 against 0.8, inside the Wilson interval of 0.8. Conformal recalibration widens the upper
  quantile by c₀.₉ = 589 and brings coverage to 0.807, at a cost of +4% width and +0.05% pinball.
- The calibration is fitted on AutoGluon's 640 validation rows. That is below AutoGluon's own 1,000-row 'auto'
  threshold, which is why it is opt-in here.
- The interval width grows with ŷ, as the data's noise (sd = 0.12·|mean| + 1,500) says it should. The fan chart shows
  it.

## Open problems

- **Conformal recalibration is a constant shift per level** (AutoGluon's CQR on the served model). It fixes average
  coverage, not coverage per segment. Fairness shows coverage per group, which ranges from 0.76 to 0.82 across
  `purpose` on the raw run. Per-group conformal (Mondrian) is not implemented.
- **The offsets of an uncalibrated run are what AutoGluon *would* apply.** With `medium_quality` they come from 640
  validation rows, so they are noisy. With bagging they come from out-of-fold rows, which is better.
- **Explain's SHAP tab explains q̂₀.₅ only.** The API (`?target=τ`) and the registry's Try It explain any level, but
  the Explain page has no level picker yet. The residual views read q̂₀.₅.
- **Latency.** The served ensemble on loan-amount includes the neural nets, so a one-row call takes ~200 ms
  (`/score` 239 ms). Registering with "serve fastest" or a single family is the remedy. Nothing quantile-specific was
  done for F3's fast path.
- **Refused, not supported:** business cost, decision threshold, monotone constraints, distillation and
  pseudo-labelling on quantile runs. Each gets a 400 with the reason.
- **Unrelated, seen but not fixed:** none new.
