## What changed

**Engine (`engine/annotations.py`, new).**
- Storage per run in `runs/<id>/annotations/`:
  - `annotations.csv`: long format (row, annotator, label, source, at);
  - `adjudications.json`;
  - `probs.npz` / `probs.json`;
  - `truth.json`: the sample only.
- **p̂(x) out of fold** for every training row, in its own process (`python -m app.engine.annotations <run_dir>`):
  - the run's own `predict_proba_oof` when it is bagged (the base model if the best is a `_FULL` refit);
  - otherwise a quick bagged fit of the run's call through F12's `prepare_fit` / `fit_predictor`: the same split, tuning
    slice, group folds, column types and text models, with `num_bag_folds = 5`, no stacking, one LightGBM plus the TF-IDF
    models. It takes about 35 s on tickets.
  - Training rows without a label (an F13 version) get the bagged ensemble's prediction; no fold saw them.
- **Analysis:**
  - cleanlab `get_label_quality_multiannotator(consensus_method=["best_quality", "majority_vote"], quality_method="crowdlab")`;
  - the posterior p̃ and the weights that chose each consensus, recomputed with cleanlab's own
    `_get_post_pred_probs_and_weights`, so the page can show them;
  - plain majority vote with seeded random tie-breaks;
  - Cohen's κ per pair (bootstrap B = 300) and Fleiss' κ with a varying number of raters per row (bootstrap B = 1,000);
  - per annotator: quality, weight, agreement with the consensus, mean κ, and the most frequent disagreement (consensus →
    label) from the confusion against the consensus;
  - truth metrics with Wilson CIs and exact McNemar when `truth.json` exists.
- **Sample annotators** (`SAMPLE_ANNOTATORS`, seed 14):
  - ana 0.96, ben 0.90 and chen 0.82: mistakes go to a look-alike class (`samples.CONFUSABLE`);
  - dara 0.55: a mistake is any class;
  - eli swaps Billing ↔ Account 60 % of the time and is 0.97 otherwise.

  The truth is `label_noise.json` (the given labels with the 300 planted flips undone). It is mapped through the lineage
  for versions of the sample.

**API (`engine/annotations_api.py`, new router).**
- `GET /api/runs/{id}/annotations?offset&limit&include=queue|all`: status, summary, annotators, pairwise κ, Fleiss parts,
  p̂ source, the queue page (votes, p̂ top 3, posterior top 3, consensus, q(x), majority vote, final), versions.
- `POST …/annotations/sample` (support-tickets only, else 400).
- `POST …/annotations/upload`:
  - multipart, `mode` replace / append;
  - rows by `row` or by a unique ID column such as `ticket_id`;
  - the annotator column may be named annotator / reviewer / rater; the label column label / annotation / the label's name;
  - 400 for unknown classes, missing columns or holdout-only rows; holdout rows are dropped and counted.
- `POST …/annotations/answer`:
  - `{reviewer, answers: [{row, action: vote | adjudicate | clear, label}]}`;
  - a vote is one more annotation under the reviewer's name;
  - the holdout is refused.
- `POST …/annotations/simulate-adjudication` (sample only; reviewer `simulated-adjudicator`).
- `POST …/annotations/version`: the final labels (adjudication, else consensus) of the annotated training rows as a dataset
  version through `DatasetStore.create_version`, with the same split record, lineage `relabel` changes with their source,
  `relabelled_holdout: 0`, and `holdout_unchanged` checked.
- The run payload carries `annotations` (`schema: annotations/1`, status, summary). `admin/reset` refuses while p̂ is being
  computed.

## Open problems

- **Simulated people.** The annotators' errors are independent draws from fixed profiles. Real annotators share confusions
  (the hard tickets are hard for everyone), so real gains over majority vote will be smaller. The numbers above are not a
  measurement of people.
- **The model carries much of the gain.** w_M = 1.58 is more than any annotator's weight (≤ 0.64). p̂ was trained on the
  dataset's own labels, which are 98.5 % right on these rows. It is out of fold, so a row's own label is not in its p̂, but
  a systematically wrong labelling of the training data would pull the consensus with it. A consensus without the model
  (`quality_method = "agreement"`) is not offered.
- **Majority-vote ties.** With 3 labels per row, 116 of the 1,500 rows tie and are broken at random. That is a large part of
  the 0.903; cleanlab's majority vote, which breaks ties with the model, reaches 0.963. Both are reported, and the consensus
  beats both.
- **Not wired in:**
  - F13's queue answers are not imported automatically (upload them, or vote here);
  - the queue does not pick rows for more labels by ActiveLab (`get_active_learning_scores`);
  - holdout annotations are dropped rather than used for κ.
- **Scheduling.** p̂ (a quick bagged fit) runs in its own process per run, beside any other work. It is not queued with
  runs, F12 curves or F13 queues. An API restart while it runs marks it failed; load the annotations again.
- **Small annotators.** An annotator with fewer than 30 labels is shown but not ranked as the least reliable. Its κ needs
  ≥ 10 shared rows per pair.
