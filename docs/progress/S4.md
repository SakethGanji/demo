## What works

**The decision threshold (the S3 credit-default problem)**
- S3's screenshot had holdout F₁ 0.106 and balanced accuracy 0.528 at t = 0.5 on 8% positives. Now the New Model
  wizard calibrates the threshold **for F₁ by default when the label's minority class is under 20%** (Goal step: a
  "Decision Threshold" card with t = 0.5 / F₁ / balanced accuracy / MCC, the reason, and the line
  `predictor.set_decision_threshold(predictor.calibrate_decision_threshold(metric='f1'))` in the resolved call).
  A user's `fit_kwargs.calibrate_decision_threshold` always wins (the card says so; the API skips its own step).
- credit-default (medium, 60 s): t = 0.182, holdout **F₁ 0.356, balanced accuracy 0.683** (0.131 / 0.535 at 0.5),
  AUC unchanged at 0.772. `good_quality` (refit, `WeightedEnsemble_L3_FULL`): t = 0.194, F₁ 0.347, bacc 0.663.
  The slow test pins F₁ ≥ 0.30, bacc ≥ 0.65 and the gains over 0.5.
- Engine: `POST /api/runs` takes `calibrate_threshold` (`f1`, `balanced_accuracy`, `mcc`, `accuracy`, `precision`,
  `recall`, or `auto` = F₁ when the training minority < 20%). After `fit()` the worker runs
  `calibrate_decision_threshold(metric)` (AutoGluon's own validation data: tuning split or OOF, never the holdout),
  `set_decision_threshold`, `save()`, emits `calibrating` and `threshold` events, and **reports every holdout metric at
  that t** (AutoGluon's `evaluate()` and the saved holdout predictions use it). If calibration ever raises, the run keeps
  t = 0.5 and logs a warning instead of failing. Every binary run records `threshold` =
  `{value, default, source (default | calibrated | manual | autogluon_auto | fit_kwargs), metric, holdout_at_default,
  holdout_at_threshold}`. Without the option nothing changes (parity with raw AutoGluon holds).
- `GET /threshold?cost_fp&cost_fn&t`: on the holdout, at every t on a 0.005 grid and at any exact t: TP/FP/FN/TN,
  precision, recall, F₁, specificity, FPR, balanced accuracy, accuracy, MCC, flagged share, cost
  C(t) = c_FP·FP + c_FN·FN; the maximisers, the cost minimiser, the Bayes threshold c_FP/(c_FP + c_FN), the score
  histogram per class. Positive means **p > t**, as AutoGluon predicts (`1 if pred > decision_threshold`).
- `POST /threshold {metric}|{value}`: calibrate or set, persisted in the predictor (`TabularPredictor.load` sees it,
  `/predict` uses it), holdout re-scored, saved predictions rewritten.
- UI (Explain → Threshold): t readout and slider (0.005 steps over the API's grid; the exact t is fetched when the slider
  rests; a number input for any t), chips for 0.5 / holdout max F₁ / max bacc / min cost, the 2×2 counts, seven
  metric tiles with Δ vs 0.5 and their formulas, the cost tile; "Calibrate threshold" (F₁ / bacc / MCC) and
  "Use t = …"; curves of precision, recall, F₁, bacc against t (click to move t), the score histogram split by the true
  class (√ scale) with t, the cost curve with its minimum and the Bayes line, and a default-vs-in-use table.

**Explain** (`#/explain?run=<id>`; from Experiments rows, New Model's results "Explain this model →", or its run picker)
- Navy strip: the run's holdout metric, AP or AUC (whichever is not the primary), Brier, log loss, t, mistakes; for
  regression σᵣ / MAE / R² / bias / the 90% miss band.
- **Performance**: ROC (AUC, the operating point at t, chance line), precision–recall (AP, prevalence line, operating
  point), reliability diagram (10 uniform bins sized by count, count bars, Brier with the ȳ(1 − ȳ) reference, ECE);
  multiclass draws one-vs-rest curves per class (switchable) with macro AUC and top-label calibration with the multiclass
  Brier. Confusion matrix at t and the per-class report (sklearn `precision_recall_fscore_support`). Regression:
  residuals vs ŷ with r̄ ± 1.96 σᵣ and the worst misses circled; the residual histogram with its normal fit and
  q₀.₀₅/q₀.₉₅.
- **Features & SHAP**: permutation importance (AutoGluon's `feature_importance` on the holdout; 5 shuffles on demand,
  "Tighten: 10 shuffles") with **95% t-intervals** Î ± t₀.₉₇₅,ₙ₋₁·s/√n and p-values; features whose interval clears 0
  are coloured. **Kernel SHAP** for one holdout row (`shap.KernelExplainer` on `predict_proba` of the class, or
  `predict` for regression; 50 background training rows from `shap.sample(…, random_state=0)`, 2048 coalitions, no L1
  selection; ≈1–3 s; cached per row in the run folder): quick picks (highest / median / lowest score, worst miss) or any
  row number, a class picker for multiclass, the equation f(x) = φ₀ + Σ φᵢ written out with the real terms, and the
  waterfall from φ₀ = E[f] to f(x) with every feature's value.
- **Errors**: the most confidently wrong rows (lowest p̂ of the true class) with p̂(y|x), p̂(ŷ|x) and all features;
  regression's largest |r| with |r|/σᵣ. "why? φ" opens SHAP for that row.
- **Fairness**: pick a group column (categories ≤ 50 values; numbers cut at quartiles; missing is a group): fairlearn
  `MetricFrame` per group (count, selection rate, base rate, accuracy, TPR, FPR, precision at the run's t), the gaps
  (demographic parity difference and ratio with the four-fifths rule, equalised odds difference, TPR gap), a dot plot
  per group against the overall value, and the MetricFrame table with max − min. Multiclass: accuracy and macro F₁ per
  group; regression: MAE, RMSE, bias, mean prediction.
- **Text** (text runs): the TF-IDF models' top words per class (`TopWords`, now shared).

**Experiments on real runs** (live; mock keeps its simulation, labelled SIMULATED)
- Filters: dataset, problem type (with counts), status, a floor (or ceiling for errors) on the run's own metric, search.
- Runs table: holdout and validation score in natural units (refit runs show their bagged original's validation), t,
  models, presets · τ, fit time, created; Explain / Results / Watch per row; refreshed every 5 s.
- **Parallel coordinates** over the comparable runs (same dataset, label and metric; a picker when there are several
  groups): τ, presets, k (bag folds), models, fit time, µs per row, t, validation and holdout metrics; constant axes
  dropped; selected runs in their own colours.
- **Compare** (≤ 6 selected): holdout metrics with formulas, best per row in bold, Δ vs the first run; ROC and PR
  overlays (PR marks each run's t) or residual distributions for regression; best validation score per model family;
  a warning when runs predict different labels.
- **Parameter Diff**: the exact resolved `TabularPredictor(...)` / `.fit(...)` arguments (flattened, presets as
  AutoGluon expanded them, our callback left out), the data, ENSEMBLE options and the results, side by side,
  differences tinted; "everything" shows all rows.

**No fake data on the pages touched**
- Live mode: the status bar shows `GET /api/status` (AutoGluon version, the active run with stage, models finished /
  started, best validation score and its clock against τ, link to it; queued count; run count; CPUs and memory; Python;
  ENSEMBLE version). The context bar's compute chip shows the host and CPU count. The sidebar shows "Local workspace ·

- Every number on Experiments and Explain comes from the API (curves, metrics, intervals, gaps, SHAP). No client-side
  maths beyond picking the nearest grid point and drawing.

**Shared pieces**: `XYPlot` (real-valued axes, staircase curves, bars, reference lines, labelled marks, snapping hover

## What doesn't / not done

- Explain works on the run's **best model** (the holdout predictions saved at fit time). Other models of the run,
  custom ensembles included, are not explained separately yet.
- SHAP uses Kernel SHAP on the whole AutoGluon pipeline (model-agnostic, exact additivity, ≈1–3 s per row on these
  samples). Very wide tables (d ≫ 11) get sampled coalitions; a text column is one feature.
- The threshold affects all of the run's models (AutoGluon has one predictor-level threshold); leaderboard `score_test`
  for threshold-dependent metrics was computed at fit time and is not recomputed when t changes later.
- The bootstrap intervals on New Model's metric cards are still computed in the browser from the API's holdout
  predictions (S3). Experiments and Explain compute nothing in the browser.
- Fairness is descriptive (MetricFrame and gaps at the run's t); no mitigation (ThresholdOptimizer, reweighing) yet.
- Calibration (Platt/isotonic of the probabilities themselves) is shown, not changed; AutoGluon's `calibrate` fit
  kwarg passes through.
- The stored post-fit importance (when a run asked for it) has 3 shuffles; on-demand uses 5; "Tighten" recomputes 10.
- SHAP and on-demand permutation importance run **in the API process** (thread pool). While they compute, other
  requests can slow down. This exposed an S3 race in the full suite: a run resumed from the URL could time out
  fetching its dataset and fall back to the built-in sample, and Try a Prediction then sent an all-missing row
  (UI "yes", API "no"; it failed 2 of 3 full runs). Fixed: resuming retries the fetch, Results fetches the run's own
  dataset when it holds another, and the form fills examples that arrive late. The e2e assertion now reports the
  request the UI sent. `make test-full` was green twice in a row afterwards. Moving SHAP and importance into worker
  processes (like custom ensembles) would remove the contention; not done.

## Notes for S5 (registry + use)

- `run.threshold` is what a registered model should carry into its model card ("t = 0.182, calibrated for F₁ on
  validation; holdout F₁ 0.356 / bacc 0.683; 0.131 / 0.535 at 0.5"). The predictor on disk already has it, so batch
  scoring and Try It through `/predict` use it automatically. The model card can quote `GET /explain` (AUC, AP, Brier,
  ECE, per-class report), `GET /fairness` for a chosen group, and `GET /feature-importance` (with intervals).
- Try It with reasons: `GET /runs/{id}/shap?row=` explains holdout rows only. For an arbitrary input row, reuse
  `explain.shap_row`'s inner function with the posted row instead of `df.loc[[row]]` (same background, same f).
- `GET /api/status` is the place to add registry counts for Home; the status bar polls it every 3 s through
  `useApi().status`.
- Experiments' row actions are where "Register" fits; `features/experiments/LiveExperiments.tsx` exports `primary`,
  `bestRow`, `bestVal`, `presetsOf`, `RUN_COLORS`.
- PSI drift: the holdout predictions (`holdout_predictions.csv`) are the reference distribution of p̂ / ŷ; the training
  frame is `data.csv` minus `splits.json`'s holdout.
