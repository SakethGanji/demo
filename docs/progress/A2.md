## Wrong, ranked

### C1 CRITICAL: neutral-name leaks are called "at the data's limit" offline and before any review, and What's Missing asks for more of the leaked columns

**Repro (telco_planted)**
1. POST /api/runs `{label: Churn, presets: medium_quality, time_limit: 60, fit_kwargs: {num_bag_folds: 0, num_stack_levels: 0}}`
2. GET /doctor
3. POST /review `{offline: true, max_experiments: 3}`

**What happens**
- The headline is "At the data's limit (minor)", and the leakage check is "clear".
- Yet the same check's text says svc_ticket_days holds 51 % and segment_score 38 %.
- It also says "16 % of holdout rows share an entity"; its own rule makes ≥ 1 % a finding.
- What's Missing gap #1: "the model already leans on segment_score, svc_ticket_days, so a finer or historical version of those is a start".
- The offline review serves Single CatBoost, and its plan says "the gain must come from new information".

**What should happen**
- Offline, a dominant feature with no decision-time answer is an open question. Run one-column ablations of the top-k features; these need no LLM.
- No ceiling headline while such a question is open, and no "collect a finer X" for such an X.
- An overlap of ≥ 1 % is a finding.

### C2 CRITICAL: the one-click "rescale" fix for a unit change corrupts the transition month

**Repro:** credit_planted with dates written YYYY-MM-15. The Data Doctor reports "loan_amnt × 0.001 from 2024-06-15"; apply its fix.

**What happens**
- Effects: rescale from 2024-06-15, factor 1000, 2,851 cells.
- The change actually starts in 2024-07, so all 412 June rows were multiplied by 1000 (June median 8,250,000).
- The cut is the start of the mixed bin (`check_unit_change` in data_doctor.py, `cut_row = bins[k][0]`).
- F-A1 shows the same early cuts: 2014-12-23 for a change on 2015-01-01, and 2024-03-28 for 2024-04-01.

**What should happen**
- Find the change point at row level, or rescale only the rows outside the pre-change scale.
- Before applying, preview the affected rows (before and after).

### M3. The label-noise signal is inverted and does not discriminate

**What happens**
- telco_planted (614 flips): the label_noise check is CLEAR (+0.0026 [−0.0036, +0.0092]).
- telco_clean: it is a FINDING and the headline (+0.0111 [+0.0039, +0.0178]).
- The "Wrong labels or missing information?" gap names Month-to-month on both, never Mailed check.
- On fraud, where the labels are clean, it ranks #1.
- "cleanlab flags 48 % of errors vs 0 % of correct rows" is circular.

**Should**
- Compare each segment's cleanlab rate with what a clean-label model would expect, and rank a label review only when the segment beats it.
- Never headline label noise on a quick-model gain alone.

### M4. The near-duplicate prescription does not remove near-duplicates
- The Doctor says "294 holdout rows (15 %) are not new: 43 identical, 251 identical but for one column".
- Its prescription is apply_data_fix drop_duplicates, which drops exact duplicates only. Its Δ is within noise, so the concern reads as "cleared".
- The Data Doctor sees 15 near-duplicates out of 900 planted.
- **Should:** add a typed near-duplicate dedupe, or a group_split on near-duplicate clusters. The Data Doctor should use the Model Doctor's definition.

### M5. The R* lower bound is beaten on clean data
- On credit_clean, model error is 0.064 against an R* lower bound of 0.105 (ratio 0.61; the rule fires below 0.60), yet the text still calls it the unavoidable error.
- On credit_planted the rule fired, but blamed overlap; it never names contact_count_q.
- **Should:** calibrate (bias-correct the 1-NN bound, or set the threshold from clean benchmarks), and stop calling it a lower bound when the model beats it.

### M6. After deployment, a unit change at the source becomes "drop the feature"
- Train on credit before 2024-07, register it, then send batches from 2024-07 to 2024-12 with labels.
- Changes reports loan_amnt drifted, PSI 7.90; suggested_drop: loan_amnt; retrain_window: worse.
- Nothing mentions a change of scale.
- **Should:** detect the constant-ratio shift, and propose "fix the feed / rescale × 1000" first.

### M7. Name-based ID typing silently drops real columns
- tax_assessment renamed to ref_value_b (integers, 98.6 % unique, ρ 0.89) becomes an ID, ignored and dropped by the API. It is a leak, and it is hidden.
- The pattern is REF_NAME in profiling.py:17.
- **Should:** require values that are integer-like and either sequential or uninformative about the target. Never auto-drop a column strongly tied to the target.

### M8. Number-guard holes
- With facts {AUC, parent .8504, child .7991, delta −.0512}, these pass:
  - "removing it improved AUC by 0.0512";
  - "AUC rose from 0.7991 to 0.8504".
- With facts {roc_auc .85, accuracy .80}, "accuracy is 0.85" and "AUC 0.80" both pass.
- Cause: the context is every key of the same object, and signs are stripped.
- It does not over-block.
