# G2 · Credit-risk model report

**What it does.** A binary scoring version now has a **Credit Report** tab under Registry. It holds the standard credit model report: Gini and KS overall and by month, a score-band table, bad rate by decile, PSI of the score, CSI per feature per month, and vintage curves. **Download report** exports the whole thing as an HTML (or Markdown) "Model Performance Report". The model card links to it. It is zero-config: open the tab and every input is already detected.

## Backend

- **`registry/credit_report.py`** holds the pure numbers.
  - Gini = 2·AUC − 1, with DeLong's interval mapped the same way.
  - KS is the largest gap between the cumulative score distributions of bads and goods, with a bootstrap CI (B = 300). The report also gives the p̂ and the score at that gap.
  - Score bands use the scorecard points scale: Score = 487.1 + 28.85·ln((1 − p̂)/p̂), so 600 points means odds of 50:1 and every 20 points (PDO) doubles the odds. Bands are 20 points wide and cover the holdout's 2nd–98th percentiles, with open ends. Each band has n, share, bads, bad rate (Wilson CI), mean p̂, cumulative capture, cumulative share, lift, cumulative lift, and the decision at t (approve, decline or mixed).
  - Deciles are ten equal-count groups by p̂, each with its observed bad rate (Wilson CI), mean p̂ and lift.
  - The CSI matrix is built from F18's stored per-feature PSI for each batch, which is CSI against the training rows. For each feature it records the first month in watch, the first month in shift, and whether the feature stays flagged afterwards.
  - Vintage: V_c(k) = #{defaulted by k months on book}/n_c. A cohort is shown only while all its loans have been watched for k months. Cohorts are by origination month, or by quarter when there are more than 12 months.
  - `to_markdown` writes the report. `card.md_html` is the card's converter, factored out so the card and this report share one HTML path; it now renders `###` as a heading too.
- **`registry/credit_report_api.py`** gathers the data.
  - **Holdout:** the version's `holdout_predictions.csv`, split by month of the date column.
  - **Batches:** each batch's `labels.csv` + `scored.csv`, read through F18's `monitoring_state`. A batch whose labels have not arrived is listed as "labels pending".
  - **Detected inputs (G0):** `intake.detect` on the training data finds the date role (the run's split time column is preferred when it has that role) and the id role (the monitoring config's id column is preferred). Each is shown with its evidence. `?date_column=` overrides the date.
  - **Performance tape:**
    - An uploaded tape (audited `credit_tape_uploaded` / `credit_tape_removed`) takes precedence.
    - Otherwise, for the loan-stream sample, the tape comes from the new **`samples_g2.py`**: a seeded months-to-90-DPD draw per defaulter, 1 + ⌊Gamma(2.2, 3)⌋, capped at 24, observed as of 2026-03-31. `samples_f18.py` is untouched. The tape is filtered to the loans this version has seen (its training data plus its scored batches).
    - The tape's columns (open date, default date, as-of date, id) are found from the G0 roles plus name rules, with a value-parse fallback for low-cardinality or mostly-blank date columns.
  - Each GET stores the headline beside the version (`credit_report.json`), so the model card shows it without recomputing.
- **Model card:** a "Credit model performance report" paragraph (JSON, MD, HTML) with the last headline and the HTML/MD links.
- **G0 suggestion `credit_report`, "Credit model report":** it shows when the table has a yes/no target and a ready binary registry version, and opens `#/registry?version=…&tab=Credit Report`. Its score is 68 when the target reads like default and there is a date, else 50.

## UI (no new navigation; Registry → version → Credit Report)

- **One primary action, "Download report"** (HTML). Markdown is a secondary link.
- **Hero strip:** holdout Gini [CI], KS [CI], bad rate, labelled months, first CSI flag and vintage cohorts. Below it are the formula well and the "where" paragraph.
- **Inputs:** a fold-out, closed by default. It shows the detected date and id with their evidence, and the tape source and mapping. You can change the date column, and upload or remove a tape there.
- **Gini By Month:** CI bars for each month. Holdout months are grey, batch months teal, and months still waiting for labels are drawn as ○. The table is in a closed fold-out.
- **Score Bands:** the band table, with a Holdout / Labelled batches toggle, and the decile chart (bars with Wilson CIs, plus the mean-p̂ line).
- **Stability:** a heatmap of score PSI plus CSI per feature × month. A closed fold-out breaks down the first flagged feature's CSI bin by bin.
- **Vintage Curves:** one line per cohort.

- Holdout: Gini 0.528 [0.472, 0.584], KS 0.376 [0.335, 0.438], bad rate 18.7% (339 / 1,815).
- **Independent recompute** of the 10,800 pooled labelled batch rows with sklearn matches the report to 1e-6 (Gini 0.5514, KS 0.4196).
- Decile bad rate falls from 0.615 to 0.011. The band and decile totals add up, and cumulative capture ends at 100%.
- Report time: 1.2 s cold. Markdown export ~6.9k chars, HTML ~16k chars.
- Tape upload: `open_date` / `default_date` / `as_of_date` are found from the roles and names, giving 8 monthly cohorts. A tape without dates gets 400. Removing the tape falls back to the sample tape.

**Smoke.** `SMOKE_ONLY=credit,core make smoke`: **25/25 passed in 164 s** (credit 4 steps, ~75 s; core 21). `npm run build` and `tsc` are OK.

## Limits and open problems

- **The vintage needs a performance tape** (default timing). Only the loan-stream sample has one built in; any other model needs an upload, and the tab says so. The sample's default timing is simulated (Gamma), not part of the F18 generator. The tape is per registered model, not per version.
- **KS's CI is a bootstrap with B = 300,** so the bounds move in the third decimal between seeds. There is no multiplicity control over months. Holdout months are small (≈ 600 rows), so their CIs are wide.
- **CSI is measured against the training rows,** as F18 does, not against a separate development sample. The bands are fixed (0.10/0.25).
- **Score bands are fixed PDO-width bands on the holdout's range.** No custom cut-offs or scorecard grade names yet.
- **The report is computed on each GET.** About 1 s on this sample; it grows with the number of batches. Only the headline is cached, for the card.
- **Not in the Model Doctor or Vela.** G10 should expose `GET /credit-report` as a tool. Mock mode has no mock for it, so the tab shows its error state.
- **Smoke leftovers:** the smoke registers a new `smoke.credit-report` version on every run.
