## A. Fixes from S5's screenshot

- **MLflow bug.** `worker.py` emitted `emit("tracked", **mlr)` where `mlr` holds MLflow's own `run_id`, so
  `RunStore.emit(run_id, type_, **data)` got `run_id` twice and the log ended with "MLflow logging failed". The run was
  tracked (the result was merged before the emit) but the event and every later step of that block were lost. Fixed
  twice over: `RunStore.emit` and the worker's `emit` take `run_id` / `type_` positional-only, and the event carries
  `mlflow_run_id`. Test: `test_completed_run_logs_to_mlflow_without_warning` (one `tracked` event whose
  `mlflow_run_id` equals the run's MLflow record, no "MLflow" log line, no ENSEMBLE warning).
- **Home layout.** Run strings: the id column is `max-content` (it overlapped the name), the readout column is bounded and

## B. What works

**Gym backend** (`app/gym/`)
- `GET /api/gym/schema`: 11 families with slider specs (AutoGluon key, symbol tied to the family's objective, interval,
  log / linear, integer, default read from the model class's `_set_default_params` where it has one, e.g. GBM η = 0.05),
  presets with what they expand to, metrics per problem type, HPO options, GPU count (0 here, with a note), the default
  zoo, and **every keyword `TabularPredictor.fit` accepts** (signature + the `**kwargs` AutoGluon validates, collected by
  calling `_validate_fit_kwargs` on a probe, so it follows the installed version: 56 keys on 1.6.3).
- `POST /api/gym/validate` (in the worker pool): unknown keys with a difflib suggestion, reserved keys, value checks
  (k ≠ 1, L needs bagging, GPUs, HPO scheduler/searcher/trials, holdout_frac, infer_limit, booleans, sample-weight column,
  excluded types, pseudo-label data has the features, distill arguments), metric vs problem type, hyperparameter values
  outside the slider interval as warnings. Returns the **resolved call** (the worker's own `resolve_fit_kwargs`, so the
  Gym shows exactly what runs), a **diff** against fit()'s defaults with origin (you / preset / ENSEMBLE), AutoGluon's
  own `get_validation_and_stacking_method` for this data (k, s, L, dynamic stacking, holdout_frac, refit), and the
  **estimate** T̂ = min(τ, c₀ + Σ_f v_f·r_f·n·d·max(1, k·s)·(L+1)) with r_f the median seconds per row·feature per fold
  model over models already fit on this machine (prior when none). `POST /api/runs` runs the same validation and refuses
  errors with 400.
- New run fields: `pseudolabel` (`fit_pseudolabel` after the fit, or `unlabeled_data` into fit; label column dropped),
  `distill` (`predictor.distill` after the fit, seeded), `parent_run_id`, `patch`, `source`. Post-fit steps are events
  (`post_fit`) and part of `resolved.post_fit`.
- **Export** `GET /api/runs/{id}/export.py`: data path + SHA-256, the exact holdout rows (zlib bitmask), drops, column
  types / feature metadata, resolved predictor and fit kwargs, post-fit steps, the threshold step (calibrate again, or set
  a user value), then the holdout leaderboard compared with the run's model by model; exits 1 on a difference. Tiny
  runs reproduce with **max |Δ| = 0**.

**Python client** (`clients/python/ensemble_client`, installed editable by `make setup`): datasets (list, get, upload a
path / bytes / DataFrame), runs (start, get, list, wait, events as a live SSE stream, leaderboard as a DataFrame, predict,
config, vela, export, cancel), registry (register → wait, review, transition, predict, card), gym (schema, validate);
`ApiError` with status and detail. README with a notebook session.

**Vela** (`app/vela/`): findings computed in a worker from the run record, holdout predictions, data, events, dataset
profile and scored batches; each states its numbers and formula and has one patch (`changes` with from → to, and the
patched `body`): overfit (z = gap / max(SE_boot, σ_folds) ≥ 2 → bag 5 folds, or regularise the best family when bagged),
weakest class (recall vs macro mean → calibrate for balanced accuracy or `balance_weight`), worst segment (error ratio of a
category level, n ≥ 30 → high_quality or 2τ), imbalance (minority share, F₁ at 0.5 vs the best t on the holdout grid →
calibrate for F₁, or balance weights when already calibrated), leakage (a depth-6 single-feature tree scores ≥ 0.97 on the
holdout and the column holds ≥ 50% of positive importance, or an identifier used as a feature → drop it), budget
(≥ 95% of τ, skipped models, fewer stack levels than planned → 2τ), columns (constant / > 50% distinct categories → drop),
drift (PSI > 0.25 in a scored batch of a version from this run → retrain without the feature). Wording: `claude -p --model
claude-sonnet-5-5 --output-format json` (works here, ≈ 8 s), else the Anthropic API, else computed; 30 s timeout each;
a reworded finding must contain every number of the computed text or it keeps the computed text; cached per findings.

**UI**
- `#/gym` live (`features/training-gym/live/`): the body of `POST /api/runs` is the only state; every control is a path in
  it, so the form, the raw JSON and Vela's patches stay in step. 10 steps, Advanced ones tagged and skipped in Guided.
  Side panel: resolved call diff (tinted changed lines, origin tags, preset expansion as comments, Vela lines marked),
  T̂ with every symbol bound to numbers, AutoGluon's k/s/L chips. Dock: server checks and a dry-run log. Start Training →
  `#/quick-train?run=…`. Mock mode keeps the scripted prototype with a SIMULATED pill. `gym` is out of PrototypeBanner.
- Vela sidecar live: picks the run (URL, Gym source, latest), shows findings with severity, formula, patch diff, Apply /
  Dismiss, and the wording source ("Claude CLI · claude-sonnet-5-5", "Anthropic API", or "computed text" with why).
  Apply puts the patch on the Gym (on top of the loaded config when it is the same run, else the patch's body).
- Results of a patched run link to `#/experiments?compare=parent,child`; Experiments shows the patch and Δ on the
  holdout, and a "↳ patch · parent" line under the run's name. Results also link to the Gym (`?from=`) and the export.

## What doesn't / not done

- **Reproduction is exact except under two conditions**: a time limit that binds (AutoGluon stops at a wall-clock point),
  and the TF-IDF logistic regression refit on pseudo-labelled rows, whose multithreaded BLAS can flip one validation row
  (1/1,600 in the slow test; holdout scores stay exact). The script reports each model that differs.
- The estimate is linear in n·d per family; early-stopping boosters and neural nets vary more than that. It says where
  each rate came from.
- Vela's free-text questions are off in live mode (the input is hidden); S7's Claude layer is the place for them.
- Findings are computed on request (≈ 1 s, in the worker pool), not stored; wording is cached per set of findings.
- `hyperparameter_tune_kwargs` searcher `bayes` depends on AutoGluon's optional searcher packages; validation accepts it,
  the fit may fall back.
- The Gym's per-family sliders edit one config of a family at a time (the default zoo has 3 GBM / RF / XT configs).
