## Cause

The bank's validation standard is a challenger model a reviewer can read line by line. Nothing in ENSEMBLE produced one,
and nothing measured what the ensemble gains over it.

## What changed

**Model (`backend/ensemble_models/scorecard.py`, new).** `ScorecardModel`, key `SCORECARD`, name `Scorecard`. It is an
AutoGluon `AbstractModel` defined at module level and registered like TFIDF_LR, so it pickles for bagged workers, the
saved predictor, export.py and Ray fold workers. A `parallel_local` fold fit was tested. By default it fits its folds
in-process (`sequential_local`), because it takes milliseconds. It is binary only and `valid_stacker=False`. It
excludes dates, text n-grams, text statistics and stack features through AutoGluon's own feature-type filters.

How it fits, all inside `_fit`, so in a bagged run each fold child fits on its own training folds and no out-of-fold or
holdout row shapes a bin:
- **Numeric bins:**
  - quantile fine bins (20);
  - merge bins under 5% of rows;
  - merge by pool-adjacent-violators until the *smoothed* event rate (b + ½)/(n + 1) is monotone. WoE is a decreasing
    function of that rate, so the WoE is exactly monotone;
  - merge down to ≤ 6 bins, always the pair with the closest event rates;
  - the direction comes from the F8 constraint if the column has one, else from the data (`monotone_bins: auto`).
- **Missing values** get their own bin.
- **Categories:** levels under 5% share an "other" bin; then merge by event rate.
- **WoE and IV:** WoE = ln((gᵢ+α)/(G+kα)) − ln((bᵢ+α)/(B+kα)), α = 0.5; IV per feature. Features with IV < 0.02 are
  left out.
- **Logistic regression** on the WoE columns. A positive coefficient (collinearity) is dropped and the model refitted,
  so every βⱼ ≤ 0.
- **Points:** factor = PDO/ln 2, offset = base − factor·ln(odds). pointsᵢⱼ = −factor·βⱼ·WoEᵢⱼ + (offset − factor·β₀)/n.
  The defaults are PDO 20 and 600 points at odds 50 : 1.

**Coexistence with earlier fixes:**
- **F8.** A constrained column is binned in the constraint's direction. With βⱼ ≤ 0 the scorecard is monotone by
  construction; `_fit` asserts it, and the model sets `monotone_applied` so F8's report counts it.
  - `translate_hyperparameters` passes the constraint to SCORECARD and keeps it even with `compliant_only`.
  - The Gym lists it among the families that honour the constraint.
- **F7.** With a cost, the scorecard competes on the cost metric inside AutoGluon; in the cost smoke the ensemble gave it
  weight 0.29. The report adds its expected cost per 1,000 decisions at the Bayes threshold, next to the served model's.
- **F6.** Group and time splits work unchanged: bins come from whatever rows AutoGluon trains on, and the deployable
  refit uses the training frame only, never tuning or holdout rows.
- **F10.** The scorecard has its own reason codes: points lost against each feature's best bin, top 4. The UI labels them
  as explaining the scorecard, not the served model.
- **F3.** Registration, the deployed copy and Try It work with SCORECARD in the predictor; checked in smoke.

**Run (`engine/scorecard.py`, worker, API):**
- `POST /runs` takes `scorecard`:
  - null or true: on for binary;
  - false: off;
  - or `{pdo, base_score, base_odds, max_bins, min_bin_share, min_iv, monotone_bins, fine_bins, C}`. Bad values → 400.
- `resolve_fit_kwargs` adds SCORECARD at level 1 of whatever hyperparameters the run uses (presets or given).
- After the fit the worker builds the report:
  - The in-run model is bagged (one set of bins per fold child), so it is not one table.
  - The **deployable scorecard** is the same class with the same hyperparameters, refitted on all training rows through
    the predictor's feature generator and feature metadata.
  - Its table is saved, along with `scorecard.csv` and the pickled model.
  - Holdout AUC, Gini and KS for the scorecard, the in-run bagged scorecard and the served model.
  - ΔAUC with a paired bootstrap for both scorecards.
  - Score bands (rank ordering), the F8 points check, and the F7 cost.
- Endpoints:
  - `GET /runs/{id}/scorecard`;
  - `GET …/scorecard.csv`;
  - `POST …/scorecard/score {holdout_index | rows}`: points per feature with the bin, score, P, reason codes, and the
    served model's P.
- The run payload carries the headline (`scorecard.available`, AUCs, ΔAUC).
- Model card: a "Scorecard benchmark" section in the JSON, the Markdown, HTML and the registry UI.
- export.py marks SCORECARD runs as needing `ensemble_models`. The core export check reproduces the leaderboard with
  the scorecard in it: max |Δ| = 0.

## Open problems

- **The table is a refit.** The in-run model is a bag of k fold scorecards, so the exported table is the deployable
  refit on all training rows. Both are scored on the holdout and reported; here the bag scores 0.7538 against the
  refit's 0.7492 on the cost run.
- **Greedy binning.** It is quantile fine bins plus merges, not an optimal binning solver (e.g. optbinning's MIP).
  - An ordinal category is binned by event rate, not by its order.
  - A two-valued number is shown as 0/1, AutoGluon's encoding.
- **Unseen values.** Unseen categories, and missing values when training had none, score WoE 0, the average applicant.
  A bank may want a policy value instead.
- **Reason codes describe the scorecard.** They explain the scorecard, not the served ensemble; F10 covers that. The
  scorecard itself cannot be the served model of a registered version yet, beyond registering the run with that model.
- **customer_id.** On credit-default it reaches the scorecard as a category, because the sample types it as category,
  not id. It is dropped by IV (0.008). Drop it in the request, as F10's smoke does.
