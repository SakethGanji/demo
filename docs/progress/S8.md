## What was built

**Backend.** Forecast and anomaly runs are rows in the same `runs` table and go through the same `JobRunner` (one
process per fit, cancel, restart recovery) and the same events and SSE: `engine/worker.py` dispatches on
`config.kind`. `GET /api/runs` lists tabular runs and imports by default, so older pages never see the new kinds;
`?kind=forecast|anomaly|all` lists them.

- `app/forecast/core.py`, `api.py`: long-format reader (rows past each series' last target are the horizon's known
  covariates), freq inference, the last H steps held out, `TimeSeriesPredictor(...).fit(train, **fit_kwargs)` with
  every argument passed through. TimeSeriesPredictor has no callbacks, so a log handler turns its trainer's lines into
  `model_started` / `model_finished` (validation score, fit time) / `ensemble` events. Results: the leaderboard on the
  full data (val + holdout), the greedy ensemble's weights, `backtest_predictions` / `backtest_targets` scored per
  window and model, the holdout forecast with per-series MASE, WQL, sMAPE, bias and interval coverage, and the future
  forecast (`forecast.csv`, `chart.json`). Forecast from new history with the saved predictor. Column mapping
  suggestions from the sample's spec or from names and types.
- `app/anomaly/core.py`, `api.py`: ColumnTransformer (median impute + missing flags, one-hot top 20) → IsolationForest,
  optional LOF (novelty, robust-scaled). s, E[h], c(ψ), threshold at the (1 − c) quantile, histogram, TreeSHAP on the
  forest summed back from one-hot columns, robust z / category share, precision@k, ROC AUC, AP and recall per kind
  against `anomaly_truth.json` (stored in the run config for the worker, stripped from every API response). Batch
  scoring with percentile and reasons; one-row scoring. Saved as `model/model.joblib`.
- `app/engine/importer.py`: `POST /api/runs/import` (zip upload with safe extraction, or server path), validated in a
  worker (loads, label and features in the dataset), then the normal tabular worker path minus the fit: leaderboard,
  holdout metrics, threshold record, importance, MLflow. Explain, Results, registry, card, Try It and batches work.
- Registry: `build_other` copies the model folder, measures forecast/scoring latency, hashes, registers in MLflow
  (engine tag `autogluon.timeseries` / `scikit-learn`). Try It on an anomaly version scores the row; batches for the
  new kinds point to their own pages. Model card: engine, call and split per kind, and §11 Forecasting / Anomaly
  detection / Imported predictor (JSON, Markdown, HTML).
- Samples: `transaction-volume` (6 series × 730 days + 28 future rows; trend, weekly and yearly seasonality, December
  peak, holidays and paydays as known covariates, segment static) and `card-transactions` (6,000 rows, 90 planted
  anomalies of five kinds). Dataset `kind` gains `timeseries` / `transactions`, plus `flows`.
- `make reset`: `POST /api/admin/reset` (`{"confirm": "reset"}`, refused while a run is active) or `python -m
  app.reset` offline. Deletes runs, events, registry, batches, autopilots, MLflow and uploads; regenerates the samples.

**UI.** Sidebar: New Forecast, Anomaly Detection (new group), Import Predictor (under the registry). New Model's
problem-type step links to all three. Shared: `useRunEvents` (SSE → live model rows), `FlowParts` (live rows, the
register strip). The registry's version view handles forecast/anomaly versions (measured card instead of the tabular
trade-off, links to the flow page instead of tabular Try It / Batch).

**Fixes on the way:** dataset kinds in the response schema (the new samples made `GET /api/datasets` 500); a crash in
`HeavyPool.shutdown` when the executor had no processes; the model card view on versions without dependencies.

## Open

- Interval coverage on the sample is wide: [q₀.₀₅, q₀.₉₅] covers 100% of holdout actuals against 90% nominal (smoke
  config with few models). Shown honestly on the page.
- IsolationForest finds 0/18 "amount spike" anomalies: they are large only relative to the card's own 90-day average,
  which the model sees as two separate columns. The page says so; an amount ÷ avg feature is the fix (not added, so
  the sample stays a fair check).
- Forecast runs are not in Experiments or Home (they list tabular runs); a forecast comparison view is S9 material.
- Batch scoring of forecast/anomaly versions lives on their run pages, not in the registry's Batch & Drift tab (no PSI
  drift for them yet).
- Presets `high_quality` / `best_quality` / `chronos2` download Chronos-2 / Toto weights from Hugging Face on first use
  and are slow on 4 CPUs; the smoke uses a small zoo with Chronos-Bolt tiny.
- `e2e/registry.live.spec.ts`'s stale Autopilot banner assertion (from S7) is still there.
