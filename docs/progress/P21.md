## What was built

| Piece | Where | What it does |
|---|---|---|
| **Contracts** | `catalog/contracts.py` (new) | Versioned per dataset (root) in `data_contracts`: each PUT or freeze writes version n+1, the others go inactive, audited `contract_set`.<br>**Spec** (C §4.5): per table `required`, `key`, `rows {min,max}`, `columns {type, nullable, unique, max_null_share, range, values, severity}`, `allow_new_columns` (allow / warn / block), `on_removed_column`, `on_type_change`; cross-table `relations [{from, to, min_coverage}]`; `severity_default`. Validated (400 `contract_invalid` naming the place).<br>**Evaluation** runs in DuckDB (`duck.job()`) on the tables as the version holds them. Results carry counts, never values (a column may be PII-tagged): `{status pass/warn/block, n_rules, n_blocks, n_warnings, rules[]}`.<br>**Routes:** `GET/PUT /datasets/{id}/contract`, `POST /datasets/{id}/contract/from-version/{v}` (freeze: every table required, columns with their kinds, `nullable: false` where the version has no missing value, the valid primary keys and declared relations; removed column and type change **block**, new columns warn; each overridable in the body), `POST /datasets/{id}/contract/check` (stores `datasets.contract_result`). |
| **The check step** | `catalog/datasets_api.py` (`check_upload`, `commit_upload`: 6 lines) | `POST /uploads/{u}/check` runs the parent dataset's active contract on the version the upload would make (single file: the replaced table + the parent's others; multi-table: typed / appended / carried tables, through P12's `_rel_sql`). A failed `block` rule goes into `blocks` (`contract_block`), a `warn` into `warnings`; `check.contract` names the contract version; tables get `contract: pass/warn/block`. The check is stored again (new `check_sha256`), so `commit` answers **409 `check_blocked`**.<br>`commit` first refuses a check made against an older contract (409 `check_stale`), and afterwards keeps the check's result on the version (`contract_result`). |
| **Certifications** | `catalog/certify.py` (new) | `POST /datasets/{id}/certifications {version_id?, level, reason}` (`data.certify`, maintainer). Refused unless the active contract passes on the version (409 `contract_required` / `contract_failed`) and the PII tags are reviewed (profiler runs first, then no `suggested` tag may remain: 409 `pii_review_required` with the list). Pins the contract id and result.<br>`POST /certifications/{c}/decide {approve, comment}`: the route gate is `data.certify_decide`; the handler then decides the level's own key through `deps.check` (`data.certify_decide_certified` = owner, `data.certify_decide_model` = risk reviewer), audited / enforced like a `require()`. Four eyes → **409**. The contract is checked again. Approval supersedes the root's earlier live certification of that level and sets `expires_at = now + policy.certify_days` (365). Rejection needs a comment.<br>`GET /datasets/{id}/certifications`, `GET /certifications/{c}` with the effective status (expired after `expires_at`). |
| **Shares** | `catalog/shares.py` (new) | `POST /shares {object_id (dataset or prj_…), grantee_team, scope certified/default/pinned/all, pinned_version?, pii masked/unmasked, expires_at?, reason}` (`data.share`, maintainer of the owning team). One pending-or-live share per (object, grantee). `POST /shares/{s}/decide` (`data.share_decide`, owner; four eyes 409; **a `pii='unmasked'` share is approved only with `grant_unmasked: true`**, else 400). `POST /shares/{s}/revoke {reason}` (`data.share`): returns `runs_kept`. `GET /shares?team=&object_id=&status=` (enforce: only shares from or to the caller's teams), `GET /shares/{s}` with its runs. Approve / revoke are audited in **both** teams' chains (`share_approved` + `share_received`, `share_revoked` ×2).<br>**Grants** are computed from the rows at request time (`grant`, `grant_for_version`, `in_scope`): a dataset share covers the versions of its scope (certified = a live certification of either level; default = the effective default; pinned; all), a project share covers the project's versions, and a run only through a project share with scope `all`. Deleted versions are never shared. |
| **Policy** | `authz/policy.py`, `authz/deps.py`, `authz/scope.py`, `authz/api.py`, `authz/lists.py` | `shared_to()` is narrowed from "any share from that team" to the object and its scope (`shares.grant`).<br>**`data.read_unmasked` / `data.export_unmasked`** allow a grantee only through a live `pii='unmasked'` share (P20's `for_request` unchanged: the reason is still required and the read is audited `dataset_rows_read`).<br>New keys: `data.certify_decide`, `data.certify_decide_certified`, `data.certify_decide_model`, `data.share_decide`. New scopes: `certification`, `share`, `shareable`.<br>**`visible_teams()`** = own teams + teams with a live (unexpired) share to them; **lists then keep a sharing team's rows only when a share covers that row** (`shares.row_visible`), and every foreign row carries `access: shared/none` in audit mode (declared on `DatasetSummary`).<br>`deps.record()` / `deps.check()`: a handler-level decision with the same mode semantics as `require()` (context, header, `authz_would_deny` / `authz_denied`, 401/403). |
| **Four eyes** | `policy.four_eyes(action, req, by)` → `decide_check` | Checks the recorded decider name **and** the request's principal against every field of `FOUR_EYES[action]` (`identity_key`: punctuation, spacing, accents, Cyrillic / Greek / full-width confusables, zero-width, I/l/1). Rewired: **champion decide** (`catalog/api.py`), **registry review** (now also ≠ the run's creator, C §1.3), **retire decide** (`registry/api.py`), **dataset delete decide** (`dsets.py`), **admin reset decide** (`main.py`), plus the new **certification** and **share** decides. Existing paths keep their status codes and messages (403 / 409 as before); the new ones answer 409. |
| **Cross-team training** | `engine/api.py` (route + 5 lines), `catalog/store.py` (`record_run`) | `RunCreate.project_id`. The route's `require` is `run.train` on the **project** when one is sent (else the dataset), plus `data.preview` on the dataset (a share's scope). The project rule (`shares.train_project`): a version of another team without `project_id` → 400 `project_required`; into a project of a third team, the **project's team** must hold a live share covering the version (a denial recorded like a `require()`). The run's `project_id` / `team_id` are the project's; the `trained_on` edge makes it show in the owner's `…/usage`. |
| **`require_certified_inputs`** | `registry/api.py` (transition), `certify.inputs_gate` | Moving to Production reads the run's team policy: `true` / `"certified"` (either level) or `"approved_for_model"`. Every input version (`run_inputs`, else the run's dataset) needs a live certification now, else **409 `inputs_not_certified`** with the versions and tables. The certifications found go in the transition audit row and `model_versions.result.input_certifications` (with `checked_at`), so a later expiry does not rewrite history. |

## Deviations and notes for dependants

- **Enforce: role before four eyes.** C §1.5's `decide_check` checks the role first (403) and then the person (409). So
  in enforce, Ana (maintainer) deciding her own certification gets **403** (needs owner), and so do her lookalikes; in
  audit it is would-deny + **409 four eyes**. The 409-in-enforce case is shown on the share (Ben, an owner, requested it:
  Ben and `B.e.n`, `Bén`, Cyrillic `Веn`, `BEN` → 409; Bo approves).
- **Non-ASCII lookalikes** cannot be an HTTP header value, so the scripts send them only as the body `by`. In enforce a
  route whose body has no `by` field (registry review: `reviewer`) then has no principal → 401. Refused either way.
- **Existing decide paths keep their status codes** (champion / retire / delete / reset 403, review 409); only the check
  is shared. Registry review is now also refused for the run's creator (C §1.3), which is stricter than before.
- **Audit mode lets would-deny requests through**, as P19 designed: e.g. Carl training on v2 (not shared) into his own
  project is would-deny `data.preview, run.train` and runs. The scripts use `/authz/check` for role-only probes (PII
  tags, contract, share decide) so audit-mode side effects do not pollute later steps.
- **Upload check preview** shows the uploader's own raw rows (`pii 10` on `/check`): P20 left it out on purpose.
- **Not built (outside the P21 row):** forks (a grantee's copy-free derived dataset), the catalog's
  "exists, owned by X: [Request access]" discoverable rows, contracts on the **edit** path (only the upload check step
  and explicit checks run them), contracts on CSV-era versions (409 `not_parquet`: migrate first), the model card's
  rendering of `input_certifications` (stored on the version result and the audit row; `registry/card.py` untouched),
  a certification revoke route, and the other run kinds' `/{kind}/runs` (only `POST /runs` takes `project_id`).
- **Files outside the row (small):** `main.py` (3 routers; `require("data.read_meta")` on `GET /datasets/{id}` so a
  version outside a share's scope is refused; the reset decide), `catalog/api.py` + `catalog/dsets.py` (four eyes),
  `catalog/store.py` (`record_run` project/team), `schemas.py` (`access`), `authz/*`.
- **For U2:** contract editor / freeze button, `check.contract` and `tables[].contract`, certification request / decide
  (grey out with `/authz/check data.certify_decide_certified|_model`), share request / decide (`grant_unmasked`
  checkbox for pii unmasked) / revoke, `access: shared` on list rows, `project_required` on training a shared version.
- **For P24:** `shares.runs_on(share)` lists the grantee's runs on a shared object (the purge impact report);
  `live_certification()` for `keep_certified`.
- **For P23 / Postgres:** all new SQL is portable (no `json_extract`, no `rowid`); verified on Postgres 16.
- **Scratch:** the data dirs, the Postgres cluster, the venv and the API processes were in the scratchpad / `/var/tmp`
  and are removed.
