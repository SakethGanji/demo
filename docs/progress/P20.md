## What was built

| Piece | Where | What it does |
|---|---|---|
| **Tags** | `column_tags` (P01's table), `lake/mask.py` | One row per (root, table, column): `tag` ∈ pii_direct, pii_quasi, protected, sensitive, key, none; `mask` ∈ redact, hash, last4, year_only, bucket, none; `source` suggested / confirmed.<br>Tags belong to the **root**, so every version carries them.<br>A column is masked when its mask is not `none`. A **suggested tag masks like a confirmed one** until a maintainer reviews it. |
| **Suggestions** | `profiling.pii_suggestion`, `mask.ensure` | **Name rules first** (`PII_NAME_RULES`):<br>• ssn / national id / passport / tax id → pii_direct redact;<br>• email → pii_direct redact; phone → pii_direct last4;<br>• person names, addresses → pii_direct redact;<br>• dob → pii_quasi year_only; zip / postal → pii_quasi bucket;<br>• account / card / IBAN numbers → pii_direct last4; ip → pii_direct hash;<br>• race / gender / … → protected, mask none.<br>**Then value patterns** on a 200-row sample of the text columns (≥ 80 %): email, the SSN shape `123-45-6789`, Luhn-valid card numbers.<br>`ensure()` tags the columns a root has not seen. It runs **before every masked read** (cached by table content), so no read can outrun a suggestion. It also runs on the first dataset detail. Audited as `pii_tags_suggested` (actor `profiler`).<br>`POST /uploads/{u}/check` shows the coming tags per table (`tables[].pii`): the root's tag for a new version, else the suggestion. |
| **Masks** | `lake/mask.py` (`mask_sql`, `mask_value`) | **What each mask shows:**<br>• redact → `•••`;<br>• hash → `sha256(team salt ‖ value)[:12]`, stable within a team, so joins and counts still work. The salt is `catalog_meta pii_salt:<team>`, random, made on first use;<br>• last4 → `•••6789`;<br>• year_only → `1984`;<br>• bucket → numbers by their leading digit (`47` → `40–50`), text by its first 3 characters (`021•••`).<br>Missing stays missing; a masked column is VARCHAR.<br>The masks exist **in SQL and in Python with identical output**: a whole DOUBLE is written as an integer and booleans as true/false on both sides. Checked on 25 values of 5 types × 5 masks, 0 differences. |
| **`frames.scan(version, table, *, mask_for)`** | `frames.py`, `lake/pages.py` (`masked`, `Source.wrap`) | **The one relation builder for every read that shows rows.** `mask_for` is keyword-only with no default: a `Mask`, or `"masked"`.<br>It returns P08's `pages.Source` whose `rel` is `(SELECT __row_id, <masked exprs> FROM read_parquet(…))`, so a WHERE, a search, a sort or a lookup sees only masked values.<br>The position path (`file_row_number`) and the CSV-era Arrow bind are wrapped the same way.<br>A masked column is **not searched** (a hit would tell its value).<br>`frames.scan_csv(src, dest, drop, limit)` writes a scan as CSV by DuckDB `COPY`: the **masking happens inside the COPY**. |
| **Unmasked reads** | `mask.for_request` | `unmasked=1&reason=…` on rows, grid, lookup, filter preview, diff and export.<br>**The reason** (2–500 characters; the done-when uses `QA`) is required, else `400 reason_required`.<br>**The decision** is `data.read_unmasked` (`data.export_unmasked` for an export), made through P19's `deps._decide`, so it lands in the context, the header and the hash-chained audit like any `require()`.<br>**Allowed:** the read is audited as `dataset_rows_read` `{read, reason, columns, action, unmasked}`, never deduplicated.<br>**Denied, `audit` mode:** the response **stays masked** with `unmasked_refused: {action, needed, role, message}`, the header `would-deny data.read_unmasked` and an `authz_would_deny` row.<br>**Denied, `enforce` mode:** 403 `{code: forbidden, action, team, needed}`; 401 without a principal. |
| **Routes** | `main.py` (`/rows`, `_detail`), `catalog/datasets_api.py` | **Rows and pages:**<br>• `…/rows`, `…/rows?value=` (lookup), `…/grid`, `…/rows/preview` and `…/rows/count` go through the scan;<br>• responses carry `masked_columns`, `masks`, `unmasked` (and `unmasked_refused`); grid columns carry `masked` / `mask`;<br>• the lookup value and a filter value on a masked column are not echoed, and the filter-preview audit row stores the filter masked.<br>**Profile and history:**<br>• `GET /datasets/{id}` and every other `_detail` (upload, edit, patch, Data Doctor apply, Feature Lab, SQL refresh) mask the stored profile's `example`, `top`, `range` and number `stats` of PII columns (`profiling.mask_profile`);<br>• `…/history` is scrubbed (edit logs, audit details).<br>**New routes:**<br>• `GET /datasets/{id}/pii` (`data.read_meta`);<br>• `PUT /datasets/{id}/pii` `{columns: [{column, tag, mask?}]}` or `{confirm: "suggested"}` (`data.tag_pii`), audited as `pii_tags_set` with the old values. |
| **Stats rendering** | `mask.stats` on `GET …/stats` | For a masked column:<br>• the top-20 values are masked, with equal masks merged;<br>• histogram, min / max / mean / std / quantiles / median are null;<br>• a date's min / max are masked;<br>• counts stay.<br>The diff's column table masks `top_a` / `top_b` and blanks mean / median. |
| **Export** | `datasets_api.export`, `_export_csv`, `_masked_csv` | Masked by default.<br>**Parquet:** the COPY reads `frames.scan(mask_for=m)`, cached as `lake/exports/<v>/<table>.masked-<masks+salt>.csv`. A re-tag makes a new file; the unmasked file is a separate cache entry.<br>**CSV-era:** the same COPY from the bound Arrow table.<br>**In the zip:** `schema.json` marks masked columns (`masked`, `mask`, `stored_type`); `export.json` has `masked` (columns, note) or `unmasked` (reason, columns).<br>`csv_sha256` is the masked file's; `table_sha256_stored` stays the stored table's. The header is `X-Ensemble-Masked`. |
| **Diff** (P08's hand-off) | `lake/diff.mask_result`, `mask_key_error` | **Computed on stored values**, so a change between two equal masks still counts. Then masked per side:<br>• `samples.added` (b) / `samples.removed` (a) are **re-read through `frames.scan` by `__row_id`** (Parquet). A CSV-era side goes through the Python masks, because its diff `_row_id` can be a lineage root row;<br>• changed cells (a's mask / b's mask, renamed columns mapped), keys, the column table;<br>• `key_invalid.repeated`;<br>• the edit log (`edit`: old → new).<br>`unmasked=1&reason=` on the diff too (audited for each side). |
| **Errors never echo a tagged value** | `mask.tagged_values`, `scrub_error`; the edit route | Before an edit, the values the ops send for masked columns are collected (set_cells, where / filter, replace / fill, add_rows).<br>Any 4xx body (ValueRefused, DatasetError, HTTPException; preview too) has them replaced by "the value (not shown: the column is PII-tagged)", and loses `value` fields. It keeps `column` and `type` and adds `masked_columns`.<br>An untagged column's error is unchanged. The upload's `key_invalid` examples (`upload._mask`) now use the shared masks with the team salt (they had a salt-less hash). |
| **Agent CSV** | `agent/tools._dataset_csv` | `frames.scan(mask_for="masked")` → `scan_csv` (COPY, drop, limit). The agent has no unmasked path. |
| **Run pages** | `Mask.scrub`, `mask.run_scrub` / `for_run` | A net for results built by code that does not know about masks. It masks:<br>• `{column\|feature\|name: c, value\|a\|b\|old\|new\|from\|to\|lo\|hi\|values\|top\|key\|example}` pairs;<br>• a column named by an enclosing dict (`{column: dob, bins: [{from, to}]}`);<br>• `{c: v}` feature dicts;<br>• `{columns: [names], rows: [[…]]}` tables.<br>Then, in every string, it replaces each raw value seen above, plus its number formats (`101,403,254`) and the column's stored min / max / top values from `table_stats`.<br>**Applied to:**<br>• **SHAP row** (`explain._mask_shap_row`: contribution values and a tagged label; the cache file keeps stored values);<br>• `/runs/{id}/explain` (worst cases' features);<br>• **slices** (definitions, levels, rows, pool, slice SHAP);<br>• **Model Doctor** (plus `pii_features`: the run's features with a PII / protected tag, C §4.3);<br>• **Data Doctor** example rows.<br>**Holdout predictions** hold no feature values; only a PII-tagged label would be masked. |

## Deviations and notes for dependants

- **A denied unmasked read in `audit` mode stays masked.** P19's audit mode lets a denied request through. Here the
  request is answered, but masked, with `unmasked_refused`, the would-deny header and the audit row. Showing PII on a
  would-deny would make audit mode a leak.
- **Reason length 2–500**, not the edit's 3–500, because the done-when uses `reason=QA`.
- **Suggestion timing.** Suggestions are written by `mask.ensure` at the first read of a table's content: any masked
  read, `GET …/pii`, or the dataset detail. They are not written in the commit job. This avoids touching `writer.py` /
  `lake/stats.py`, and no read can happen before them. `/uploads/{u}/check` shows them before the commit.
- **Two implementations of the masks.** The plan wants every masked read in the one DuckDB builder. Rows, grid,
  lookup, filter preview, count, export, the agent CSV and diff samples (Parquet) are. The diff's cached cells, the
  stats, the profile, error messages and the run pages hold values that are already computed (cached JSON, pandas run
  frames), so they use the Python masks. Those are checked identical to the SQL ones.
- **Run pages are masked by a net** (`Mask.scrub`), not at the source: `vela/doctor.py`, `slices.py`,
  `data_doctor.py` and `explain.py` (beyond the SHAP row) were not edited (P11's / other lanes' files). The net is
  thorough (pairs, enclosing column, tables, strings with number formats and the stored min / max / top values), but it
  is a net. Run pages have **no unmasked path**: the run's own features in the clear are a training-side right.
- **Not masked (outside P20's list), for a later phase:**
  - anomaly top rows;
  - shift rows;
  - the active-learning queue and annotations;
  - Feature Lab previews;
  - the edit preview's frames: they are scrubbed, but are a pandas read;
  - `split-options` / intake examples;
  - fairness group values: a protected column is not masked by default;
  - the upload `/check` preview of the uploader's own file;
  - search text (`q`) kept in `dataset_read` audit rows.
- **The agent's batch score** uploads the masked CSV, so a model that uses a masked feature scores masked values. That
  is the plan's rule (agent CSV through the masked scan). The Model Doctor flags such features in `pii_features`.
- **Files outside the row** (small):
  - `main.py`: `/rows`, `_detail`;
  - `lake/pages.py`: `masked`, `wrap`, masked columns not searched;
  - `lake/diff.py`: the P08 hand-off;
  - `lake/upload.py`: `_mask` uses the shared masks;
  - `engine/api.py`: explain, holdout predictions;
  - `engine/slices_api.py`, `vela/api.py`: the doctor route, not `doctor.py`;
  - `data_doctor_api.py`.

  P11's merge (5fe4afa) auto-merged cleanly into `engine/api.py`, `explain.py` and `slices_api.py`.
- **For P21 (shares):** `for_request` decides `data.read_unmasked` with P19's rule, which has no shared-`pii='unmasked'`
  case yet. P21 should add it to the rule and leave this code unchanged.
- **For P23 (Postgres):** `catalog_meta` holds `pii_salt:<team>`; copy it verbatim, or every hash mask changes.

  - a tags panel on `GET/PUT …/pii` (`pending_review`);
  - `tables[].pii` in the upload check;
  - `pii_features` in the Model Doctor.
