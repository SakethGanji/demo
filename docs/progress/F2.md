### How the defaults were chosen (sample, seeds 0–3, P@90 / bursts found)

| forest inputs | ψ = 256 | ψ = 1024 | ψ = 2048 |
| --- | --- | --- | --- |
| round-1 (group + Δt) | 0.71 / 2 (seed 0) | 0.72–0.74 / 3–5 | 0.72–0.77 / 4–7 |
| + all 7 velocity columns | 0.62–0.66 / 11–14 | 0.70–0.71 / 13–14 | 0.69–0.72 / 11–14 |
| + all 7, sums log-scaled | 0.61–0.68 / 13–15 | 0.69–0.72 / 15–17 | 0.68–0.74 / 13–17 |
| **+ n₁ₕ, n₂₄ₕ, Δ (default)** | 0.68–0.76 / 4–13 | **0.80–0.82 / 13–17** | 0.80–0.81 / 13–16 |
| + n₁ₕ, n₂₄ₕ, Δ, k₂₄ₕ | 0.62–0.68 / 7–14 | 0.76–0.79 / 12–14 | 0.78–0.81 / 12–16 |

Two causes: (1) an isolation split picks a feature uniformly, so near-duplicate columns (Σ_W ≈ n_W·x̄, k ≈ n, the
running-mean ratio ≈ the leave-one-out ratio) multiply one signal's say and dilute the others: night/foreign fell
from 18 to 3–10 with all seven; (2) with ψ = 256 a tree has < 1 burst row and the single-feature extremes are masked
by chance; ψ = 1024 helps every configuration. Combining a separate velocity forest (max or mean of scores, max of
percentiles, max of robust z) was also tried: P@90 0.20–0.68, never better.

## What changed

**Backend (`app/anomaly/`).**
- `velocity.py` (new): per entity and time, from the entity's **earlier** rows only (t_j < t_i): `txns_prev_1h`,
  `txns_prev_24h`, `amount_usd_sum_prev_1h/24h`, `distinct_<category>_prev_24h`, `<amount>_over_running_mean`,
  `log_hours_since_prev`. Vectorised per entity with `searchsorted` and cumulative sums. New rows (batch, Try It,
  registry batches) are computed against the saved training history (entity, time, amount, category; in the joblib
  model) plus the batch, a row already in the history (same entity, time, amount) counted once, so re-scoring a
  training row gives its training features.
- `core.run`: velocity on by default when entity and time are mapped (`velocity_features`), amount = the first
  relative column, category suggested (`merchant_category` on the sample). The group Δt is replaced by the velocity
  gap (same quantity). The forest sees `velocity_in_forest` (default: n₁ₕ, n₂₄ₕ, Δ); the rest are still computed,
  shown in the row values and given to the supervised model. **`max_samples` default is now min(1024, n)** (was
  sklearn's 'auto' = 256; still selectable). `data.velocity` holds the spec, columns, per-column mean / p99 / max.
  `derived.csv` holds every derived column per row.
- `labels.py` (new) + routes: `GET/POST /api/anomaly/runs/{id}/labels` (confirm = 1, dismiss = 0, null clears),
  stored with the **dataset** (`anomaly_labels.json`; a transaction is fraud whichever run flagged it), audited
  (`anomaly_review`). `/top` rows carry their `review`; `review.can_train` once ≥ 10 confirmed (`MIN_POSITIVES`).
- `POST /api/anomaly/runs/{id}/supervised`: a new dataset version (data + derived columns + `anomaly_score`,
  `lof_score` + `confirmed_fraud`; stratified holdout and folds on the label; lineage to the parent) and an ordinary
  AutoGluon run through the engine (`problem_type='binary'`, `eval_metric='average_precision'`,
  `num_bag_folds=5`, IDs / entity / time dropped; everything else as any run: leaderboard, explain, register).
  `negatives`: `unlabeled` (PU, default) or `dismissed_only`. `GET …/supervised` lists them and, once finished,
  computes and caches the comparison: AutoGluon's `predict_proba_oof` for the training rows and `predict_proba` for
  the rest, then IF vs supervised on the unreviewed rows (truth_check: P@k, AP, AUC, per kind).

**UI (`features/anomaly`).** Setup: a Velocity features block (amount, category, the formulas, Advanced: which columns
the forest sees with the reason) and ψ in an Advanced fold-out (the formula shows the rule). Run: a velocity card
(formulas bound to the run's columns, per-column mean / p99 / max, forest marks), the truth card's text, ✓/✕ review
buttons in the top-rows table and "Confirm fraud / Dismiss" in the reason card (acting-as name from the registry),
and a **Review → supervised model** panel: the PU formula with every symbol defined, progress to N, Train supervised
(Advanced: time limit, presets, negatives, score as feature), each supervised run with status, links to its run and
Explain, and the comparison table.

**Smoke.** New steps `anomaly: velocity features (F2)` (velocity on by default, ψ = 1024, a round-1-config run for
before → after, bursts ≥ 10, P@90 ≥ 0.71, and the 24 h count, 24 h sum and gap of the top 40 rows recomputed in
pandas from earlier rows only), `anomaly: confirm / dismiss` (review the 90 flagged rows, clear and re-set one, the
audit entry), `anomaly: train supervised (PU, F2)` (the run, its binary label, ≥ 4,000 out-of-fold rows, the
comparison on 5,910 unreviewed rows).

## Open problems

- The forest trades signals: bursts 2 → 13/18 but amount spikes 8 → 7 and night/foreign 18 → 16. The remaining 5
  bursts look like normal second transactions (a 1–5 min gap is rare but not unique: about 100 normal rows have another
  transaction in the previous hour).
- The supervised model's reviewed rows were chosen by the forest's score, so s nearly determines ŷ on the labelled
  rows (holdout AP ≈ 1.0; Vela's leakage check flags `anomaly_score`). The fair test is the unreviewed-row table.
  It learns only kinds the analyst confirmed (PU assumes confirmations are a random sample of frauds: they are not,
  they are the forest's top). Turning the score off (`include_score: false`) is in Advanced.
- The supervised model needs the derived columns (velocity, group, s): registering it works like any run, but
  scoring raw transactions through the registry would need the anomaly run's feature step in front; not done.
- Velocity windows are fixed (1 h, 24 h); the running mean uses all earlier rows (not a 30-day window). The saved
  history is the whole training frame's four columns (fine at this size; large tables would want the last 24 h per
  entity plus running sums).
- Labels belong to the dataset, not to a run; a new upload of the same file is a new dataset with no labels.
- Registry batch on 800 resampled rows: 5/8 amount ×30 rows flagged vs 6/8 in S9 (s* is higher at ψ = 1024).
