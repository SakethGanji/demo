# G4 · Fair-lending check without protected attributes (BISG)

**What it does.** Most credit products don't record race or ethnicity, so a lender can't check approvals by group directly. This check estimates each applicant's group probabilities from **surname × zip (BISG)**. It then reports, for each group:
- the approval rate;
- the **adverse impact ratio** (AIR, against White);
- the approval-rate difference;

each with a 95% bootstrap CI. It also runs F4's fairness metrics on the probability-weighted groups, and says how wrong the proxy is.

Where it lives (no new navigation):
- **Registry → version → Fair Lending** (binary tabular versions);
- **Models → run → Explain → Fairness**: "estimated race/ethnicity (BISG)" is a new choice in the existing group select, and the default when the table has a surname column;
- the model card;
- a Build suggestion.

## Backend
- **`fairlending/tables.py`: the BISG tables.**
  - It bundles a **synthetic stand-in** in the Census format: 2,000 invented surnames with P(group | surname), and 400 invented zips with population by group.
  - It is labelled as synthetic in the API, on the page (warning pill and note) and in the model card.
  - If `<data_dir>/bisg/surnames.csv` (the Census 2010 surname file, "(S)" handled) and `zips.csv` exist, they are used instead.
  - Groups: White (reference), Black, Hispanic, Asian/PI, AIAN, Multiracial.
- **`fairlending/bisg.py`: the maths.**
  - **The proxy:** p_ir = P(r|s)·P(g|r) / Σ_r′ P(r′|s)·P(g|r′). An unknown surname gets the table's prior; an unknown or absent zip gives surname only.
  - **Approval rates, two estimates:**
    - **Plain weighted:** Σp·a/Σp. This is the textbook version, and it is *attenuated*: gaps shrink because each group's weight includes other groups' members.
    - **Corrected (the headline):** solve Q·A = b, where Q_rr′ = Σ p_ir p_ir′ and b_r = Σ p_ir a_i. This is a method-of-moments correction, valid when P is calibrated and the decision depends on the group only through the applicant's data.
  - **Intervals:** AIR and difference CIs come from 400 multinomial bootstrap resamples, for both estimates.
  - **Which groups are judged:** groups need n_eff = Σp ≥ 50 **and** separability S_r = Σp²/Σp ≥ 0.5. Below that the proxy can't tell the group apart; Multiracial gets S = 0.20.
  - **F4 metrics:** fairlearn `MetricFrame` runs on stacked rows with `sample_weight = p_ir`.
  - **Proxy quality:**
    - always: the expected accuracy, mean max p;
    - with a true-group column: accuracy, Brier, and per group the recall, precision, mean p and estimated vs true share, plus the confusion matrix.
- **Route `GET /api/runs/{id}/fair-lending`** takes optional `surname`, `zip` (empty = surname only), `truth`, `t` and `favourable`.
  - **Zero-config:**
    - surname, zip and the true group come from the G0 roles;
    - t is the run's threshold;
    - "approved" means ŷ ≠ positive when the label reads adverse (default, fraud, …).
  - **Storage:** the headline is stored on the run (`fair_lending`), and the model card shows it (JSON/MD/HTML + view).
  - **Explain:** the Explain response gains `bisg_surname`.
- **G0 (intake):**
  - **New role `protected`** (race, ethnicity, gender, sex, religion, …), excluded like id/leak/constant.
  - **Never model inputs:** `surname` and `zip` are now left out of training pre-fills (redlining risk), and Build's "left out" counts them.
  - **New suggestion `fair_lending`** (score 72) appears once a binary version of the table is registered, and opens its Fair Lending tab. The binary suggestion says these columns are kept for the check.
- **Sample `samples_g4.py` → `fair-lending`** (no existing sample file touched):
  - 20,000 applications with surname, zip, income, score, DTI, loan amount, employment and home ownership;
  - `defaulted`;
  - the hidden `race_ethnicity_true`.
  - Surname → group → zip is drawn from the same tables (s ⟂ g | r). The default depends on the features only, with group-shifted income and score, so disparities arise through the features.

## Numbers (smoke `fair`, zero-config pre-fill, quick GBM, F7 cost, t = 0.083)

The holdout is 4,009 applicants (out-of-time) with an approval rate of 42.8%. Against the hidden true groups, the proxy's accuracy is **86.3%** (it expects 86.1%), with Brier 0.205.

| group | AIR corrected [95% CI] | AIR true groups | plain weighted |
| --- | --- | --- | --- |
| Black | **0.515** [0.433, 0.605] | 0.515 | 0.699 |
| Hispanic | **0.650** [0.575, 0.730] | 0.663 | 0.733 |
| Asian/PI | **1.002** [0.901, 1.099] | 1.019 | 1.068 |
| AIAN | **0.621** [0.455, 0.779] | 0.611 | 0.734 |
| Multiracial (not judged, S = 0.20) | 0.651 | 0.781 | 0.873 |

- **Acceptance: met.** The largest |AIR − true AIR| over the judged groups is **0.016**, within ±0.05.
- **Plain weighting fails it** (0.183 max). That is why the corrected estimate is the headline; the plain one is shown beside it.
- **The page labels the proxy's error** (hero, note and "How Good Is The Proxy").
- **Surname only (no zip):** proxy accuracy 0.781.
- The endpoint takes ≈ 1.8 s.

**Smoke.** `SMOKE_ONLY=fair,intake,core make smoke` passed **37/37 in 150 s**: fair 4 steps; intake 13, with the new fair-lending truth row at 12/12 and the other 9 samples unchanged at 100%; core 20. `npm run build` and `tsc` pass.

## Limits and open problems
- **The tables are synthetic** and calibrated by construction, so the proxy is better behaved than real BISG. On real Census tables, both the accuracy and the correction will be worse: the correction needs calibrated P and no zip/surname effect on the decision beyond the group. The real tables are not bundled (size and download).
- **Multiracial can't be estimated** by BISG (S = 0.20). It is shown but not judged.
- **The zero-config threshold is harsh.** The F7 cost (c_FN = 10·c_FP) gives t ≈ 0.08 and 43% approval, which makes the AIRs low. The check uses whatever threshold the run has.
- **Scope:** only the holdout is checked; scored batches are not. Groups are fixed to the Census six.
- **Not in the Model Doctor or Vela yet.** G10 could expose the route as a tool.
- **Smoke leftovers:** each run adds one fair-lending run and a `smoke.fair-lending` version.
