## What was built

| Piece | Where | What it does |
|---|---|---|
| **The edit SQL compiler** (§5.5) | `dataset_edit.py` (`compile_ops`) | **The ops become one DuckDB query.** Each op adds a temp view (`_e0` = the parent table with `__row_id`, `_eN` = the edited table), so the writer's `COPY` runs one query over the parent.<br>**How each op compiles:**<br>• `set_cells` → a typed VALUES table joined on `__row_id`;<br>• `delete_rows` / `filter_rows` → a WHERE from the whitelisted filter AST (eq/ne/lt/le/gt/ge/contains/in/is_missing/not_missing; `ne` keeps pandas' "missing ≠ x");<br>• `add_rows` → `UNION ALL BY NAME` with ids `next_row_id + k`;<br>• rename / drop / add_column → an explicit select list;<br>• a formula → SQL from the `ast` (never eval). ÷0 and log/sqrt of a negative are NULL; an overflow is ±inf and refused (`non_finite_result`); `round` is `round_even`, as numpy does;<br>• `cast_column` → `TRY_CAST`, with the count of values that became missing;<br>• `replace_values` (exact / contains) and `fill_missing` (constant / mean / median / mode). A fractional mean in a whole-number column widens it to DOUBLE, and the widening is reported.<br>**Rows are addressed** by `row_id` (`__row_id`), or by `row` (the grid's `_row` position), which is translated through the row order (§5.5: "for one release"). Each op's log has its counts and up to 20 examples.<br>**Value checks** (§4.4) run before any SQL is compiled: every value goes through `lake.values.check` against the column's DuckDB type. After each op, every touched number column must stay finite with a finite sum and mean. Any engine error is a 400 `edit_invalid`; the engine text is logged and never returned.<br>The pandas `apply_ops` is gone; `_coerce` stays for Data Doctor. |
| `edit_version` | `datasets.py` | **Before the edit.** The parent is re-hashed (§5.5), unless every part has `blobs.verified_ok = 1` from the last 24 h. A mismatch gives a 409 and the audit row `dataset_integrity_failed`. A CSV-era parent keeps its data.csv sha check.<br>**Compile and check:**<br>• the DL3/DL4 target guards (drop / rename / cast refused without `set_target`, whose reason needs ≥ 10 characters);<br>• `set_target` must name a column with ≥ 2 classes;<br>• the **one-class block** (`400 target_one_class` unless acknowledged), counted in DuckDB (`guard_one_class_counts`);<br>• the caps: 200 ops, 5 000 cells, 1 000 added rows;<br>• at least 2 rows and 2 columns.<br>**The summary is the diff on `__row_id`:** matched, changed (a shared column of the same type family differs), added, removed. The contract warnings come from P06's `Matcher.contract`, with renames reported. Also: `types_changed`, the schema kinds and the target before / after.<br>**Preview** writes nothing; it returns the summary plus 5 sample rows.<br>**Commit.** `VersionWriter(op="edit", dedupe=True)` writes `_eN` as the edited table. The parent's other tables are carried, and the parent's keys are re-validated. `provenance.ops` records the op summary and row counts. A **repeat edit returns the existing version** (data_sha256). |
| **The `derive()` contract** | `datasets.derive` + `lake/derive.py` (new) | **One way to make a derived version.** Its signature is unchanged, so every caller works: Data Doctor (+ relabel = `clean_labels`), Feature Lab, Autopilot (keep mask, synthetic rows), active learning, anomaly review, shift weights, annotations, the sample generator and `create_version`. It now writes **Parquet through the VersionWriter**.<br>**Row ids.** A kept row keeps the parent's `__row_id`. A new row gets `next_row_id + k`. A CSV-era parent's ids follow P06's rule (`lineage.json` root_rows, else `0..n-1` for a root). A CSV-era non-root with no row mapping gets fresh ids and an unpaired edge.<br>**Kinds are preserved** (`typed_select`, P04's handoff). A column the parent has is written in the parent's type when its values fit exactly:<br>• float64 back to BIGINT (an int column with missing cells under engine_v1);<br>• ISO text back to DATE / TIMESTAMP;<br>• text "0"/"1" back to BIGINT.<br>A real change (values no longer fit) keeps the frame's type and adds a `type_changed` warning. The notes go into the manifest op (`types`) and the profile (`types_kept`).<br>**Only the primary table is written;** the others are carried. **Dedupe** follows `datasets.DEDUPE_OPS` (writer flag `dedupe`). **No floats** in the provenance: a caller's change list is made float-free (`no_floats`; found when active learning's `share: 0.5` hit the canonical-JSON check). |
| `_sample_as_version` | `datasets.py` | P06's handoff. Matching now runs on the `Matcher` with an **explicit method**: the parent's confirmed key, else `row_hash`. The method and its counts are recorded in the manifest op (`match`). The last `guess_key` / `match_rows(None)` caller is gone. |
| Active learning | `engine/active_learning_api.py` | The label keeps its kind (P04's handoff). A numeric label stays numeric (float while cells are hidden, never `object`). An answer given as text ("1") becomes the class value. derive() then writes it back as the parent's BIGINT. The frame is read by position (`reset_index`). |
| Positional reads | `data_doctor_api.py`, `featurelab_api.py`, `autopilot/engine.py` | `frames.read_version(…).reset_index(drop=True)` where rows are addressed by position (issues, keep masks, split masks). A Parquet version's index is `__row_id`, which has gaps after an edit. |
| Writer | `lake/writer.py` | A `dedupe: bool \| None` argument. The default is unchanged (`op in DEDUPE_OPS`). |
| The bridge until P09 | `lake/derive.py` (`carry_split`, `reorder_split`, `legacy_bridge`) | **Split JSON.** As P06 did, the new version gets a DL4 split JSON carried by `__row_id`. A kept row keeps its fold and holdout. A new row goes to the holdout by `splitmix64(__row_id ⊕ seed)` < share, else to a fold by the same hash. A caller's given split (by frame position) is re-indexed to `__row_id` read order.<br>**`lineage.json`** gets `root_rows = __row_id` and `parent_rows`, so the CSV-era diff and compare pair on the same rows the manifest records. The legacy record (profile, target, kind) comes from P05's `finish_lake_version`, plus the lineage summary. |

## Deviations and notes for dependants

- **Files outside the row (all lane D, small):**
  - `lake/derive.py` (new): the pandas adapter and the bridge;
  - `lake/writer.py`: the `dedupe` flag;
  - `data_doctor_api.py` / `featurelab_api.py` / `autopilot/engine.py`: positional reads only.
  - No UI file was touched (lane U, U1, owns them).
- **Not run end to end here:** Autopilot, anomaly review, shift weights and annotations. They call the same `derive()` with the
  same arguments as before (keep masks, given splits, new rows). Doctor (keep mask), Feature Lab (given split) and
  active learning (given split, text labels) exercise those paths.
- **Still writing CSV:**
  - `create_from_frame` (G9 SQL source: a new dataset, not a derive);
  - `ensure_samples` (sample roots);
  - `registry/monitoring_api.py` (monitoring windows).

  None is a derive() caller. The SQL refresh is P05/R-G's "upload-as-version". The samples and the windows are left for
  P10/P12 or a follow-up slot. `upload_version` (adopt-disk-file) stays on the legacy "hash" match and now writes Parquet
  through derive().
- **Grid rows:** `_row` (a position) is accepted and translated. **U1 should send `row_id` (`__row_id`) in `set_cells` /
  `delete_rows`** (`row_ids: [...]`). The examples in the edit log now name `row_id`, not `row`.
- **Edit preview `sha256` is null.** Nothing is written in a preview, so the data identity is unknown until the commit, and
  the commit dedupes.
- **The old catalog diff** (`GET …/diff`, `dsets.py`) skips a column whose pandas dtype changed. Example: an int label with
  hidden cells reads as float64, so the AL version shows changed 0 although 380 labels were hidden. P08's two-pass DuckDB
  diff replaces it.
- **Split JSON and `lineage.json` bridges** are written for every derived version (P09 replaces them with Parquet splits,
  same rule).
- **Scratch:** the data dirs, the venv and the API process were in the session scratchpad and are removed.

## Follow-up: Data Doctor's label job on Parquet versions (reported by U1 via the orchestrator)

**The bug.** `data_doctor.label_key()` stat-ed `datasets/<id>/data.csv`. A Parquet version has no such file, so the
background label-quality thread raised `FileNotFoundError` on every `GET …/data-doctor` of a new upload, although the
endpoint itself still answered 200.

**The fix** (`data_doctor.py`, `data_doctor_api.py`):
- `label_key` / `label_state` / `start_labels` now take the **version id**, not a path.
- The cache key is the Parquet table's `table_sha256`. A CSV-era version keeps its file size and mtime, still reached
  through `frames.version_file`.
- The job reads through `frames.read_version`.

No other data.csv path is used in either file.

**Verification** on a fresh data dir: a new upload (`ds_965ff7f4`, Parquet) and the CSV-era sample `credit-default`.
`GET …/data-doctor` answered 200 for both. Their label jobs finished:
- Parquet: `status done`, key `y|852ad92c…` (the table sha), 149 labels flagged in 2.2 s;
- CSV-era: `status done`, key `defaulted|1313788|…`.

The API log had 0 tracebacks.
