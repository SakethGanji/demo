## What was built

### `frames.py` additions

| Helper | What it does |
|---|---|
| `version_file(id)` | The file a CSV-store version is written to. Used by the writers in `datasets.py` (until P07), by hashing, and by run configs' `csv_path` key. Never read directly. |
| `read_version(id, columns, rows)` | `read(Table(id))`. Replaces `load_frame`. |
| `parse_text(text, sep, name)` | The typed CSV parse: `;` files with decimal commas, leading-zero codes kept as text, plain `DatasetError` messages. The dataset upload (`datasets.read_upload`) and batch files (`read_upload`) both use it, so the parse rules live in one place. |
| `parse_csv(src, schema)` | The one `pd.read_csv` behind every typed read. `frame_io.read` delegates to it, so `frame_io` is now frames' private helper. |
| `export_schema(id)` | The `schema.json` in the export zip. |
| `read_upload` | Also reads `.xlsx` (first sheet, same leading-zero rule). |

- The forecast time column stays a string under `engine_v1`.

**R-F: the registry.**
- `scoring.read_batch` is the one reader of a batch's `input.csv`, which holds the user's upload byte for byte. It calls `read_upload`, then `align_to` the run's table. This is P03's handoff: a zero-led code stays text when it is scored.
- `score_batch`, `score_flow_batch`, monitoring, changes and the credit report all read batches through it.
- Training references use `frames.read(resolve(cfg))`. Artifacts use `read_artifact`.
- Credit-report tapes keep every cell as text, and now detect the encoding and separator (`_read_tape`).
- `build.py` hashes `frames.path_of(resolve(cfg))`, which is the same file and the same hash.
- `registry/api.py` and `engine/api.py`: `holdout_frame(frames.resolve(cfg))`. It was already typed as a `LegacyPath`; this is only for consistency.

**R-G: other.**
- `sqlsource` builds the demo database and the refresh diff through frames.
- `frame_io.read` delegates to `frames.parse_csv`.
- `gym/export`:
  - the exported script's body (its helpers and `main`) moved verbatim into `gym/export_body.py.tmpl`. The reads in it belong to the standalone script, not the app, so the `*.py` gate does not cover them.
  - the script now carries `TEXT_COLUMNS` from the version's schema and reads those columns as text, as the fit did.
  - `n_rows` and the data hash come through frames.

### §4.4 and the P03 handoff

| Item | Where | Behaviour |
|---|---|---|
| `values.check` in the Data Doctor apply | `data_doctor.check_values`, `data_doctor_api._apply` | Each value a fix writes is checked against the version's schema before anything is applied:<br>- `split_codes fill` (via `dataset_edit._coerce`: integer bounds, the 2^53 rule on the CSV store);<br>- `relabel labels`;<br>- `merge_classes into` (VARCHAR);<br>- `rescale factor` (a finite DOUBLE).<br>A rescaled column must stay finite (`check_column` → `non_finite_result`).<br>Engine errors become `400 edit_invalid`; the text goes to the log `ensemble.edit`. |
| One-class target block | `datasets.guard_one_class`, used by `edit_version` and the Doctor apply | An edit or fix that leaves a ≥2-class target with one class gets `400 target_one_class {column, classes_before, classes_after}`. With `"acknowledge": ["target_one_class"]` it goes through, and the warning is stored in the checks or the lineage. |
| Reset request marked `used` | `reset.check` | A `request_id` that is sent is always checked and returned. Before, `check` returned None when nothing was live, so the request stayed `approved`: it could be reused, and it blocked every new request with 409. |
| `runs_made_irreproducible` | `catalog/dsets.request_delete`, `get_request` | Computed for every delete request (`[]` when no run loses its data) and returned at the top level of the pending response. Before, it was only inside the `options` JSON string. |
| Rename hint | `dataset_versions.rename_hints`, `contract_checks` | The upload check lists `column_renamed_maybe` pairs (same schema kind, ≥ 95 % of the new column's distinct values are the old column's) as warnings and in `checks.renamed_maybe`. It is never applied automatically. |
| `schema.json` in the export zip | `frames.export_schema`, the export route | `{format, version_id, read_mode, tables: [{name, file, rows, columns: [{name, kind, type}]}], source}`. `source` says "inferred" for a version made before DL4. |

## Deviations and notes for dependants

1. **Files outside the P04 list. All are small, and none is being edited by an active lane right now:**
   - `main.py`: 3 read lines plus the import. It does not touch P02's startup hook or P18's routers, and the merge was clean.
   - `reset.py`: the "used" fix.
   - `dataset_versions.py` (P06's file): `rename_hints` plus one call in `contract_checks`. It is purely additive.
   - `engine/api.py` and `registry/api.py`: `holdout_frame(frames.resolve(cfg))`.
2. **P05 (started) overlaps** `frames.py`, `datasets.py` and `catalog/datasets_api.py`. In them:
   - `DatasetStore.csv_path` is now `data_file` (writer only), and `load_frame` is gone: use `frames.read_version`;
   - `frames.parse_text` is the shared upload parse;
   - the export uses `frames.version_file` + `frames.export_schema`. With Parquet, `export_schema` should list the manifest's tables.
3. **`gym/export_body.py.tmpl`.** The exported script's body is a template file. Its `pd.read_csv` calls belong to the standalone script, so the `*.py` gate does not see them. P05 should change the template to read Parquet once exports are Parquet.
4. **XLSX** batches and uploads go through `pd.read_excel`. `openpyxl` is not in `requirements.lock` (P12 adds calamine or openpyxl). Until then an `.xlsx` gets `400 "Could not read … as an Excel workbook."` Only CSV and Parquet were exercised.
5. **Behaviour changes, all deliberate:**
   - batch files and credit-report tapes get encoding and separator detection, and Parquet;
   - upload and tape errors no longer echo pandas' text;
   - the SQL demo database is built from typed reads;
   - a one-class target edit is blocked unless acknowledged.
6. **Active learning writes labels as text** (`ds_21f5a289` `defaulted` kind `text`, where the parent's is `integer`), because the queue's classes are strings. This happens before this phase's changes, in the active-learning write path, which moves to `derive()` in P07.
7. **`rescale` messages** say "Operation 1" (the wording of `values.check_column`), while the other Doctor refusals say "Fix 1". Both carry `op_index`.
8. **Process:** R-E and R-F were swept by two helper agents in parallel, on their own ports and data dirs. All three of us briefly ran `git stash` / `pop` to lint the old code. The pops were clean, `git stash list` is empty, and the full diff was re-checked (gate, pyflakes, `import app.main`). Scratch predictors, data dirs and the old-code worktree are deleted.
