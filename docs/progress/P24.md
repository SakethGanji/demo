When every team approved → **execute, all-or-nothing**: re-computed (a new team → 409 `impact_grew`, a hold → 409), then one transaction: referencing versions → `deleted`, run pins → `purged:<role>` markers, other refs dropped, the default moved if needed, blobs → `purging`; then each blob through `delete_blob(bypass_governance=True)` → `purged`. `POST /purges/{id}/resume` finishes bytes that failed. | **Join caches after GC** | `catalog/joins.py` (1 statement) | A frame whose cache GC removed is materialised again (the blob row goes back to live only when `purge_reason` is `gc:%`); a purged cache stays purged. |

## Also checked

- **Nothing runs on its own.** No timer calls retention, GC or purge (`grep` of `main.py`, `jobs/`, `engine/workerd.py`:
  the only callers are the routes above). The one existing timer is DL2's opt-in `ENSEMBLE_VERIFY_EVERY_HOURS`
  verify; a pass it makes can arm GC (it deletes nothing). `config.RETENTION_POLICY` keeps only the pin rules; the day
  periods (7 / 30 / 3) are gone. A team with no `retention` policy has 0 candidates and `no_period_set` lists every
  category (step 4a).
- **Every action is audited and the chains verify** (step 7): `legal_hold_placed/_released`, `dataset_delete_*`,
  `retention_dry_run`, `retention_run`, `retention_evict_cache`, `gc_dry_run`, `gc_run_started`, `gc_run`, `gc_armed`,
  `blob_deleted`, `purge_requested/_approved/_executed/_bytes_deleted`, and every refusal as `*_refused`.
  `GET /teams/{t}/audit/verify` → `ok: true` for Credit Risk, Collections and tm_default on all three runs.
- **GC on S3 with Object Lock** (`s3check.txt`): bucket with Object Lock enabled; after the chain **27/27 purged blobs have no object version left** and **60/60 live blobs are present under GOVERNANCE retention** (GC and purge used the governance bypass: `blob_deleted.bypass_governance: true`, `versions_removed: 1`). `abort_stale_uploads()` ran with each GC run (`aborted_multipart: 0`).
- **legacy_json and pre-P24 deletes** (`extra.sh` → `extra.txt`, on the SQLite chain's data): a DL4 split JSON put as a live `legacy_json` blob: verify-all → `ok: true, legacy_json {checked: 1}`; its stored bytes rewritten → verify-all **`ok: false`**, the blob listed with its new hash (and a pass that fails does not count, so it could not have armed GC). Also there: a version deleted the pre-P24 way (state only, refs kept) is listed by the GC dry run under `deleted_versions_with_refs`; the run drops its refs (`gc_refs_dropped`), the next dry run lists its table part, and that run deletes it.

## Deviations and limits

- **Orphans** (objects in the store with no `blobs` row, GC phase 2) are reported, not deleted: the rule is that bytes go
  only through `delete_blob`, which needs a row. Stale `tmp/` writer scratch (never blobs) is removed by a run.
- **Retention of versions requests deletes** (four eyes) rather than deleting: a retention run never removes data without
  the second person today's delete needs. The bytes then go with the next GC run.
- **Purge:** not built: the redacted manifest for sensitive column names (§5.10 step 4); a purge while any version of the
  dataset is still CSV-era (409 `not_parquet`: migrate first). DL2 `holdout_sample.csv` files of the deleted versions
  are unlinked (no per-file audit row). Share grantees **without** runs on the data are listed in the report but do not
  have to approve (their teams hold nothing that breaks); grantees with runs do.
- **`blob_deleted` audit rows** land in the chain of the request's team (Collections for Cole's approval): that is
  `lake.store.delete_blob`'s (P10b) scoping; the `purge_*` rows are in every involved team's chain.
- **GC race** (§7 R-S3): a writer that re-puts a blob between GC's `purging` mark and the delete is detected after the
  delete and audited `gc_race`; its bytes would have to be put again. Not reproduced here.
- **Files outside the lane** (small): `engine/api.py` (run delete: hold check, drop the run's pins), `lake/migrate.py`
  (`verify_run` reports `purged`), `catalog/joins.py` (re-create a GC'd cache), `authz/policy.py` (+1 action, +1
  four-eyes row), `main.py` (2 routers), `config.py` (`RETENTION_POLICY` periods removed), `lake/api.py` (GC route).
