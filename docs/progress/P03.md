## What was built

| Piece | Where | What it does |
|---|---|---|
| Typed reader | `backend/app/frames.py` (new) | `Table / JoinFrame / LegacyPath` refs, plus `to_json` and `from_json`.<br>`read(ref, columns, rows, mode="engine_v1", hash_into)`: `engine_v1` = `frame_io.read(raw, schema.json)`, exactly what the worker has always fitted on. The index is the data.csv row position (the CSV-era `__row_id`).<br>`resolve(cfg)`: `input_ref`, then `csv_path`, then `join_frame_id`, then `dataset_id`.<br>`input_ref_for(id)`, `path_of(ref)`, `columns`, `column_names`, `n_rows`.<br>`read_upload(src, filename, kind, sep)`: user files; header, encoding and separator detection, leading-zero codes kept as text, `;` files with decimal commas, Parquet as stored.<br>`align_to(df, ref)`: casts a user file to the table's column kinds.<br>`read_artifact(path)`: files the app itself wrote next to a run. |
| Bounded values | `backend/app/lake/values.py` (new), `lake/__init__.py` (new, one docstring line) | `check(value, type)` for BIGINT, INTEGER, DOUBLE, VARCHAR, DATE, TIMESTAMP and BOOLEAN, per the §4.4 table.<br>`check_finite` raises `non_finite_result {count, examples}`.<br>`check_column`: a number column whose sum or mean overflows gets `value_out_of_range`.<br>`ValueRefused(code, message, op_index, column, type, min, max)`.<br>`json_safe` / `dumps` / `SafeJSONResponse`: `allow_nan=False`; a non-finite value becomes `null`, plus `"non_finite": true`. |
| Validation calls | `backend/app/dataset_edit.py` | Every value from `set_cells`, `add_rows`, `fill_missing`, `replace_values` and `add_column value` is checked against its column's type. `apply_ops(..., kinds)` gets the version's schema, so an integer column with missing cells is still BIGINT.<br>Formulas: ÷0 is missing (SQL semantics); an overflow is `non_finite_result`.<br>Any engine error inside an op is `edit_invalid {op_index, column}`. The engine text goes to the log `ensemble.edit` and is never returned. |
| Error mapping | `backend/app/main.py` | `default_response_class=SafeJSONResponse`; an exception handler maps `ValueRefused` to `400 {"detail": {code, message, …}}`. The UI's `client.ts` already shows `detail.message`. |
| Writer guard | `backend/app/datasets.py` (`edit_version`, 2 small changes) | Passes the schema kinds to `apply_ops`. If `roundtrip` or `to_csv_bytes` raises, the result is `edit_invalid` (logged), not a 500. |
| Edit route | `backend/app/catalog/datasets_api.py` (2 lines) | The preview and duplicate responses use `SafeJSONResponse`; they used `JSONResponse`, which 500s on inf. |

## Deviations and notes for dependants

1. **No `frames.scan`.** It needs DuckDB, which arrives with P01, and masking, which is P20. `agent/tools._dataset_csv` is typed but not masked yet; it moves to the masked scan in P20.
2. **`frames.read_artifact`** is not in the plan. It wraps files the app wrote itself (holdout_predictions.csv, shift scores and weights, annotations, the bundled BISG tables), so the grep gate needs exactly one allowed module. **`frames.align_to`** casts a user batch to a table's kinds; P04 should use it for R-F scoring.
3. **Behaviour changes, all deliberate per §4.4:**
   - A non-integral value into an integer column is now `400 value_invalid`. Before, it silently turned the column into floats.
   - A formula that overflows (`x * 1e308`, `exp(1000)`, `log(0)`) is now `400 non_finite_result`. Before, it silently became missing. ÷0 is still missing, which matches SQL/DuckDB.
4. **Added rule:** a number column whose sum or mean overflows is refused (`value_out_of_range`). 1.797e308 is a valid DOUBLE, but a column of them crashed the profile. This is how the `add_column 1.797e308` cases give 400.
5. **CSV-store limit:** an integer column with missing cells is held as float64 (data.csv reads it back that way), so its values are bounded to ±2^53 (`value_out_of_range`, min/max in the body). The Parquet tables of P05 lift this.
6. **Files outside P03's list** (neither is a P01 file):
   - `datasets.py` `edit_version`: passes the kinds and adds the writer guard;
   - `catalog/datasets_api.py`: 2 lines switch `JSONResponse` to `SafeJSONResponse` on the edit route.
7. **Not done here:**
   - **P04:** `values.check` in the Data Doctor apply (§4.4 names it; Doctor is R-D, P04/P07), and `schema.json` in the export zip.
   - **The smaller §4.4 items** are not in the §9.1 P03 row, so they are left for a follow-up slot: the one-class target block, the reset request marked `used`, `runs_made_irreproducible`, and the rename hint.
   - **Not exercised by a call:** learning curve, active learning, Vela experiments `delta` and the agent tool, beyond import and lint. The swept changes there are mechanical (`pd.read_csv(cfg["csv_path"])` → `frames.read(frames.resolve(cfg))`).
8. **`lake/__init__.py`** was created with a single docstring line. P02 (lane D) creates `lake/*` too: on a conflict, keep either version.
