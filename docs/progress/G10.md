# G10 · Vela Agent: an AI agent that does the work for you

**What it does.** **Vela** is now one page in the navigation with two modes:

- **Ask Vela**: the agent chat.
- **Run It End To End**: Autopilot, unchanged in capability.

You ask in plain language. The agent plans, then calls the workbench's own HTTP API one typed tool at a time and reads each result before its next step. Calls that only read run at once. Calls that change state stop on a confirm card that shows the exact call; you click **Run It** or **Skip**.

Approving a version and promoting it to Production are not tools. The agent can only request approval, which moves the version to Staging with a note. Every call goes to the registry audit log as "Vela agent on behalf of <user>". Every final answer passes through the F5 number guard against the tool results.

The sidecar's "Ask Vela" button stays on every page and gains an **Agent** tab: the same chat in compact form.

### The three scenarios

The wall time is end to end, including the clicks on Run It, which the smoke makes at once. One planner decision takes about 4–8 s through the CLI.

  5. `model_doctor`: overfitting (minor)

  7. `watch_run`

  9. `register_version`: mv_0faa143e.
  10. `request_approval`: Staging, still pending.

## What changed

**Backend: `app/agent/`.**

`tools.py` is the typed tool registry: 40 tools, each with a description, a JSON schema, a read or write kind, the route(s) it calls, and a page link. A tool calls the existing routes in-process through `httpx.ASGITransport`, so it gets the same validation, refusals and audit as the UI. It adds no business logic: it shapes the arguments, then trims the answer into a short digest. The tools cover:

| Area | Tools |
|---|---|
| Datasets | list, profile, upload, find rows |
| G0 | intake |
| G9 | SQL preview, save, refresh |
| Training | train from the intake pre-fill, start a run (Gym-validated), watch, results, list, compare |
| Diagnosis | explain, Model Doctor, preview and apply a Gym patch, Gym validate, split-twin, learning curve / shift / slices (start and read) |
| Registry | register, request approval, list versions, Try It, reason codes, counterfactuals (G1), batch score + drift, monitoring, credit report (G2) |
| Credit features | expected loss + stress (G3), fair lending (G4), segmented (G5), survival (G6), reject inference (G7), multi-label (G8), read a special run |
| End to end | start an Autopilot |

Two guards block approval and promotion: `_guard_path` refuses `/review` and any `transition` to Production, even from a free-form call.

`loop.py` runs plan → tool → result → continue:

- **Budgets:** 24 steps and 1,800 s by default. Time spent waiting for your click does not count.
- **Planners, in order:**
  1. The Anthropic SDK with native tool use (`claude-sonnet-5-5`, one tool per turn), when a key is set.
  2. Otherwise the F5 router's CLI path with JSON actions, validated with `jsonschema`. Three invalid replies in a row stop the loop.
  3. Otherwise **none**: the chat says so and offers the matching one-click pages.
- **Stub:** a deterministic planner (`decider: "stub"` or `ENSEMBLE_AGENT_DECIDER=stub`) that covers the 3 scenarios.
- **Confirmations:** a write waits on an event until `POST …/confirm` arrives.
- **Stop:** cancels the task. A run that was already started keeps going on the server, and the step card says so.
- **Number guard:** `llm.unsupported_numbers` checks the answer against the user's words and every tool argument and result. If it flags a number, the model gets one rewrite. Any number still flagged is shown on the answer.
- **Audit and storage:** every call, including declined ones, is written as `agent:<tool>` with the session, arguments and status. Conversations are saved in `data/agent/`. Admin reset clears them, and refuses to run while the agent is working.

`api.py` serves `/api/agent/…`:

- `tools` and `status`;
- `sessions` (start, list), `sessions/{id}` with `?since=rev`;
- `messages`, `confirm` and `stop`.

There is one new generic route, `GET /api/datasets/{id}/rows?value=&column=`. It looks up one applicant's row, and the agent needs it for scenario 2.

**UI.**

- **`features/vela/VelaPage.tsx`:** the header, and the **Ask Vela | Run It End To End** switch (`#/vela`, `#/vela?mode=auto`, `?s=<conversation>`).
- **`agent/AgentChat.tsx`:**
  - Each tool call is a compact card: status, tool, the read/write tag, seconds, one line with the arguments and a glance at the result, the full arguments and result on fold-out, and **Open →** to the page.
  - The confirm card shows the exact route chain and the arguments.
  - The page polls live while the agent works, and Stop replaces Send.
  - The answer card shows the decider, its latency and the number-guard line.
  - Example prompts and recent conversations; a footer with the planner, budget use, the tool count and "acting for".
- **Autopilot:** the `AutopilotPage` component is deleted. Its body is now `vela/autopilot/EndToEnd.tsx`, without its own header. The `live/` and `components/` folders moved under `features/vela/autopilot/`, and every capability is kept: the brief, the run view, the Ground-Truth Inbox, Stop and New Brief.
- **Redirect:** `#/autopilot[?ap=…]` redirects to `#/vela?mode=auto[&ap=…]` with a one-line rule in `routes.ts`, using `location.replace` so the mode readers update.
- **Navigation:** the sidebar's "Vela Autopilot" and "Vela AI Assistant" items become a single **Vela** item. The sidecar still opens from the context bar's Ask Vela button.

**Smoke:** a new `agent` section, added to the default `SMOKE_ONLY` list.

`npm run build` passes, and `tsc --noEmit` is clean.

## Open problems

- **The SDK tool-use path has not been run against the real API**, because there is no key here. It is written against the Anthropic Messages tool-use format, and on any error it falls back to the CLI JSON path for that turn.
- **The CLI path costs 4–8 s per decision.** A 10-call task spends about 60 s planning on top of the work itself.
- **The page polls (700 ms, `?since=rev`) rather than using SSE.** Updates look live, but they are not pushed.
- **Stop does not cancel a run or build the agent already started.** The card says so.
- **The number guard flags, it does not block.** The scenario answers passed without a rewrite.
- **Reason code R06 is region.** That is the existing F10 mapping, not the agent's choice, but a bank would likely mark geography as a reason not to show. It belongs to G4/G11.
- **`batch_score`'s score PSI came out null.** The drift answer used the per-feature PSIs only. The key name in the batch result still needs checking.
- **For G11:**
  - the toolbelt still lists "Delegate · Vela Autopilot";
  - `e2e/fixtures.ts` and `scripts/f19_shots.cjs` still name `autopilot` (the redirect handles both);
  - `docs/demo-script.md` is not updated.
