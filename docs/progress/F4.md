Status: **done. `SMOKE_ONLY=targets,core make smoke`: 27/27 green in 122 s; `SMOKE_ONLY=targets,core,samples,import,autopilot`:
43/43 green in 628 s (Autopilot's derived datasets and imports still work); `npm run build` passes.** Acceptance met: the deposits CSV uploaded **without** a target (the profiler

## Cause, confirmed

Before F4 a dataset had one split, `splits.json`, drawn at upload and stratified on the profile's target. Uploaded
without a target, that was the profiler's guess (`salary_credited`, binary), and a run on another label used it anyway.
Reproduced on the pre-F4 commit (`a14bdcb`, separate API and data folder, same CSV and fit):

## What changed

**Backend.**
- `splits.py`: `RANDOM_STRATIFIED = "random-stratified"` (the only strategy; F6 adds group / time), `split_key(target,
  strategy)` (readable slug + hash of the exact column name), `split_sha256` (of the holdout and fold arrays). A split
  records `target`, `strategy`, `key`; `summarize` adds `strategy`, `key`, `sha256`.
- `DatasetStore`: splits live in `data/datasets/<id>/splits/<key>.json`. `ensure_splits(id, target, strategy)` returns
  the stored split or draws it once from data.csv with seed 42 (so the same file and target always give the same
  holdout, whatever was guessed); it never redraws. The legacy `splits.json` is kept untouched (pre-F4 runs point at
  it) and adopted as the keyed split when it was drawn for that target (samples, Autopilot's and anomaly's derived
  datasets, whose holdout is given). `set_target` re-profiles for the confirmed target (classes, task, conflicts; keeps
  lineage, the sample kind and the original guess), stores `target_source = confirmed` and a `target_history`.
  `list_splits` lists every stored split. Profiles carry `target_source`: `given` (named on upload / sample), `guessed`,
  `confirmed`.
- `PATCH /api/datasets/{id}` `{target}` confirms the target (400 for an unknown or constant column);
  `GET /api/datasets/{id}/splits` lists the stored splits and the current key.
- `POST /api/runs` (and imports, and runs started by Autopilot / anomaly) take the split of the run's **label**, not
  the dataset's target: `cfg.splits_path` is that file and `cfg.split` / `run.split` records key, target, strategy,
  seed, stratified, holdout share and rows, SHA-256 and whether it was drawn for this run. Every consumer
  (worker, explain, registry build and card, export, heavy pool, Vela) already read `cfg.splits_path`, so they follow.
  The worker's `data_ready` event and `result.data` carry the split; the model card's split sentence names it.
- Autopilot reads the holdout of its own label (`splits_path(id, label)`).

**UI.** New Model → Target: a **Confirm The Target** card (top right). Not confirmed: what confirming does and a
"Confirm y = …" button; confirmed: H ⊂ {1…n}, |H| = 20 % · n, F₁ ∪ … ∪ F₅ = {1…n} ∖ H with every symbol defined
(rows, fold sizes, seed, stratified or not and why), the strategy, key and SHA-256, and a table of every stored split
(target, strategy, |H|, SHA-256, current). Continue and Start Training stay disabled until y is confirmed (the footer
says so); the label select marks "(confirmed)" and "(suggested)". The race's "The Fit" card shows H: the holdout drawn
for y, with its strategy and SHA. `scripts/walkthrough.cjs` clicks the confirm button.

**Smoke** (`targets` section, new; in the default `SMOKE_ONLY`): upload without a target (guess ≠ y) → API path
(upload naming y → train) → UI path (PATCH unknown column → 400; PATCH y → profile and split for y, split SHA equals
the API upload's, the guessed target's split unchanged and both listed → train with the wizard's body) → identical
holdout rows, labels, predictions, scores and best model → a run naming an unconfirmed label gets that label's split
and does not confirm it → switching y → guess → y reuses both splits and the earlier run's recorded split is unchanged.

## Open problems

- A numeric target gets a plain random holdout (as before); stratifying a regression target on quantile bins would be a
  new strategy key, not a change to this one.
- Splits are stored per target and strategy but not per seed or holdout share (both fixed: 42, 20 %). Making them
  configurable would add them to the key.
- The guessed target's split is still drawn on upload (cheap, and it keeps `splits.json` for older code); it is unused
  unless that target is confirmed or named by a run.
- Runs made before F4 keep pointing at `splits.json` and have no `split` record; their holdout is unchanged.
- The Gym and Autopilot brief do not show the confirm step: they name the label in their own forms, and the run uses
  that label's split anyway (the API guarantees it, confirmed or not).
