## 1. EditVersion: acknowledge by code (`EditVersion.tsx`, `catalog.ts`)

- `data.edit(…, acknowledge)` sends `acknowledge: [codes]` when any; `DsEditPreview.needs_acknowledge` typed.
- The preview splits `checks.warnings`: integrity warnings (`needs_ack` and code in `INTEGRITY_ACKS`) go to
  `<IntegrityAcks>` (counts, why, relation ends; the same sentences as on an upload); the rest stay "n contract
  warnings". With only integrity warnings the preview says "v_n will be created but not made the default: it changes
  what v_m promised (below)". A code in `needs_acknowledge` with no matching warning (e.g. `target_one_class`) gets its
  own box with the warning's message, so Create can never be stuck.
- Any new pending operation or a new preview clears the boxes. Create's tooltip names what is still unacknowledged.
- **Found on the way (pre-existing since P07):** a Parquet edit preview answers `sha256: null`, and the hero strip did
  `pv.sha256.slice(…)`, so **every Parquet preview crashed the editor** (pageerror, blank card). It now reads "on write"
  with a tooltip; the type is `string | null`.

## 2. Per-table change counts (`catalog/dsets.py`, `DataView.tsx`, `data.css`)

**Backend (backward compatible).** `history` adds `table_changes` to a version only when it has more than one table:
`[{table, change, primary, rows_before, rows_after, added, changed, removed}]`. `change` and rows come from
`version_tables` (the parent's rows for `rows_before`); the counts from the version's manifest `provenance.ops`
(`delta` → inserted / updated / deleted; `upload_version` match; `upload_append`; `edit`; a frame write's kept / new
/ removed), summed per table. A carried table is 0/0/0; a table with no op that counts rows (e.g. a key
declaration) has null counts and shows "—". Manifests are read once and cached by their sha256 (immutable). `changes`
stays the primary table's, so older readers see what they did.

```
GET /datasets/ds_1d134c53/history  (U2's dataset; v2 = bureau_delta.csv applied to bureau, not the primary)
v2 changes {}  table_changes
   applications carried   3,000 → 3,000  +0 ~0 −0
   payments     carried  14,587 → 14,587 +0 ~0 −0
   bureau       rewritten 2,806 → 2,811  +10 ~20 −5      (the delta: 10 I, 20 U, 5 D)
v3 (the edit above) bureau rewritten 2,811 → 2,812 +1 ~0 −0
```

**UI.** A multi-table version's "changes from its parent" cell is a `<details>`: summary = one `ChangeBar` of the sum
over tables + "1 table changed: bureau · 3 tables" (title = one line per table); expanded = per table its name (★
primary), a change `Badge`, its own `ChangeBar` and rows before → after. Clicking it doesn't select the row.
Shots: `U5/01-versions-v2-total.png`, **`02-versions-v2-per-table.png`**, `06-versions-v3.png`. (Before U5 the v2 row
read "0 changes", as U4 noted.)
