| Staged upload | `src/features/models/data/StagedUpload.tsx` (new) | **Steps.** Pick a file (and, for a new dataset, a project of the current team) → **Check file** = `POST /uploads` (+ `?parent_version_id=` for a next version) then `POST /uploads/{u}/check` → **Create** = `POST /uploads/{u}/commit {by, check_sha256, reason?, match?, acknowledge?}`. There is one primary action per step, and **Discard** sends `DELETE /uploads/{u}`.<br>**Check view.** There is one tab per `tables[]` entry (one table today; ready for P12's multi-table check). Each tab shows rows, columns, encoding and separator; every column with its stored type and the *why* (`leading zeros: kept as text`, `ambiguous day/month order…`); warnings and blocks next to their column; and the first rows in a fold-out. Create is disabled while there are blocks.<br>**Match view (next version, §5.3).** It shows every simulated method (best candidate, confirmed key, row hash, and a simulated choice) with its counts: **matched / changed / added / removed / holdout identity lost (n / holdout, %)** and its warnings. The preselect from the check is chosen (the declared key, else the top candidate). The key candidates are listed with score, overlap, uniqueness, id-like and "not a key"; **simulate** on another valid candidate does `PATCH /uploads/{u} {match}` and checks again. The contract shows columns added/removed, type changes and the rows before → after.<br>**Acknowledge.** When the chosen method has `needs_acknowledge` (identity loss ≥ 1 % of the parent holdout, or a better key is available), its messages are shown with a checkbox. Create stays disabled until it is ticked, and then `acknowledge: ["holdout_identity_loss"]` is sent. |

## Deviations and notes

- **Files outside the U1 row** (all frontend):
  - `src/app/shell/{Sidebar.tsx, TeamSwitcher.tsx, shell.css}`: the switcher belongs in the sidebar header;
  - `src/app/routes.ts`: the Data redirect;
  - `src/features/models/{RunList.tsx, components/ProjectTree.tsx}`: the Data tab removed, `NewProject` shared, links moved;
  - `src/shared/{lib/team.ts, api/client.ts}`.
- **No backend change.** One existing backend bug was seen and left alone for its owner (lane D, P07's file):
  - **Where:** `data_doctor.py` `label_key()` runs `csv.stat()` on `datasets/<id>/data.csv`, which a Parquet version does not have.
  - **Effect:** the label-quality background thread raises `FileNotFoundError` once per `GET …/data-doctor` on a new upload. The endpoint still answers 200, so the UI is unaffected; the API log shows 4 tracebacks per walk.
- **v2 and v3 did not become the default.** The file's `date_ambiguous` typing warning counts as a warning. Under P06's rule ("a next version with any warning is not made the default unless `make_default: true`"), every next version of a file with an ambiguous date stays non-default.
  - The UI says so in the result line and leaves "Make vN the default" to the dataset page.
  - A "Create and make default" option was left out to keep one primary action. U2 can add it if wanted.
- **Not in U1:**
  - declaring a column's type or format from the check (the API's `PATCH types/formats` exists; the warning text names it): U2 or a follow-up;
  - multi-file staging: the backend answers `single_table` until P12. The tabs already render `tables[]`.
- **The old version upload route is gone from the UI.** `POST /datasets/{id}/versions` (P06's wrapper) is still served for the API and the notebook client. Its UI client (`uploadVersion` / `previewVersion`) and the DL2 preview component were deleted.
- **Old screenshot scripts.** `scripts/dl*_shots.cjs` still open `#/models?tab=Data`; the redirect keeps them working. Their selectors for the removed DL2 preview (`data-preview`, `data-create-version`) no longer exist. Those scripts are history, not suites.
- **Clean-up.** The scratch data dir, the API and Vite processes and the generated CSVs were removed after the run.
