# F7 · Business-cost metric

Status: **done. `SMOKE_ONLY=cost,core make smoke`: 28/28 green in 150 s. `npm run build` passes.** Acceptance met on
credit-default with FN = 10 × FP: the cost-optimised run costs **478.3 per 1,000 decisions [419.1, 545.0]** on the
holdout, the ROC-AUC-optimised twin **553.8 [475.8, 638.0]**. Paired on the same 2,400 holdout rows,
**Δ = +75.4 per 1,000 [+12.1, +139.6]** (Δ > 0 in 98.9% of 1,000 bootstrap resamples). Honest caveat: most of the
saving comes from the threshold. If the ROC-AUC twin's threshold is also calibrated for this cost on its own
validation data, it costs 496.7, and Δ = +18.3 [−24.6, +62.5], which is within the noise.

## Cause

Before F7, the only cost in the product was the Explain Threshold tab's C(t) = c_FP·FP + c_FN·FN, computed after the
fact on a model trained and thresholded for something else (ROC AUC, and t calibrated for F₁). Models, ensemble
weights and the threshold never saw the bank's costs.

The Bayes threshold is t* = 1/11 = 0.0909: at t* the cost run costs 489.6. The hindsight minimum on the holdout is
475.8 at t = 0.085, which is a bound, not a rule. Both twins are WeightedEnsemble_L2. On this small zoo (GBM 40 rounds,
RF 40 trees, LR) the cost run's ensemble is LinearModel alone, so model selection can only change so much.

## What changed

**Scorer (`backend/ensemble_models/cost.py`).** The score functions live at module level with plain keyword
arguments. A scorer therefore pickles by reference into worker processes, bagged children and the saved predictor.
Loading needs only `ensemble_models` importable, exactly like the TF-IDF models. Checked in the smoke: the API process
reloads the predictor and predicts. The module defines:
- `binary_cost_scorer(c_fp, c_fn, g_tp)`: the run's `eval_metric`. It is `needs_proba`, and every model decides by the
  Bayes rule p > t* = c_FP/(c_FP + c_FN + g_TP). A label-based scorer would score each model at AutoGluon's t = 0.5,
  where with 7.4 % positives every model costs about the same as flagging nobody.
- `binary_cost_class_scorer(...)`: `needs_class`. It is passed to
  `predictor.calibrate_decision_threshold(metric=...)` after the fit.
- `multiclass_cost_scorer(matrix)`: the cost of the arg-max (what `predict()` serves). It is written as
  `needs_proba`, because AutoGluon 1.6.3 passes a `needs_class` multiclass scorer its internal integers inside the
  trainer but the original labels in `evaluate` / `leaderboard`. The smoke found this, and the run had crashed on it.

**API and worker.**
- `POST /api/runs` takes `cost`: `{c_fp, c_fn, g_tp}` or `{classes, matrix}`.
  - It is checked and normalised: matrices are reordered to AutoGluon's class order (the sorted labels).
  - It refuses negative amounts, all zeros, a missing class, a cost with another `eval_metric`, and a regression
    label.
  - The run's `eval_metric` is `expected_cost`, and binary runs get `calibrate_threshold = expected_cost`.
- The worker builds the scorer and records `resolved.cost_metric`.
- `holdout.metrics.expected_cost` is the cost of the decisions actually served (the deployed threshold), with
  `expected_cost_bayes` beside it.
- New endpoints:
  - `GET /runs/{id}/cost`;
  - `POST /runs/{id}/metric-twin` (the same body with only the metric changed);
  - `GET /runs/{id}/cost-comparison` (twins with the same split key and fit settings, costed with this run's cost,
    paired-bootstrap Δ). For runs not trained on the cost it also computes a cost-calibrated threshold with
    AutoGluon on the run's validation data, cached per cost.
- `export.py` rebuilds the scorer (`COST`), and the Gym keeps `cost` on re-run.
- Unrelated, but it would have shown up on every cost run: Vela's "validation is optimistic" finding bootstrapped the
  holdout through `get_metric(name)`. That fails for a custom metric, so the noise became 0 and the finding claimed
  a gap of "6,666,666 × the noise". Cost runs now bootstrap the per-row costs, and the finding is skipped when no
  noise estimate exists.

**UI.**
- New Model → Goal: a **Business cost** metric. When chosen, a Business Cost card shows:
  - inputs for c_FP, c_FN and g_TP, with presets FN = 10 × FP, 5 ×, 1 ×;
  - the 2 × 2 cost matrix with the class names;
  - t* evaluated with the entered values, with a where-list, and the no-model baselines from the label's prevalence;
  - for multiclass, an editable K × K matrix.
- The threshold card explains the cost calibration, and the resolved-call preview shows the scorer.
- Results → **Business Cost · Per 1,000 Decisions**:
  - the cost with its 95 % bootstrap interval, the no-model baselines, and E[C] bound to the run's FP, FN, TP and n;
  - the cost curve over t for every run, with each run's t, t* and flag-nobody marked, and a hover read-out;
  - a table of cost at each run's t and at its cost-calibrated t, with paired Δ and CIs;
  - the Δ formula with every symbol defined;
  - buttons that train missing ROC AUC / accuracy twins.
- Explain → Threshold starts from the run's own costs.

## Open problems

- **The threshold does most of the work** here (Δ +18.3, not significant, once the ROC-AUC twin's t is also chosen
  on cost). Model selection on cost helps more with a richer zoo or when models' calibration differs. This one
  sample does not show it.
- **Ranking at t\* assumes calibrated probabilities.** AutoGluon's temperature scaling (`calibrate="auto"` for
  `needs_proba` metrics) is skipped under 3,000 validation rows; here there were 960.
- **Multiclass is served as the arg-max.** AutoGluon has no cost-aware multiclass decision rule, so the Bayes decision
  is only reported. On the smoke's 3-class data it is worse (1,380 vs 1,107 per 1,000, always "high"), because the
  probabilities are not calibrated enough for a 20 × cost.
- **Classes dropped by AutoGluon** (too rare to learn) would break the multiclass matrix's order. This was not
  exercised.
- **The pytest fast tier has 5 failures that predate F7**: assertions on run keys (`kind`, `imported`), F3's
  registry `measure` step, and sample / profile lists. F7 changed none of these, and they were not fixed (rule 2).
- Gym and Autopilot have no cost editor. A `cost` in the body works and is kept on re-run.
