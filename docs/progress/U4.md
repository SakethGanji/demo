# U4: polish of the data-platform screens (lane U)

Scope: every screen U1, U2 and U3 added or changed. The aim was the same finish as the best existing pages (Data
Doctor's report, Model Doctor, the registry card), with **no change of behaviour**: every request, payload and
permission greying is as it was. **No backend change.**

## The shared parts (new)

Before U4 each screen had its own header markup, its own `when()` / `kb()` / `n()` formatter, its own status chip
colours (`pt-chip cert-…`, `purge-st-…`, `up-ct-…`, `tbl-…`) and its own warning box (`data-warn`, `up-block`,
`lc-confirm`, `lc-result`, `purge-executed`). They now share one kit.

| Part | Where | What it is |
|---|---|---|
| `CardHead` | `shared/components/DataKit.tsx` | Title, an optional badge, a one-line description, actions on the right. Used on every data card. |
| `CopyId` | same | A long id or sha as a short mono chip; the whole value is its title and a click copies it. Version ids, shas, frame ids, join ids, team ids, purge ids, GC blobs. |
| `IdDetails` | same | Internal ids folded behind a "▸ ids" disclosure (join spec, frame). |
| `Badge` | same | Every status word of the platform (active, pending, rejected, revoked, carried, rewritten, held, kept, armed, executed, block/warn/pass, …) mapped to one `StatusPill` tone: never colour alone. |
| `ChangeBar` | same | +added ~changed −removed as one 72 px stacked bar with the counts beside it; the title gives the share of the table touched. Versions, diff, delta plan, append plan, SQL refresh versions. |
| `CoverageBar` | same | m / N as a thin bar (teal from 95 %, amber from 80 %, red below), with m, N and c in the title. Relations (tables card, upload plan), join coverage, the card's join coverage. |
| `Callout` / `Flash` | same | Boxed warnings, refusals and results with a tone and an icon; the ✓ / ✕ result line of an action. |
| `ConfirmButton` | same | A destructive button that asks once more in place (Confirm / Cancel). The confirm button's test id is the button's own + `-confirm`. |
| `Field`, `Steps`, `Why`, `Stats` | same | A label over its control; the plan → dry run → run step indicator; "⊘ why this is greyed" under a greyed control (the same words as its tooltip); a strip of headline numbers. |
| Formatters | `shared/lib/format.ts` | `int`, `when`, `day`, `bytes`, `plural` (were copied into a dozen files). |
| CSS | `shared/components/datakit.css` (new, imported by `styles/index.css`) | The kit, plus a zero-specificity baseline for `.input` / `.select` that no page styled (the data screens showed native controls), focus rings, `accent-color` on checkboxes and radios. |
| Tokens | `styles/tokens.css` (3 aliases) | `--text-secondary`, `--font-body`, `--border-subtle` were used by feature CSS but never defined, so those colours fell back to inherit. They now alias `--text-muted`, `--font-sans`, `--border-row`. |

## Deviations and notes

- **No backend change.** No API, payload or permission changed; every `data-testid` the walks use is unchanged.
- **Behaviour additions, all confirmations:** Ask to delete…, Revoke (share) and Remove (member) now confirm in place.
  Retention and GC already had their confirm boxes; Release (hold) and Purge already asked for a reason.
- **Settings › Teams still has its own `useCan`** (it reports a failed check as a refusal, the shared one as
  "unknown"). Merging them would change what a greyed button says on an API error, so it was left.
- **Versions "0 changes" on a multi-table delta version.** The row reads the primary table's counts; the delta's
  per-table counts are in the diff (table picker). Showing them on the row needs the per-table numbers in
  `/history`: a backend change, not made.
- **Not restyled:** the F-PII pages around the `MaskBar` (anomaly, shift, AL, annotations, Feature Lab, split options,
  intake) keep their page layout; only the bar itself changed.
- **Clean-up:** the scratch data dirs, the worktree, the APIs and the Vite servers were in the scratchpad.
