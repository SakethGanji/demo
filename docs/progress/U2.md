It preselects the parent table whose columns hold the file's (bureau here) and PATCHes `{table, tables: {t: {action: 'delta'}}}`. ## Deviations and notes

- **Backend change (minimal):** one route appended to `catalog/joins_api.py`, `GET /datasets/{root}/frames/{id}/rows`. "Preview the frame" had no row read in P14. It has `require("data.preview")` and is masked (see above). Authz coverage is unchanged in kind (one new covered route).
- **`unmasked_refused` in the walk.** The UI greys Unmask for anyone `/authz/check` refuses, so a refused read only reaches the API when the check is stale or wrong. To exercise that rendering path, step 11b stubs `/authz/check` in Playwright for that one step. The API's refusal itself is real.
- **Usage `via_join`.** The chip renders when the API sets it. That happens when the version is reached only through a frame, e.g. another dataset's `merged_from` input. In this walk the join run also has a direct `trained_on` edge to its grain version, so the API dedupes it, and the walk shows the "join frames built on it" line instead.
- **Catalog "shared with you".** `/data/search` rows are per root, and their `access` is the root's. A share with scope `default` covers v2, not the root row, so the chip also reads the team's live incoming shares.
- **Delta options.** `op_column`, `ops` and `allow_new_columns` are not editable in the plan view. A file uses `_op` with I/U/D/insert/update/delete/upsert, and anything else gets the `delta_op_unknown` sentence. Small follow-up.
- **Not built:**
  - **F-PII → U2:** "Unmask (reason)" / `unmasked_refused` on the anomaly top rows, shift, active-learning, annotations, Feature Lab, split options and intake screens. The data grid and the frame preview have it; those screens still render their masked values without the action.
  - **P24 → U2:** the retention plan / dry run / run, GC and purge screens. Legal holds are built.
  - **P21 follow-ups:** the discoverable "request access" rows.
- **Forks used:** the Registry and Settings › Teams slices were written by two parallel sub-agents in this session and reviewed here. Fixes made after review:
  - the predictions parity line read `status`, not `ok`;
  - retention no longer shows §6.4 periods as defaults.
- **Local branch:** the container's local `motion-components` had unrelated history. Work is on `origin/motion-components` (merged, never rebased). The old local pointer was dropped (nothing of it is pushed).
- **Clean-up:** the scratch data dir, the API and Vite processes and the generated files were in the scratchpad and are removed. The two scratch runs lived only there.
