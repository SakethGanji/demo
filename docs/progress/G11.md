# G11 · Integration and cohesion

**What it does.** The workbench now has five places in the sidebar: **Home, Build, Models, Registry and Vela**. Settings is a gear in the sidebar footer. Every feature is still reachable. Pages that were merged into others are deleted, and their old routes are one-line redirects.

**Status:** both G11a batches are done, plus the carried items.

- **Smoke:**
  - Batch 1, the sections asked for: 102/103.
  - Full `make smoke`: **224/224 in 4,159 s**, every section, on the final backend code.
- **Build:** `npm run build` and `tsc --noEmit` pass.
- **UI lines** (`src/**/*.{ts,tsx,css}`): **22,228 → 21,762** (−466).
  - About 24 component functions were removed and 14 added, a net of −10.
  - The new ones are KindFlow, KindSetup, KindRun, NumField, KindResults, TryItFor, RunPage, LiveRun, TabularRun, DoctorTab, MockRun, ExplainTab, MockConfusion and NotForNotice.
- **Backend lines** (`backend/app/**/*.py`, non-test): **33,041 → 33,110** (+69).
  - Two dead routes were deleted.
  - The Doctor's next steps, the SQL audit, the notice flag and the leak flag were added.

## Navigation and routes

| Route | Now |
| --- | --- |
| `#/home` · `#/build` · `#/models` · `#/registry` · `#/vela` | The five places. |
| `#/settings` | The gear in the sidebar footer. The Go To group of the command palette lists the five places and Settings. |
| `#/models?run=ID&tab=Results\|Explain\|Doctor&sub=…` | One run's page (see below). |
| `#/quick-train`, `#/forecast`, `#/anomaly`, `#/import`, `#/expected-loss`, `#/segmented`, `#/survival`, `#/reject-inference`, `#/multilabel`, `#/gym` | Build choices, plus the Gym as Build's **Advanced**. Each is a setup page; the run opens in Models. |
| `#/experiments` | → `#/models` (query kept). |
| `#/explain?run=X&tab=T` | → `#/models?run=X&tab=Explain\|Doctor&sub=T`. The old tab name is mapped to the tab that holds it now: Shift, Weak Slices, Learning Curve, the Labelling Queue and Annotators go to Doctor; the rest go to Explain. |
| `#/autopilot` | → `#/vela?mode=auto`. |
| `?run=` on any per-flow route | → `#/models?run=`. `#/quick-train?run=` watches a run that is still training. Once the run succeeds it redirects to `#/models?run=`. |

`useTabParam` (in `shared/hooks/useHashParam.ts`) is the one way a page reads `?tab=`.

- It matches case- and punctuation-insensitively, and by unique prefix.
- It also accepts aliases: the agent's `tab=doctor` and `tab=batch`, the Registry's old Expected Loss, Segments, Survival, Labels and Audit tabs, and Fair Lending → Fairness.
- The Registry and the run page use it. The agent's deep links land on the right tab.
- The agent's tool links point at the new routes directly.

## Batch 1

1. **Five-item navigation.** The toolbelt is gone, everywhere:
   - the sidebar, the CSS, the Settings card and Home's Toolkit grid;
   - `ToolCard`, `ToolGlyph`, `shared/lib/tools.ts`, prefs `pinned`, the palette's Tools group and Customize Workbench.

   Titles are "Models", "Registry" and "Advanced · Training Gym". The agent says "Open the run in Models → Doctor".
2. **Dead code removed:**
   - `PrototypeBanner` (it always returned null) and its CSS and e2e asserts;
   - unused Icon keys (autopilot, gym, forecast, anomaly, importer, explain);
   - the client methods `featureImportance`, `gym.exportText`, `registry.monotone`, `registry.mlflow` and `anomaly.labels`;
   - dead CSS: `.vela-tag`, `.stage-cap`, `.lib-grid[style]`, `.cls-row` and `.lib-card .bot`;
   - the backend routes `POST /api/anomaly/runs/{id}/score-one` (`core.score_one` kept) and `GET /api/autopilot/menu`.
3. **No second "past runs" table on the setup pages.** Forecast, Anomaly and Import each show one line, "Earlier … are in Models →", which opens Models with that `?type=` filter.
4. **Registry: one Results tab.** It replaces the Expected Loss, Segments, Survival and Labels tabs.
   - `shared/components/KindResults.tsx` holds the map `RESULTS: kind → {get, ready, View}`, which the run page reuses.
   - **Try It** goes through `TryItFor`:
     - tabular and segmented: one row;
     - survival: a survival curve;
     - multi-label: a label set;
     - expected loss, forecast and anomaly: a help card, each with its own wording and endpoint. Forecast uses `/api/forecast/runs/{run}/predict`.
   - Tab visibility is one `APPLIES` map.
   - The Audit tab is gone; the audit card below filters to the selected version.
   - `BatchDrift` describes each kind's CSV and output.
   - Reject-inference runs show "not registrable" with the API's reason, in Models and on the run page.
5. **One wording for actions:**
   - **Register…** everywhere;
   - **Open** for a run;
   - **Advanced** for the Gym ("Apply in Advanced" on Shift's patches);
   - **Run it end to end** for Autopilot;
   - the mock Registry in sentence case, like the live one.
6. **Screen discipline:**
   - the Registry's header Register… becomes secondary once a version is selected;
   - Models shows `<Loading>Connecting…</Loading>` while the API is being checked;
   - Fair Lending's inputs stay closed unless they need fixing.

## Batch 2

7. **`KindFlow`** (`shared/components/KindFlow.tsx`, 168 lines) is the one setup and run shell for expected loss, segmented, survival, reject inference and multi-label.
   - Each page is now a `KindSpec` (roles with options and evidence, extra rows, the formula, notes, Advanced, the body, running steps, the register name) plus its results, maths and charts.
   - The five pages went from **1,436 to 900 lines**, plus the shell.
   - `CiBar` and the step and CI styles moved to `kindflow.css`; `expected-loss.css` and `segmented.css` are gone.
   - All the data-testids are kept, derived from `spec.testId`: `el-start`, `seg-label`, `surv-duration`, `ri-decision`, `ml-label`, `*-detected`, `*-setup`, `*-run` with `data-status`, and the per-role and Advanced inputs.
   - Forecast and anomaly stay bespoke.
8. **The run page** (`features/models/RunPage.tsx`; `features/experiments` and `features/explain` moved under `features/models`).
   - **Tabular and imported runs** get three tabs:
     - **Results:** `ResultsStep` with one primary **Register…** and a secondary **Advanced**. The custom ensemble sits in a closed "Advanced · custom ensemble" fold-out.
     - **Explain:** Performance, Errors, Features & SHAP, and Fairness (fair lending folded in). The **Advanced** group holds Threshold, Monotonicity, Scorecard and Text.
     - **Doctor:** Model Doctor, Weak Slices, Shift, Learning Curve, and Labels (the labelling queue and annotators).

     The compact Doctor, the residuals and the duplicate confusion matrix left Results: they live in Explain. The confusion matrix and top words stay for mock mode.
   - **Imported runs** keep their facts strip above the tabs. They have no Doctor tab (the API refuses imported runs).
   - **G-kinds** render `KindRun`. **Forecast and anomaly** render their existing run views.
   - `ExplainPage` is deleted; `ExplainTab` is the Explain tab without the head, run picker and buttons.
   - The Registry's Fair Lending tab is now a link to the run's Fairness view.
   - The Doctor's links use `runView()` (`features/models/tabs.ts`), and `applyVela` still opens the Gym with the patch.
9. **Mock mode** has a run page, `models?run=…`, built on a simulated run:
   - Results: the scripted results;
   - Explain: the scripted confusion matrix;
   - Doctor: the standard ApiOnly card.

   The run IDs in the mock list link to it. Import uses `ApiOnly`.
10. **`Loading` and `ErrorCard`** take `inline`, used by KindFlow, the run page and ResultsStep.

## Carried items

- **e2e and scripts.** `e2e/fixtures.ts`, `pages.spec.ts` (the route → title map), `mock.spec.ts`, `understand.live.spec.ts`, `gym.live.spec.ts` and `registry.live.spec.ts` are updated. So are `f19_shots.cjs`, `demo_walk.cjs` and `walkthrough.cjs`, all on `#/models` paths. The e2e suites were not run (speed mode).
- **`docs/demo-script.md`.** A "Where things are" section for the five places, every path updated, an **optional credit-risk add-on** (recourse, the credit report, EL stress, fair lending) and an **optional Vela agent segment**.
- **README.** The Screens table rewritten for the five places and the redirects, a G11 navigation note, and the project tree.
- **In-app `#/quick-train` redirect.**
  - Without `?dataset=`, it now goes to Build with `location.replace`, so Back no longer bounces.
  - A finished run's `?run=` replaces itself with `#/models?run=`.
- **G6 leak flag.**
  - An explicit time-to-event column (`duration_months`) next to a yes/no target gets a second role, `leak` (0.85): "the time up to 'churned': known only after the outcome".
  - It stays a `duration` (primary 0.9), so survival still uses it as T. The yes/no suggestion's drop list now leaves it out: `['account_id', 'duration_months']`.
  - It only fires on `account-attrition` among the bundled samples.
- **The Model Doctor recommends.** A new "Also Worth Checking" card (`doctor.next_steps`, `d.next`) lists, from Smart Intake's roles and suggestions for the run's own table:
  - segmented models;
  - reject inference;
  - fair lending, for binary runs with a surname (linking to Explain → Fairness);
  - recourse, for binary runs (linking to Try It on its registered version, else to Register).

  These are never findings and never the primary. Checked on the samples: credit-rejects → reject inference; segmented-loans → segmented; fair-lending → fair lending.
- **Reject inference** is not registrable. Models shows "not registrable" with a tooltip, and the run page shows one line with the API's reason. Its runs are not offered in Register.
- **SQL loads and refreshes are audited:** `dataset_loaded` and `dataset_refreshed`, with who, the redacted URL, the query, rows, version, data SHA and, for a refresh, the parent and the diff. The UI sends the acting name, and Home and the audit table show them.
- **G10 batch-score PSI.** The agent's `batch_score` now reads `drift.prediction.psi`, the key the batch report uses, as `prediction_psi`. Before, it read a key that does not exist and always got null.
- **R06 / region.** The reason-code mapping marks geography and protected characteristics (and their proxies) as `notice: false`: region, zip, state, county, surname, gender, race and so on. Each code carries it.
  - The UI tags them **not for adverse-action notices**, in the mapping table and in each decision.
  - The agent's `explain_decision` returns `for_notice: false` with the reason.
