# S2 · AutoGluon engine

Status: **done, `make test-full` green** (58 fast pytest, 11 slow pytest, 21 Playwright).

## What works

**Install**
- `backend/requirements.txt` adds `autogluon.tabular[all]==1.6.3`, `autogluon.timeseries==1.6.3`, `cleanlab==2.9.0`, `shap==0.54.1`, `fairlearn==0.15.0`. AutoGluon 1.6 needs pandas < 2.4, so pandas is now `2.3.3` (all S1 tests pass on it). The separate `xgboost` pin is gone: AutoGluon brings `xgboost-cpu`, and both together clash.
- Torch comes from the PyTorch CPU index (`--extra-index-url …/whl/cpu`): 2.6 GB venv, no CUDA. Drop that line and `make lock` for a GPU machine.
- `backend/requirements.lock` is the fully resolved set (`make lock` regenerates it with uv). `make setup` installs the lock with `uv` (≈30 s) or falls back to pip. pip resolving `requirements.txt` directly backtracks for a long time; don't.
- `vite.config.ts` now ignores `backend/**` and the data folders: the AutoGluon venv has enough files to exhaust the OS file-watcher limit (that crashed the e2e Vite server).

**Samples** (seed 42, generated on first start, sidecar `signal.json` with the true coefficients)
- `credit-default`: 12,000 applicants, 14 columns (numeric and categorical, missing `income_usd`, `months_employed`, `region`), label `defaulted`, **8.0% Yes**. Known logistic signal; `age`, `region`, `income_usd`, `loan_amount_usd` are noise.
- `loan-amount`: 8,000 applications, label `loan_amount_usd` (**regression**), linear signal plus heteroscedastic noise; **40 rows have no label** (listed in the sidecar).
- Profiles gained `task` (`binary | multiclass | regression | null`) and `target_stats` (regression only). A numeric label with more than 50 values is regression: no classes, unstratified split.

**Runs** (`backend/app/engine/`, API table in the README)
- `POST /api/runs` → a queued run. The training frame is `data.csv` minus the S1 holdout rows, minus rows with a missing label, minus `drop_columns` (default: the profile's ID columns). `fit_kwargs` and `predictor_kwargs` pass through untouched; `presets` and `time_limit` are just the first keys of the fit call (`fit_kwargs` wins on a clash). Nothing is capped.
- Two documented additions, both recorded in `run.resolved.notes`: (1) text data with `custom_text_models` on (default): `TFIDF_LR` and `TFIDF_SVM` are added to the hyperparameters the presets would have used (or to yours), and `_feature_generator_kwargs.enable_raw_text_features=True` keeps the raw text for them; (2) the presets' callbacks are passed explicitly so ours can be appended. `run.resolved` = the exact `TabularPredictor(**predictor_kwargs).fit(train, **fit_kwargs)` call.
- **One OS process per fit** (`python -m app.engine.worker <run_dir>`, own process group). `ENSEMBLE_MAX_PARALLEL_RUNS` (default 1) fits at once; the rest queue. The worker exits on its own if the API dies.
- **Restart recovery**: on start, runs left `queued`/`running` are marked `failed` ("The API stopped while this run was in progress."), a stray worker from the old process is killed, and a `run_failed` event closes their streams. A normal stop does the same at shutdown. Note: `make dev` runs uvicorn with `--reload`, so editing `backend/app` stops running fits.
- Cancel (`POST /runs/{id}/cancel`) works queued or running; delete removes a finished run and its folder.
- Each run folder: `config.json`, `worker.log`, `predictor/` (a plain AutoGluon predictor; `TabularPredictor.load` works without ENSEMBLE for tabular runs, text runs need `import ensemble_models`), `holdout_predictions.csv` (row, y_true, y_pred, p_<class>…).

**Results on `GET /api/runs/{id}`**
- `leaderboard`: AutoGluon's `leaderboard(holdout, extra_info=True)` row for row (score_val, score_test, fit/pred times, stack_level, hyperparameters, features, ancestors…) plus `rank`, `family` (catalogue key), `score_*_natural`, and for bagged models `fold_scores`, `fold_scores_natural`, `val_score_std` (sample std over the fold children); weighted ensembles carry `weights`.
- `ensemble` (the best model's weights, sorted) and `ensembles` (every weighted ensemble); weights sum to 1.
- `holdout`: `evaluate()` on the S1 holdout (`scores` higher-is-better, `metrics` natural units), `classes`, `confusion_matrix`.
- `oof`: `{available, models, note}`; `GET /runs/{id}/oof?model=` returns rows (data.csv positions), classes and probabilities (only bagged runs).
- `feature_importance`: permutation importance on the holdout (≤2,000 rows, 3 shuffles, ≤60 s), computed after the fit unless `feature_importance: false`; `GET /runs/{id}/feature-importance` computes it on demand.
- `text_models`: per TF-IDF model, per class, the 15 words with the largest coefficient (averaged over fold children).
- `eval_metric`: `{name, greater_is_better, optimum}`. **Scores**: `score_*`/`val_score` are AutoGluon's higher-is-better values (RMSE is negative); `*_natural` are in the metric's units. Show the natural ones.

**Events** (`GET /runs/{id}/events`, SSE; `id` = seq from 0, `event` = type, `data` = JSON with seq/ts/type)
`run_queued → run_started{pid} → data_ready{train_rows, holdout_rows, dropped_*} → config_resolved → fit_started{problem_type, eval_metric, greater_is_better, num_classes, k_fold} → (model_started{model, family, model_type, stack_level, bagged, order, time_limit} → model_finished{val_score(_natural), fit_time, predict_time, fold_scores, val_score_std, n_children, elapsed} | model_failed{error, skipped})* → ensemble{model, weights} → fit_finished{best_model, ensemble} → leaderboard → evaluation → [text_models] → [explaining → feature_importance] → run_succeeded | run_failed{error} | run_cancelled`, with `log{level, message}` lines from AutoGluon in between (≤3,000). Replay from any index with `?from=N` or `Last-Event-ID`; the stream closes after the terminal event; `?format=json` for a one-shot read. `ensemble` is also emitted live, as soon as each WeightedEnsemble fits.

**Custom models** (`backend/ensemble_models/text.py`, registered in AutoGluon's model registry on import)
- `TFIDF_LR` (`TfidfLogReg`): TF-IDF (1–2-grams, sublinear tf, min_df 2) → L2 logistic regression, one-vs-rest for multiclass (C = 5).
- `TFIDF_SVM` (`TfidfLinearSVM`): TF-IDF → LinearSVC (C = 0.5), Platt-calibrated with 3-fold CV (softmax of margins if a class is too small to calibrate).
- Both `AbstractModel` subclasses, classification only, raw-text columns only (skipped with "no valid features" otherwise), `top_words(k, classes)`. Hyperparameters work as for any AutoGluon model: `{"TFIDF_LR": {"C": 2.0, "ngram_max": 3}}`.
- On the tickets sample: TF-IDF models ≈0.915 accuracy on the holdout, LightGBM ≈0.944, the weighted ensemble ≈0.948.

**Catalogue** `GET /api/models`: GBM, CAT, XGB, RF, XT, KNN, LR, NN_TORCH, FASTAI, REALMLP, TABM, TFIDF_LR, TFIDF_SVM, ENS_WEIGHTED. Each has `objective` (Unicode, e.g. `ŷ(x) = Σₘ wₘ·fₘ(x), w = argmin …` for the ensemble), `objective_tex`, and `symbols` defining every symbol (n, xᵢ, yᵢ, ℓ are included in every entry).

**UI (minimal, S3 owns the real thing)**
- `src/shared/api`: types for runs, events, predictions and the catalogue; `api.models()`, `api.runs.{create, list, get, cancel, events, predict, featureImportance}`; `followRun(id, onEvent, {from, onEnd, onError})` wraps EventSource and stops at the terminal event.
- Quick Train, live mode, Train step: **AutoGluon · Real Run** card (`components/LiveRun.tsx`). A button starts a 60 s `medium_quality` fit of the chosen server dataset; each model appears as it starts (a wave) and settles into a string whose length is its validation score relative to the best, with fit and predict time; then the stack `ŷ(x) = 0.476·f₁(x) + …` with a where-list naming every fₘ and wₘ, and the holdout metrics. The simulated run below it is unchanged; mock mode is unchanged.
- `.formula`/`.where` moved from the Gym's CSS to `shared/components/components.css` (two pages use them now).

## What doesn't / not done

- No custom-ensemble endpoint yet (`fit_weighted_ensemble` on chosen models) — that's in S3's row. Add `POST /api/runs/{id}/ensemble` by loading the predictor in a worker process (it writes to the predictor folder) and appending events to the same run.
- DyStack (`best_quality`'s dynamic stacking) sub-fit events are not streamed (it runs in a Ray subprocess); the main fit's are. `best_quality` overshoots `time_limit` by DyStack's share (240 s → ≈300 s on credit-default).
- With `best_quality`/zero-shot hyperparameters, many configs get `model_started` then `model_failed{skipped: true}` when time runs out (195 of 218 in a 240 s run). The race UI should collapse skipped ones.
- Quick Train's Continue is still disabled for regression (it wants K ≥ 2), so `loan-amount` can't reach the live card from the UI; the API trains it fine.
- TF-IDF top words keep stop words (“that”, “would”); they carry signal here, so they stay. Pass `{"TFIDF_LR": {...}}` hyperparameters to change n-grams or C.
- Torch is CPU-only (see Install).

## Notes for S3 (New Model wizard + live race)

- Start a run with `api.runs.create({dataset_id, label, problem_type, eval_metric, presets, time_limit, fit_kwargs})`, then `followRun(run.id, onEvent)`. Everything the race needs is in `model_started` / `model_finished` / `model_failed` / `ensemble`; group rows by `family` (catalogue key) for "one string per family", use `stack_level` for the stack forming, `ensemble.weights` for the live equation. Ignore events with `phase: "dystack"` if any appear.
- After `run_succeeded`, `api.runs.get(id)` has the leaderboard (show `score_test_natural`, `score_val_natural`, `fit_time`, `pred_time_test`; `val_score_std`/`fold_scores` give "± spread" for bagged runs), the ensemble, holdout metrics and confusion matrix. `eval_metric.greater_is_better` says which way is better; for errors it is false.
- Problem types to offer: `auto | binary | multiclass | regression | quantile` (quantile needs `predictor_kwargs.quantile_levels`). Metrics: any AutoGluon name (`accuracy, balanced_accuracy, f1, f1_macro, roc_auc, log_loss, mcc, precision, recall, r2, root_mean_squared_error, mean_absolute_error, …`). Presets: `medium_quality` (default, no bagging, fast), `good_quality`, `high_quality` (refit_full → best model ends in `_FULL`, no OOF for it), `best_quality` (bagging + stacking), `extreme_quality`, `optimize_for_deployment`, `interpretable`.
- `GET /api/models` gives every family's name, description, objective and symbols for the "what is this model" panel.
- Predictions: `api.runs.predict(id, rows)`; missing columns are allowed and reported in `missing_columns`.
- The profile's `task` says what the label asks for; use it to pick the default problem type and to allow regression in the wizard.
- `LiveRun.tsx` is a starting point you can replace; keep its test IDs or update `e2e/live.spec.ts`.
- One fit at a time by default: a second run waits in `queued` (its stream shows `run_queued` only until it starts).
