# S1 · Skeleton + data (plan steps 1–2) and the regression harness

Status: **done, `make test-full` green.**

## What works

**Skeleton**
- `backend/app`: one FastAPI process, SQLite through the standard library (`db.py`, one short connection per call, WAL), data folder `backend/data/` (git-ignored, override with `ENSEMBLE_DATA_DIR`).
- `backend/requirements.txt` is pinned and already has scikit-learn, xgboost, mlflow, pandas, numpy, httpx, pytest and sse-starlette for later sessions.
- `GET /api/health` → `{status, version, datasets, data_dir}`.
- `Makefile`: `make setup`, `make dev` (uvicorn :8000 with reload + Vite :5190, one command, Ctrl+C stops both), `make test`, `make test-full`, plus `make api`, `make ui`, `make e2e`, `make clean-data`.
- Vite proxies `/api` to `ENSEMBLE_API_URL` (default `http://127.0.0.1:8000`). When the API is down the proxy answers **503 with header `X-Ensemble-Proxy: api-unreachable`** (instead of Vite's bare 500) and logs one line instead of a stack trace per poll.
- `src/shared/api/`: `client.ts` (typed `api.health()`, `api.datasets.list/get/upload`, `ApiError` with `.unreachable`), `types.ts` (mirror of the backend shapes), `mode.tsx` (`ApiProvider` + `useApi()` → `{mode: 'checking'|'live'|'mock', health, recheck}`; polls health every 5 s in mock and 20 s in live, so starting the API flips the UI to live without a reload).
- Status bar shows `● live · API 0.1.0` or `▲ mock mode · API offline` (`data-testid="api-mode"`, `data-mode`). Clicking it rechecks.

**Data**
- Samples, generated on first start with seed 42 (byte-identical on regeneration):
  - `support-tickets`: 20,000 rows, columns `ticket_id, subject, body, channel, priority, customer_tier, category`. Six classes (Technical 25%, Billing 24%, Account 19%, Shipping 16%, Feature Request 13%, **Security 3.1%**, the rare one). Bodies mix sentences from neighbouring classes and shared filler, so vocabulary overlaps (TF-IDF + LogReg 5-fold macro-F1 ≈ 0.94 in a quick check — there's headroom). 300 exact duplicates (same content, new ticket ID; 303 counted, 3 natural collisions). **300 planted wrong labels**, mostly to a confusable class, never on a duplicated row. Sidecar `data/datasets/support-tickets/label_noise.json`: `{n_flipped, flipped: [{row, ticket_id, true_label, given_label}]}`, `row` = 0-based position in `data.csv`.
  - `account-churn`: 10,000 rows, `account_id, plan, region, contract, seats, mrr_usd, tenure_months, tickets_90d, last_login_days, nps, churned`. 13.75% `Yes`. Missing values in `nps` (~6%) and `region` (~2%). Signal is a known logistic model; coefficients in sidecar `signal.json` (`region`, `seats`, `mrr_usd` are noise).
- `GET /api/datasets` (samples first in fixed order, then uploads oldest first), `GET /api/datasets/{id}` (summary + full profile), `POST /api/datasets` (multipart `file`, optional form field `target`; `.csv/.tsv/.txt`; 400 with a readable `detail` for bad files; 201 on success; a rejected upload leaves nothing on disk).
- Profile (`backend/app/profiling.py`): per column `type` (`text | category | number | id`), `dtype`, `role` (`target | feature | ignored`), `missing`, `missing_share`, `unique`, `example`, `stats` (numbers: min/max/mean/std/median; text: mean/max chars) or `top` (categories). Dataset-level: `kind` (`text` if any text column), `target`, `suggested_target`, `label_candidates`, `classes` (`name, count, share`, sorted by count), `n_classes`, `imbalance_ratio`, `missing`, `duplicates` (full-row duplicates **ignoring ID columns**, per-text-column duplicates, conflicting labels among identical rows), `warnings`, `splits`.
- Holdout and folds (`backend/app/splits.py`): stratified 20% holdout + 5 stratified folds over the rest, seed 42, stored in `data/datasets/<id>/splits.json` as `{seed, target, stratified, holdout_share, n_folds, holdout: [rows], fold: [per-row 0..4 or -1 for holdout]}`. Falls back to unstratified when a class has fewer than 6 rows or there's no label.
- Quick Train's dataset step: in live mode lists the server's datasets, starts on `support-tickets`, profiles via the API, uploads go to the API, and shows missing values, duplicates, holdout/folds, seed and warnings. In mock mode it's unchanged (built-in samples, in-browser profiler). If the API drops mid-upload it falls back to the browser profiler. Continue is disabled when there's no label column with ≥2 classes.

## What doesn't / not done

- No way in the UI to pick a different label column; the API accepts `target` on upload, and the profile lists `label_candidates`. A `PATCH /api/datasets/{id}` (re-profile + re-split with a new target) would be the clean addition if S2+ need it.
- Rows with a missing label are counted in the warning but still get a fold (their label becomes the string `"nan"` in the split). The engine should drop rows where `target` is missing before training; the splits stay valid because they index rows of `data.csv`.
- Only Quick Train's dataset step is wired. Autopilot's brief still uses the mock samples (`SAMPLES` from `quick-train/datasets.ts`), and the Recipe/Train/Results steps are still simulated — that's S2/S3.
- The `subject` column in tickets has 42 distinct values and is profiled as `category`, not `text`. That's deliberate (short repeated subject lines); the engine will one-hot it.
- `npm audit` reports advisories in the existing dev dependencies; untouched.

## Notes for S2 (engine, SSE, six models)

- Read data with `DatasetStore.load_frame(id)` (= `pd.read_csv(data/datasets/<id>/data.csv)`); row positions are the IDs that `splits.json` and `label_noise.json` use. Get folds with `splits.load_splits(store.splits_path(id))` and `splits.fold_indices(splits, k)` → `(train_rows, val_rows)`; holdout rows are `splits["holdout"]`. Never re-split.
- Feature decisions come from the stored profile: `profile.columns[*].type` and `.role` (`ignored` for IDs, `target` for the label). Text → TF-IDF, category → one-hot, number → pass through (scale for linear models). Number columns can have NaN (`nps`); category columns can have None (`region`).
- App state lives on `app.state` (`settings`, `db`, `datasets`), set in the lifespan in `main.py`. Add the thread pool and the in-memory event lists there; mark in-flight runs failed in the same lifespan on start. Put new tables in `db.SCHEMA` (it's `CREATE TABLE IF NOT EXISTS`).
- Keep `schemas.py` and `src/shared/api/types.ts` in step, and add new calls to `api` in `client.ts`. Pages check `useApi().mode` and keep their simulation for mock mode.
- Golden metrics: the ticket sample is deterministic (seed 42), so pinning macro-F1 within ±0.005 is safe. Label noise caps achievable accuracy at roughly 98.5%.
- The Vite proxy passes SSE through as-is (http-proxy streams); if buffering shows up, set `Cache-Control: no-cache` and `X-Accel-Buffering: no` on the event stream.
