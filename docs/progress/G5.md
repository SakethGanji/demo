# G5 · Segmented models

**What it does.** You pick a segment column, such as a customer type. One run trains a **global** AutoGluon model and **one model per segment** with the same config. It compares each segment's model with the global one on the same holdout rows: per segment and overall, with **DeLong paired 95% CIs** (ΔAUC). The result registers as **one routed version**: each row is scored by its segment's model when that segment is routed, else by the global model. Unknown segment values also go to the global model.

Where it lives (no new navigation):
- **Build:** a "Segmented models by …" suggestion, which opens `#/segmented?dataset=` (lights up Build).
- **Run page:** `#/segmented?run=`.
- **Registry:** version → **Segments** tab, plus Try It, Reason Codes, Batch & Drift and the Model Card. All of them work across segments.

## Backend
- **`segmented/core.py`: a new run kind, `segmented`.**
  - **Where it runs:** in the run worker via `run_other`, so it has the same queue, events, SSE and MLflow logging as other runs.
  - **How it fits:**
    - one F4/F6 split;
    - every fit goes through F12's `prepare_fit`/`fit_predictor`;
    - log loss for binary targets, RMSE for regression;
    - `medium_quality`, 20 s per model by default.
  - **Which segments get their own model:** a segment needs ≥ 300 training rows and ≥ 30 rows of the rarer class. Below that, it keeps the global model and the page says why.
  - **Routing:**
    - **With a tuning slice** (an out-of-time or group split): the slice is **held back from every fit** and used only to route. A segment gets its own model if that model beat the global one on the segment's tuning rows (log loss). The holdout is never used to choose.
    - **Without a tuning slice:** every trained segment model is routed.
  - **Threshold:** one threshold t for every model: t = c_FP/(c_FP+c_FN) = 1/11, the F7 default cost. A decision changes only because p̂ changed, never because t did.
  - **Comparison:**
    - binary: ΔAUC with a DeLong paired CI (reuses F18's `paired_delong`), plus Δ log loss with a paired bootstrap CI;
    - regression: ΔMSE with a paired bootstrap CI.
  - **What is reported:**
    - per segment: each segment's own model against the global model;
    - overall: the routed model against the global model;
    - also overall with every segment model, unrouted, shown for honesty.
  - **Serving:**
    - `score_rows` / `try_row` / `score_batch` route each row to its model.
    - Reason codes come from **that row's own model**, using F10's `Reasoner` with background rows from that segment's training data.
    - Every routed model uses **one code book**: the global model's R01… mapping, with the user's edits. So R04 means the same feature whichever segment's model cited it.
- **`segmented/api.py`:**
  - `GET /api/segmented/detect` gives the target, segment column, candidates, columns left out and split, each with its evidence. It also gives a cheap heterogeneity check: the rank correlation of each input with y inside each segment.
  - `POST /api/segmented/runs` works with `{dataset_id}` alone. It refuses targets that are neither yes/no nor numeric, and segment columns outside 2–12 values.
  - `GET /api/segmented/runs/{id}` returns the run's result.
- **Registry:**
  - **Build:** `build_other` copies only the global model and the **routed** segment models, and measures latency.
  - **Version record:** problem type `binary`, plus the threshold and positive class, so the F10 card section and Try It work.
  - **Endpoints:**
    - `/predict` and `/score` (`reasons=true`) route each row.
    - Batch scoring adds `routed_model`, `p_1`, `decision` and `reason_codes` columns (codes for the first 200 adverse rows), plus PSI drift.
  - **Reason Codes tab:** the mapping editor and stability check read the global model, and the mapping is shared by all routed models.
  - **Counterfactuals (G1)** are refused for routed versions with a clear 400.
- **Model card:** a "Segmented models (routed)" table (JSON/MD/HTML plus the card view), with per-segment and overall ΔAUC and CIs and what scores each segment.
- **G0:**
  - **New suggestion `segmented`:** it needs a yes/no or numeric target and a segment-role column.
  - **Score:** 96 (top) when the quick check finds an input moving y in **opposite directions** across segments (|ρ| ≥ 0.08 on both sides). Otherwise 55.
- **Sample `samples_g5.py` → `segmented-loans`** (no existing sample touched):
  - 30,000 applications across four customer types.
  - Salaried and self-employed risk is near-linear and noisy. Student and small-business risk are strong, wavy surfaces of 2–3 inputs.
  - The formulas are in the docstring.

## Numbers (smoke `seg`, zero-config: only `{dataset_id}` sent)

The split is out-of-time: 19,149 training rows, 4,826 tuning rows (routing only) and 6,025 holdout rows. t = 0.0909.

| customer_type | holdout (bad rate) | global AUC | own AUC | ΔAUC [95% DeLong CI] | routed |
| --- | --- | --- | --- | --- | --- |
| salaried | 2,975 (6.2%) | 0.7384 | 0.7497 | +0.0113 [−0.0055, +0.0281] | global (tuning: 0.1837 vs 0.1825) |
| self_employed | 1,223 (5.6%) | 0.8763 | 0.8864 | +0.0101 [−0.0065, +0.0266] | own |
| student | 914 (41.0%) | 0.7774 | 0.7728 | −0.0045 [−0.0204, +0.0113] | global |
| **small_business** | 913 (54.9%) | 0.8224 | **0.8331** | **+0.0107 [+0.0004, +0.0210]** | own |
| **overall, routed** | 6,025 | 0.8928 | **0.8950** | **+0.0022 [+0.0004, +0.0041]** | 2 own + global |
| overall, every segment model | 6,025 | 0.8928 | 0.8960 | +0.0032 [−0.0001, +0.0066] | (not routed) |

- **Acceptance: met.** The routed model beats the global one on small_business with a CI above 0. The overall comparison is reported with its CI.
- **Honest reading:**
  - Both lower bounds are close to 0 (+0.0004).
  - Three of the four segments show no clear difference.
  - The routing rule kept student and salaried on the global model.
- **Reproducibility:** three runs (two smokes and one manual) gave identical numbers. AutoGluon finished within its time budget.
- **Earlier sample designs:**
  - with sign-flipped linear effects, the global model **won** (ΔAUC up to −0.025);
  - with a moderately different SME surface, there was no difference.

  A global GBM ensemble learns segment interactions well. Segment models help when a segment's risk surface is complex and distinct.
- **Run time:** about 90 s for five fits.
- **Registered version:**
  - 605–634 MB (global plus 2 routed models; unrouted ones are not copied);
  - single-row p50 ≈ 24 ms; batch ≈ 52 µs/row.
- **/score:** small_business → segment model; salaried → global; pensioner (unseen) → global. Codes are consistent across models.
- **Batch of 100:** 40 rows scored by segment models.

**Smoke.** `SMOKE_ONLY=seg,intake,core make smoke` passes **37/37 in 221 s**:
- seg: 3 steps;
- intake: 14, including the new `segmented-loans` truth row, 12/12 with top `segmented`; the 10 other samples are unchanged at 100% and keep their top suggestions;
- core: 20.

`npm run build` and `tsc` are OK.

## Limits and open problems
- **The effects are small.** The win is real but marginal on this sample (CI lower bound +0.0004). That is typical: a global GBM ensemble with the segment column is hard to beat. The page shows every segment, losses included.
- **Thin reason-code backgrounds.** A segment model's reason-code reference pool is that segment's *approved* training rows. At t = 0.09, with a 55% bad rate, small_business has only 16 approved reference applicants, so its codes rest on a thin background. A per-segment threshold or the "population" reference would help; neither is offered yet.
- **Routing changes training data.** Routing on the tuning slice costs the models those rows (they train on 64% of the data, not 80%). Without a tuning slice (random split), every eligible segment is routed, with no out-of-sample check.
- **Not supported:** multiclass targets; counterfactuals (G1) for routed versions; monitoring, the credit report and fair lending for routed versions (those tabs are tabular-only).
- **Not in the Model Doctor or Vela yet** (G10/G11). The Doctor could recommend segmentation when the per-segment slices differ. Vela can call `POST /api/segmented/runs`.
- **Smaller fixes made along the way:**
  - The Makefile's default `SMOKE_ONLY` now includes `fair` (G4 had left it out) and `seg`.
  - Each smoke run adds one segmented run and a `smoke.segmented` version.
