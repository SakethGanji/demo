**Acceptance.** The new `personal-loans` sample (10,000 rows, binary, about 24 % default) has a planted weak slice:
**channel = broker ∧ age < 30** (361 rows, 67 of them in the holdout). Inside it, P(default) = 0.5 whatever the
features say. On a medium_quality run (holdout ROC AUC 0.7456), the search finds it at **rank 2 of 9 listed**
(882 slices tested). It is reported as `age < 31 ∧ channel = broker` because the first age quintile ends at 31.
Against the planted holdout rows: Jaccard 0.89, precision 0.89, recall 1.00.

- **Parents.** The planted pair's parents are much weaker alone:

  - channel = broker: ℓ̄ 0.551, q 0.039.
- **Counts.** 66 slices are significant at q ≤ 0.05. 57 of them are pairs no worse than one of their parents, so they are

- **Permutation null.** With ℓ shuffled across rows (R = 5), the search finds **0, 0, 0, 0, 0** weak slices.
- **Independent check.** The smoke repeats the whole search with scipy (`ttest_ind(equal_var=False,

## What changed

**Engine (`backend/app/engine/slices.py`, new).**
- **Per-row loss ℓᵢ: the run's own metric, made per row.** A different loss can be chosen with `loss`.

  | run | ℓᵢ |
  | --- | --- |
  | F7 cost run | the decision's cost (`costs.row_costs`, at the run's threshold) |
  | F9 quantile run | the mean pinball loss over the levels |
  | regression | \|y − ŷ\| |
  | classification, probability metric (roc_auc, log_loss, average_precision, …) | −log p̂(y) |
  | other classification metrics | 1[ŷ ≠ y] at the run's threshold |

- **Slices:**
  - every value of every feature, and every pair of values of two features;
  - numbers with more than 5 values are cut at holdout quantiles; dates the same way;
  - a category keeps up to 30 values, and the rest form "(other)";
  - missing is its own value;
  - text and id columns are left out, each with its reason.
- **Support:** n_S ≥ max(30, 2 % of the holdout), and the complement must be at least as large.
- **Test.** Each slice is tested against its complement with Welch's t, one-sided ("worse"), with Welch–Satterthwaite
  ν. Δ = ℓ̄_S − ℓ̄_C gets a 95 % t-interval. It is vectorised (bincounts of ℓ and ℓ²), so 882 slices take about 0.1 s.
- **Benjamini–Hochberg** runs over every slice tested, singles and pairs together. The count m is reported.
- **Ranking** is by the lower bound of Δ's interval. A pair is listed only if the lower bound of its own ℓ̄ is above both
  parents' ℓ̄; the others are counted as "explained by a parent".
- **Permutation null:** the same search with ℓ shuffled, R = 5 times.
- **Conditions** are plain JSON, such as `{column, op: in | not_in | range | missing, values | lo/hi}`.
  `slice_mask` applies them to any rows: the holdout, or F13's pool.

**API (`backend/app/engine/slices_api.py`, new router).**
- `POST /api/runs/{id}/slices` takes `{min_support, bins, max_levels, alpha, pairs, null_permutations, loss, columns}`
  and runs the search synchronously. It returns 400 for a loss that does not fit the run, unknown columns, or too
  large a support. It returns 422 for an α outside (0, 1).
- `GET …/slices` returns the latest search. It searches again when `holdout_predictions.csv` changes (sha), for
  example after a new threshold.
- `GET …/slices/{sid}/rows`: the slice's holdout rows, worst first, with features, truth, prediction, p̂ and ℓᵢ.
- `POST …/slices/{sid}/shap {rows = 6}`: S4's Kernel SHAP worker (`heavy.shap_holdout_row`, cached per row) on rows
  sampled from the slice and as many from the rest. It reports mean φ inside vs outside per feature, plus each row.
- `GET …/slices/{sid}/pool`: how many training rows fall inside the slice.
- Each slice carries `fairness_columns`: its columns that Explain → Fairness can group by.
- **F13 link** (the "targeted labelling" that F13 noted as missing):
  - `POST /api/runs/{id}/active-learning` takes `slice_id`. The job restricts every arm's pool to the training rows
    inside the slice, so active and random are compared on the same pool.
  - It returns 400 when budget × rounds is more than the slice's hidden rows; the message names the largest budget
    that fits.
  - The state and the `active_learning/1` summary carry `slice`.
- **Summary for F17 (`slices/1`, on the run payload as `slices`):**
  ```
  {schema, computed_at, loss, overall, n, n_tested, n_significant, n_weak, alpha, min_support, null_mean,
   top: [{id, label, columns, n, mean, delta, ci, ratio, q}] (5)}
  ```

**Sample (`backend/app/samples_f16.py`, new; registered in `samples.py` as `personal-loans`).**

- `samples.py` changed, so its samples regenerate once. They are seeded, so they get identical rows.

**UI: Explain → Weak Slices (`SlicesPanel.tsx`, every tabular run).**
- **Hero:** weak slices of m tested, the worst slice with Δ and its CI, overall ℓ̄, and the permutation null.
- **Ranked table:** n_S and its share, ℓ̄_S, ℓ̄_C, Δ, an interval plot, and q. Each row has Rows & SHAP, Label more, and
  "fairness by" links for its columns.
- **Slice detail:**
  - its parents;
  - SHAP inside vs outside, computed on demand;
  - its rows, worst first; a click opens that row in Features & SHAP.
- **Formula panel:** Δ, se, t, ν, p, the CI and BH q, bound to the selected slice, with a where-list that defines ℓᵢ,

- **What Was Searched:** every feature's bins with their counts, and the columns left out with the reason. An Advanced

- **Links:**
  - `ExplainPage` passes `slice=` and `group=` hash params.
  - `FairnessPanel` takes `initialGroup`.
  - `LabellingQueuePanel` takes `sliceId`. It shows the slice, its training rows and the hidden rows that can be picked,

## Open problems

- **Hard-by-nature regions rank too.** The search ranks by loss, so it finds where the model is worse, not only where
  it is fixable. credit_score < 640 is rank 1: outcomes there are near a coin flip, so even a calibrated model has high
  log loss. Separating "irreducible" from "fixable" would need, for example, the expected loss under the model's own
  p̂ (ℓ − H(p̂)), or a learning curve per slice. F17 should read Δ next to the slice's base rate.
- **The loss decides what is weak.** Under 0/1 error at t = 0.35, the planted slice is not in the top 3 (5 weak
  slices; credit_score < 640 is first). Under the cost run (c_FN = 5, t = 0.18), nothing is weak: the slice is predicted
  positive throughout and costs no more than the rest. This is correct for those metrics, but it surprises.
- **Boxes of one or two features at quantile edges.**
  - A region whose edge falls inside a bin is found diluted (age < 31 for age < 30).
  - There are no three-way slices and no learned regions (trees).
  - High-cardinality categories keep 29 values plus "(other)".
- **Discovery uses the evaluation holdout.** The slices are found on the holdout the model is scored on; confirm a
  slice on fresh data (a registry batch with labels) before acting on it. The BH correction controls false discoveries
  among the slices tested, not the bias of then studying the chosen one.
- **Welch's t is a normal approximation.** On a 0/1 or heavy-tailed loss it is adequate at n ≥ 30; smaller slices are
  not tested.
- **SHAP inside vs outside is coarse.** It uses 6 + 6 sampled rows; Kernel SHAP takes about 5 s a row, cached. More
  rows can be requested through the API (`rows`), but the UI does not offer it.
- **The pre-filtered queue can be small.** The planted slice has 326 training rows, about 293 of them hidden at
  h = 0.9, so b defaults to about 146 per round for 2 rounds, and budget × rounds above that is refused. There is no
  active-vs-random verdict per slice in the smoke; it ran with `compare_random: false` for time.
- **Smoke residue.** The smoke leaves a pre-filtered queue open on its run (cancel only stops a working process), plus
  four runs.
