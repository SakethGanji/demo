# D5 · Real-data proof: the whole chain on public data with known answers

**What it proves.** The core ask of round 4 is "tell us as much as possible about what is missing from the data, and how
to improve". D5 runs the whole chain on real tables whose answer is known:

Data Doctor → ladder → Model Doctor + What's missing → review loop → post-deployment changes.

There are two kinds of known answer:

- **public datasets with published scores**: the four of round 4 plus two new OpenML sets;
- **planted-issue copies of real tables**: real distributions, one issue injected each, so the right finding is known.

**Verification (the user's rule).** No smoke or integration suite was run and no smoke section was added. `make realdata`
is a **manual driver**: it chains the API calls the UI makes, prints what it observed, and gives one PASS / FAIL line per
expectation. The checks are that driver plus `npm run build` and `tsc --noEmit`.

## How to run it

```
make api                        # or any API on :8000
make realdata                   # every item; REALDATA_ONLY=taiwan,bank_leak picks some
```

- **Files:**
  - `scripts/realdata.py`: the driver.
  - `scripts/realdata_data.py`: the two new datasets and the planted copies.
  - It reuses `scripts/realdata_d1.py` for the four round-4 downloads.
- **Cache:** downloads and copies go to `backend/data/realdata/` (not committed).
- **Results:** `backend/data/realdata/results.json`, plus `results_run1.json` and `run1.log` for the first, pre-fix run.
- **Flags:**
  - `--recheck` re-reads the Data Doctor and the Model Doctor of finished runs without retraining;
  - `--rereview` runs the review again (finished experiments are reused);
  - `--redo` retrains;
  - a re-planted copy (its CSV changed) is retrained by itself.
- **Chain per item:**
  1. `POST /api/datasets`;
  2. `GET …/data-doctor`, polled until the label check finishes;
  3. `POST /api/runs`: medium_quality, 3-fold bagging, no stacking, 90–300 s;
  4. `GET …/ladder`, then `GET …/doctor`;
  5. the Doctor's own prescription where the expectation needs it:
     - the leak ablation (`POST …/experiments`);
     - the time shift check (`POST …/shift`);
  6. `POST …/review`, then poll `GET …/review/{rid}`; reviews run **one at a time**;
  7. for the drift copy: register, then score four labelled batches, then `GET/POST …/changes`.
- **Run time:** the first run of every item took **2 h 10 min** on 4 CPUs, where the reviews and the Banking77 runs
  dominate. Pass 2 (below) re-checked the fixed code in about 45 min.

**How the training labels were flipped without touching the holdout.** The platform draws a stratified holdout from the
label column, so flipping labels moves rows in and out of it. Instead, the copy keeps the label column as it is and
**swaps the features** (Taiwan) or **the texts** (Banking77) of pairs of training rows with different labels. Each
swapped row then carries the other row's label: a flipped label. The split is unchanged (asserted), the holdout is clean,
and the flipped rows are listed in `planted/*_flip_rows.json` to score cleanlab against.

## Known limits (for the adversarial reviewer)

- **clean_labels was never kept on random flips.**
  - **Taiwan, 10 % flipped training labels:**
    - the flips cost the full model 0.0062 AUC (clean 0.7799 vs 0.7737 on the identical holdout);
    - cleanlab's dropped rows caught 54 % of the flips at 37 % precision;
    - on a weak-signal table (AUC 0.78) a flipped label looks like a genuine hard case;
    - the full-model Δ was −0.0038 [−0.0086, +0.0008].
  - **Banking77, 10 % flipped intents:** −0.0030 [−0.0115, +0.0050] accuracy. Bagged ensembles shrug off 10 % random
    noise, and cleanlab's flags also remove real boundary examples.
  - **The 30 % copy:** cleanlab's flags are 80 % precise with 80 % recall (2,404 dropped, 1,918 of the 2,400 flips
    caught). Even so, dropping them gives Δ −0.0175 [−0.0285, −0.0065] accuracy, and **relabelling** them to cleanlab's
    suggestion (a new `clean_labels {mode: relabel}` and a typed `relabel` transform, added in D5) gives −0.0250
    [−0.0380, −0.0130]. On the 10 % copy: relabel −0.0140, drop −0.0030; cleanlab precision 0.62 / recall 0.73. With
    77 classes, random flips do not move the argmax: more rows beat cleaner rows. The planted-flip expectation stays
    **FAIL**, and that is the honest answer.

    prescribe the experiment; the experiment then reports honestly that the full model does not benefit.
  - **For the reviewer:** a cleaner that relabels instead of dropping, or drops only the most confident flags, may do
    better. It is not built.

  overlap stay indistinguishable from data alone, and the wording now says so.
- **The far-code rule (fix 6)** reads values ≥ 90 only. A table coding missing as 77 or 88 in a count is not caught
