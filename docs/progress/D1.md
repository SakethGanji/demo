# D1 · Data Doctor

**What it does.** Before any training, Build shows a **Data Report** at the top once a table is chosen. It says what is wrong with the table, why (the rule, on screen), how much (the numbers), with example rows, and how to fix it. Fixes are typed transforms. One click applies them into a **new dataset version with lineage**, and the original is never changed. The report also asks the **"known at decision time?"** question inline. Columns answered "not known", plus the fairness-only columns, are dropped from every run on that dataset, and each run records what was dropped and why.

## Backend

- **`backend/app/data_doctor.py`**: 12 rule checks plus label quality. Each finding is `{id, severity, title, numbers, rule, evidence {columns, rows}, fix {kind, text, transforms, selected}, columns}`. Severity is `high`, `medium`, `low` or `info`; what each level means is on screen.

| id | Rule (shortened; the full text is in the API and on screen) | Fix |
|---|---|---|
| `leakage` | Smart Intake's leak roles (post-outcome names, filled for one class only, purity), or a single-column AUC ≥ 0.90 (≥ 0.97 is high). Regression: \|ρ\| ≥ 0.95. **A suspect by name only must also reach AUC ≥ 0.75.** The numbers include the median of the suspect for each class. | Question: known at decision time? |
| `coded_values` | Integer column, ≤ 20 values, mostly ≥ 0, with 1–3 negative codes on ≥ 1 % of rows | `split_codes`: codes → 0, plus a `<col>_code` column |
| `disguised_missing` | −1 / −9 / −99 / −999 / 99 / 999 / 9999 … on ≥ 0.5 % of rows, outside the column's own range | `to_missing` + a `_was_missing` flag (pre-selected) |
| `missing_words` | 'unknown', '?', 'N/A', 'null', '-' on ≥ 0.5 % of rows (low) | `to_missing` + flag (not pre-selected) |
| `rare_codes` | Integer code column (3–12 values): values outside the run of common values (≥ 1 % each) that hold < 5 % together. A thinning count tail (3, 4, 5 …, each rarer) is skipped. | `to_missing` + flag |
| `informative_missing` | Missing on 1–95 % of rows, and the outcome differs between missing and present: z-test p < 0.001, gap ≥ 5 points | `add_missing_flag` |
| `duplicates` | Exact duplicates ignoring IDs (medium at ≥ 2 %); near-duplicates after trimming, case and 4-significant-digit rounding | `drop_duplicates` |
| `conflicts` | Identical features, different labels | `drop_rows` (not pre-selected) or label review |
| `class_balance` | Smallest class < 10 rows: high; < 50: medium; minority < 5 %, or any class < 100 rows when there are more than 2 classes: low. The evidence is the smallest classes and their holdout counts. | `merge_classes` when ≥ 2 classes have < 20 rows; otherwise advice |
| `sample_size` | Binary: events per feature < 5 is high; < 20, or under 2,000 rows, is medium. The numbers include the holdout AUC ± (Hanley–McNeil). Regression and multiclass: rows per feature. | Advice: simpler rungs, read the CIs |
| `time` | A date exists: five time-ordered bins, χ² / Kruskal p < 0.001 and a gap ≥ 5 points means drift; empty months are gaps | Advice: out-of-time split |
| `ids_constants` | Row IDs, constants, text "categories" with more distinct values than half the rows | `drop_columns` |
| `protected` | Protected names (sex, gender, race, marital, …), values that name a sex (German `personal_status`), a numeric age; proxies with Cramér's V ≥ 0.5 | Question: fairness check only |
| `label_quality` | Background job (≤ 60 s): a 3-fold out-of-fold HistGradientBoosting (TF-IDF + LR when there is text), then cleanlab's `find_label_issues(prune_by_noise_rate)`. **Medium** needs all four: the model beats the majority class by ≥ 5 points; ≥ 5 % of rows are flagged; the most confident fifth is wrong ≥ 3 points more than expected; and at ≥ 0.6 × the overall error. (Flips hit confident rows; overlap does not.) | `drop_rows` of the flagged rows (not pre-selected); review queue after a run |

- **`backend/app/data_doctor_api.py`**
  - `GET /api/datasets/{id}/data-doctor`. The first call starts the label job, which is cached per dataset and target in `data_doctor_labels.json`.
  - `POST /api/datasets/{id}/data-doctor/apply {transforms, by}` creates a new version with `DatasetStore.create_version`. The lineage holds `parent`, `root`, `kind: data_doctor`, `fixes` (each with its effect: cells changed, rows dropped, columns added), `by`, `applied_at`, `root_rows` and rows and columns before and after. **The holdout is the parent's holdout rows that were kept**, so scores stay comparable. The decision-time answers carry over (`inherited_from`).
  - `GET`/`POST /api/datasets/{id}/decision-time {known: {col: bool}, fairness_only: [...], by}`, stored in `decisions.json`. Dropping the target is refused.
- **Runs.** `POST /api/runs` unions the not-known and fairness-only columns into `drop_columns` (`use_decision_time: true` by default). The run config records `decision_time = {not_known, fairness_only, dropped, applied, answered_at, by, inherited_from}`. Smart Intake's quick-train pre-fill `drop` includes them too, so the wizard shows them.
- **Answered leakage** drops to `info`: "Leakage suspects answered: duration dropped from runs".

**Interpretation of "suspects pre-ticked".** The checkbox means "known when you decide". Suspects start **unticked** (not known, so dropped) and protected columns start **ticked** for "fairness check only". **Nothing is dropped until the answers are saved** (Save answers, or Apply, which saves them too). Until then, runs keep every column. D3's leakage ablation therefore still sees bank `duration` unless the user has answered.

## UI (Build → Data Report)

- **Header:** severity counts, rows × columns, target, check time, and one primary action, **Apply N fixes →** (or **Save answers** when there are no fixes and the question is open).
- **Findings:**
  - High and medium are listed; low and info sit in an "Also · …" fold-out.
  - Each row shows the severity, the title and a **fix** tick (or "question below" / "advice").
  - Opening a row shows the fix in words with its transforms, the **rule**, the **numbers** as chips, and the **evidence rows**.
- **Inline question:** "Known when you decide?" (suspects, with their single-column AUC) and "Fairness check only?" (protected columns), with the save status in words.
- **After Apply:** Build switches to the new version, with a ✓ line and a "↳ Fixed version of …" lineage line listing each fix's effect.
- **Reuses** `ErrorCard`, `Loading`, `useFetch` (it polls while the label job runs), `pct`/`sig4` from `format.ts`, `.chip`, `.table` and `.an-adv`.
- **New code:** `src/features/build/DataReport.tsx` (Build only, so not in `shared/`) and CSS in `build.css`.

**False positives found on real data and tuned:**

1. German `duration` (a loan term, AUC 0.63) was a leakage suspect by name. A name-only suspect now needs AUC ≥ 0.75. Bank `duration` (0.818) stays.
2. 'none' counted as a missing word. It is a real category in German credit (`other_parties = none`), so it was removed.
3. Count tails were read as rare codes: bank `previous` 3–7 and German `existing_credits` 4. A thinning tail above the common run is now skipped, and the coded-value columns (PAY_*) are excluded.
4. Words and numbers were mixed in one finding: bank's pdays = 999 sat behind 'unknown'. They are now separate findings: numbers medium and pre-selected, words low and not pre-selected.
5. Label quality took class overlap for noise: medium on a weak-signal drift table and on overlapping classes. It now needs signal over the majority class and confident errors at ≥ 0.6 × the overall error.
6. Multiclass EPV flagged card-transactions; EPV is now binary only. The multi-label `topics` target got class checks; multi-label targets are now skipped.

## Smoke `datadoctor` (scripts/smoke.py; crafted data in the new scripts/data_doctor_data.py)

1. **planted issues found.** 39,443 rows: one of each issue (`PLANTED` in the generator). All 10 are found at the expected severity, with the right columns, codes and values, and the duplicate count equals pandas'. Checks take 0.7 s; the request takes 1.1 s.
2. **fixes → new version.** The 6 pre-selected fixes: 11,893 values of 999 → missing + flag, `months_late` codes split (min ≥ 0, `_code` with 3 values), 1,851 duplicates dropped. The lineage holds the parent, the root, the fixes and who applied them. The holdout goes from 7,889 to 7,502 (the parent's kept rows). The original is unchanged, and the fixed findings are gone on the new version.
3. **decision-time drop.**
   - Dropping the target is refused (400).
   - The stored answer turns leakage into "answered" (info), and the intake pre-fill drops the answered columns.
   - A **trained** run records and drops `review_score`, `gender` and `age`; none of them appears in its feature importance. With `use_decision_time: false` they are kept.
4. **refusals.** An unknown fix, an unknown column, a fix on the target, or no fixes → 400. An unknown dataset → 404.
5. **classes, sample size, time.**
   - Classes of 8 and 12 rows → high; merging them gives 7 → 6 classes.
   - EPV 3.2 → high (AUC ± 0.232).
   - Drift 0.068 → 0.228 → medium.
6. **label quality.** 507 planted flips → 504 flagged (medium), **precision 1.00** on the top 200. The planted table without label noise → info.
7. **no false alarms on samples.** All 14 samples. The only high findings are the planted ones (loan-losses lgd/ead leakage, account-attrition duration_months leakage). The medium findings are credit-default and account-attrition time drift, both real.

`datadoctor` is added to the Makefile's `SMOKE_ONLY` and to the smoke default list.

## Notes for D2–D5

- **D2 (ladder):** `sample_size` gives events per feature and the holdout AUC ±, a natural input to "prefer simpler rungs". German: EPV 15, ± 0.079.
- **D3 (Model Doctor):**
  - A run's `config.decision_time` says which suspects were dropped by the user.
  - Leakage ablation can read `GET …/data-doctor` → `decision_time.columns` (suspects with AUC). Bank's `duration` is only dropped once someone answers, so the 0.95 → 0.80 ablation story still works on an unanswered upload.
- **D3/D4 (What's missing):** reuse `data_doctor.single_auc` and the `informative_missing` and `conflicts` checks. Conflicting identical rows are the "indistinguishable twins" in their purest form: Taiwan has 21 groups.
- **D4 (review):** typed experiments can apply Data Doctor fixes as they are: `POST …/data-doctor/apply {transforms}` returns a version with the same holdout rows.
- **D5 (real data):** `scripts/realdata_d1.py` already downloads and converts the four datasets. The planted-issue generator (`scripts/data_doctor_data.py`) shows the pattern for planted copies of real data.
- **Known limits:**
  - Rare codes can't tell a documented rare code (EDUCATION 4) from an undocumented one without a data dictionary.
  - Near-duplicates are not fixed, only counted.
  - The label job's cache key is the file's size and mtime.
  - The Data Report is not shown for SQL refresh diffs: each refresh is just a new dataset, which gets its own report.
