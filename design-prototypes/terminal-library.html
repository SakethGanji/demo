Charts

7 · one per type
Charts own no query logic. Each chart binds to a saved definition or a saved view and renders whatever series that source returns — so filters, grouping and version pinning live upstream, never in the chart. Seven types only: bar · line · area · scatter · pie · table · kpi. There are no dashboards — charts live per-dataset, ungrouped — and no server-side image rendering: the API returns JSON series, the client draws.

Artifacts

214 · 41.2 GB
Export as csvxlsxparquet DELETE
Every derived output the platform produces lands here with a kind and a retention clock. Artifacts are read with server-side projection, filter, sort and paging — never downloaded whole to be sliced — and exported as csv, xlsx or parquet only. The artifact row is the only way to resolve a storage key: a blob that was never registered has no reachable path, so orphaned writes are unreadable by construction.
Artifacts are not deleted by hand — and there is no delete button here on purpose. Every row carries a retention TTL by kind (left rail); when the clock runs out the sweeper (GC) removes the blob and its registration row together, in that order. Nothing in this list is an object you own the lifetime of — the way to keep one is Publish, which promotes it to a published_source dataset retained ∞. Deleting the view or definition that produced an artifact does not shorten its clock.
An artifact inherits the masking of its source. If a source column declares sensitivity: pii, every artifact derived from it is masked the same way for the same roles — and raw egress is gated by role: your role (member) can export masked, not raw.
