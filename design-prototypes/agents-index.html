Agent platform — prototypes

Thirteen screens, one stylesheet (_agents-base.css), no build step. Ordered by the path a user walks, because that ordering is the thing under review — if the flow does not hold, no individual screen saves it. Every screen is 1440×1024 and states its own design argument in an HTML comment at the top.
The flow what a person actually does, in order
01Front door
terminal-agent-home.html
Describe a task in a command strip; the agent is inferred and shown with its reason. Fleet rail, dense run table, waiting-on-you dock, and a footer that states what the tab is for.
Decides: the first object is the task, not the agent — while staying a cockpit, not a chat box.
shippingdense rebuild
02The session
terminal-agent-session.html
The agent working: its plan as a live checklist, narration in its own voice, tool calls as one-liners, a composer pinned to the bottom — beside the diff and the running app.
Decides: the workspace is the default view, not a tab. The trace is evidence; the work is the product.
shippingdefault run view
03The checkpoint
terminal-agent-checkpoint.html
The agent stops and asks. Arguments shown verbatim and editable, blast radius enumerated rather than adjectival, deny takes a reason the agent reads back.
Decides: steerable becomes a specific moment. It never times out into either answer.
shippingmodal over the session
04The workspace
terminal-agent-workspace.html
File tree with A/M/D markers, unified diff, live preview, test results — and the build→error→agent feedback ladder across the top.
Decides: compile and test failures route back to the model. Today they reach only your toast.
shippingfile-tree variant
05The corpus
terminal-agent-code.html
Every file, query and script any agent has written, across all runs, with provenance and the code itself. Filterable by kind, agent and state — scratch included.
Decides: durable (a real row, revertable) vs recovered (a tool-call argument, dies with the run). 84 of 118 are the second kind.
shippingview over data already captured
06Full trace
terminal-agent-run.html
The unabridged tool-call tree with arguments and results, including a rejected call the agent self-corrected from. Reached from the session, not lived in.
Decides: live and replay are one code path — ?after_seq=0 on a finished run streams the whole thing.
demoted to a link
Managing three nested scopes — agent, its tools, the reachable universe
07Agent configuration
terminal-agents.html
Identity, loop bounds, memory, structured output, capabilities, skills, provenance. Every field rendered from GET /api/nodes/AIAgent.
Decides: the form cannot drift from the runtime, because it is generated from it.
becomes /agents/{id}drawn pre-reframe
08Tool binding
terminal-agent-tools.html
Bound tools ⟷ catalogue, per-tool config as an attached detail, discovered-tool schemas read-only, and a permanent schema-token budget.
Decides: tool count is a real cost. 12 of 24 max, 4,180 of 6,000 tokens — a hard error at bind, not a warning.
the differentiated screen
09Connectors
terminal-connectors.html
Register an MCP server or OpenAPI spec, browse what it offers, curate by rule, see whose identity the calls carry.
Decides: import ≠ select. And identity headers are stripped from generated schemas — the analytics spec declares X-User-Id as a parameter.
shippingMCP + OpenAPI
—Front door, airy
terminal-agent-home-airy.html
The rejected first attempt: same structure, big soft prompt box, centred column of whitespace. Kept only so the two can be compared directly.
Why rejected: conflated task-first (structural, right) with spacious (aesthetic, not implied) — and looked like every other AI product.
rejectedreference only
Compounding the flywheel, and the two doors onto it
10Make it recurring
terminal-agent-schedule.html
A finished session plus one sentence — “do this every Monday and email me” — becomes a scheduled workflow. 14 tool calls map onto 6 nodes, and three rows show an em-dash where no node came from.
Decides: the workflow is recorded, not invented. £16.12 and 45m a year as an agent against £0.02 and 1m 49s as a workflow.
shippingbusiness-user bridge
11Promote to a tool
terminal-agent-promote.html
An accepted workflow becomes callable by the next agent. Ranked catalogue, usage, success rate, cost per call, and the slot competition that promotion actually is.
Decides: capability compounds while cost and variance do not — $0.004 a call against $0.38 by hand. Promotion is zero-sum: binding evicts rank 24.
shippingthe flywheel
12The programmer surface
terminal-agent-devsurface.html
Agents as YAML in the repo, tools as typed functions in tools/, environment promotion as a PR — and the divergence when someone edits a file-backed agent in the UI.
Decides: same object, two doors. Export writes a file; it does not adopt one — so nothing silently claims ownership.
shippingagents as code
