## 1. Product recap (the decisions this design implements)

- An n8n-style workflow editor as its own product area, sharing projects, secrets, tables, runs, releases, identity and audit with the app builder.
- Every workflow can have an interface: **Form** (generated from its input contract), **Chat**, or **Custom UI** (generated by the app builder engine and wired to the workflow).
- Every node has a **contract** (what goes in and comes out); workflows carry **tests**; AI generation is **spec first** and self-tested; releases are **four-eyes** and produce an **evidence pack**.
- Target: enterprise (bank) use. Identity, audit and durability are not optional.

## 3. Phase B0: identity, roles, audit (gates any pilot; can run in parallel with B1-B2)

**Identity**
- OIDC login (Microsoft Entra ID first; generic OIDC config). Studio uses a server session cookie (HttpOnly, SameSite=Lax, CSRF token on writes). Machines use project API keys (exist) or OAuth client credentials.
- `core/identity.py` becomes `get_principal(request) -> Principal{user_id, email, display_name, roles_by_project, kind: user|api_key|service}`. `X-User-Id` is accepted only when `WORKFLOW_DEV_AUTH=1` (tests, local dev) and refused otherwise.
- Every router gets `Depends(require(role, project_from=...))`. Default deny: a route without a declared requirement fails a startup self-check (test enumerates `app.routes`).

**Roles** (per project, plus team admin): `viewer` (read, run nothing), `operator` (run, resolve tasks assigned to them), `builder` (edit drafts, run tests), `approver` (approve releases and tasks), `admin` (members, secrets, settings). Table `project_members(project_id, user_id, role, granted_by, granted_at)`.

**Audit log**
- Table `audit_events(id bigserial, ts, actor_id, actor_kind, action, project_id, target_type, target_id, details jsonb, prev_hash, hash)`. `hash = sha256(prev_hash || canonical_json(row))`, so tampering is detectable. The app DB role gets INSERT and SELECT only; a trigger rejects UPDATE and DELETE.
- Written by one helper `audit.record(...)`, called in the same transaction as the change it describes. Covered actions: login, membership, secret create/rotate (never values), workflow save/publish/delete, test approve, generation keep, release create/approve/promote/rollback, task resolve, run start/cancel/retry, export.
- `GET /projects/{p}/audit?filters` and `GET /audit/verify` (re-walks the hash chain).

**Fixes on the way:** `/api/files/*` requires auth; public app tokens unchanged but recorded as `actor_kind=app_token`.

**Migration:** `2026xxxx_identity_audit.sql` (users gains `external_id`, `project_members`, `audit_events`, trigger).

**Tests**
- Unit: principal parsing, role matrix (table-driven: every role × every action), hash-chain build and verify.
- Integration: the route-enumeration test (no route without a requirement); 401 without session; 403 per role; audit row written in the same transaction (rollback leaves no audit row); UPDATE/DELETE on `audit_events` rejected by the DB.
- E2E stack: a fake OIDC provider (`tests/fixtures/oidc`) so Playwright logs in for real.
- **Exit:** no endpoint reachable without a principal except health, login and public app routes; the existing suites pass with dev auth.

## 4. Phase B1: contracts and the static checker

### 4.1 Shape format
A JSON Schema subset, so it maps directly onto OpenAPI and the app builder's typed client:

```
Shape = {
  type: object|array|string|integer|number|boolean|null|unknown,
  properties?, items?, required?, enum?, format?, nullable?,
  "x-source": derived|declared|observed|unknown,
  "x-labels"?: ["pii", "confidential", ...]          # used in B6
}
NodeContract = { inputs: {port: Shape}, outputs: {port: Shape}, error: Shape }
```
A port's shape describes one item's `json`. Items are lists, as today.

### 4.2 Node API additions (`nodes/base.py`)
```
class BaseNode:
    side_effects: Literal["none","read","write","network","llm"] = "none"
    idempotent: bool = True
    def contract(self, params, inputs: dict[str, Shape]) -> NodeContract   # default: type-level schema or unknown
    def egress_hosts(self, params) -> list[str]                             # for checks, mocks, evidence
```
Tiers:
- **Derived** (implement `contract`): Set, Filter (passthrough), If/Switch (passthrough per branch), Merge (by mode), Aggregate, Item lists, Sample, Respond, Stop and error.
- **Declared**: Start/Webhook/ExecuteWorkflowTrigger/ChatInput (`params.input_schema`), Code and PythonStep (`params.output_schema`), AI Agent (`output_schema` exists), LLM chat with a response schema.
- **Observed**: HttpRequest, Postgres, MongoDB, Neo4j, DataTable read (table columns give a declared shape for free), LLM without schema. Inferred with `infer_json_schema` from a run, stored on the node instance as `contract: {outputs, source: "observed", approved_by, approved_at, from_execution}`. Until approved, the shape is `unknown`.

Node instance schema (`schemas/workflow.py` `NodeDefinitionSchema`) gains optional `contract`. Stored in the workflow definition, so it is versioned and snapshotted with releases.

### 4.3 Static checker (`services/workflow_checker.py`)
1. Build the graph, topologically order it (cycles are only allowed through Loop; report others).
2. Propagate shapes from triggers through each node's `contract()`.
3. For every string parameter, extract `{{ }}` expressions, run `_transform_expression`, `ast.parse`, and walk attribute/subscript chains rooted at `$json`, `$input`, `$node[...]` to get field paths. Resolve each path against the shape reaching that node.
4. Check `$vars.X` exists for the project/environment, tables exist, hosts are on the egress allowlist, ExecuteWorkflow targets exist.

Findings have stable codes, severity and location (`node`, `param`, `path`):

| Code | Severity | Meaning |
|---|---|---|
| WF001 | error | Reference to a node that does not exist or is not upstream |
| WF002 | error | Field not present in the upstream shape (only when upstream is known) |
| WF003 | warning | Type mismatch (e.g. string used in numeric compare) |
| WF004 | warning | Branch output with no downstream path |
| WF005 | info | Upstream shape unknown, reference not checkable (coverage gap) |
| WF006 | error | Missing secret / table / sub-workflow |
| WF007 | error | Host not on the project's egress allowlist |
| WF008 | error | Required parameter missing or invalid for the node's property schema |
| WF009 | error | Expression does not parse |

API: `POST /projects/{p}/workflows/{id}/check` (draft or given body) returns `{findings, shapes_by_node, coverage}`. Save never blocks on findings; publish and release block on errors.

### 4.4 n8n format and import (`services/n8n_import.py`)
- `POST /projects/{p}/workflows/import?format=n8n` takes n8n JSON. A mapping table covers node types (`n8n-nodes-base.httpRequest` to HttpRequest, set, if, switch, merge, splitInBatches to Loop, wait, executeWorkflow, webhook, scheduleTrigger to Cron, postgres, respondToWebhook, and so on), parameter renames, and `connections` to our edge list.
- Expressions: n8n uses JavaScript; ours is simpleeval. Member access (`$json.a.b`, `$node["X"].json.y`) translates directly. Common JS methods get a small translation table; anything else is kept verbatim and reported.
- n8n Code nodes are JavaScript: imported as a disabled Code node holding the original source, plus a finding. Optional later: AI translation to Python, held to the same tests.
- Returns `{workflow, report: {mapped, unmapped_nodes, untranslated_expressions}}`; nothing is saved without the user's confirmation.

### 4.5 Tests
- Unit: `contract()` for every derived node (table-driven, including multi-output and passthrough); expression path extraction (fixtures of tricky expressions); each finding code with a minimal workflow that triggers it and one that does not.
- Golden fixtures: `tests/fixtures/workflows/*.json` (seeded examples, the Marketplace workflows, 10 imported n8n workflows). Snapshot test of checker output per fixture.
- Integration: `/check` endpoint, observed-contract approval flow, n8n import round trip (import, check, run with mocks).
- **Exit:** every seeded workflow checks with zero errors; deliberately broken copies produce the expected codes; 10 public n8n workflows import with a report.

## 5. Phase B2: test mode

### 5.1 Test case schema (stored in the workflow definition as `tests: []`)
```
{
  id, name, description,
  target: {kind: "workflow"} | {kind: "node", node} | {kind: "range", from, to},
  input:  {trigger: [items]} | {node_inputs: {port: [items]}} | {from_execution: id},
  mocks:  { <node>: {items: [...]} | {error: {message}} },
  expect: [ {node, port: "main", path, op, value} ],
  kind:   "behaviour" | "eval",            # eval used by AI nodes in B6
  status: "draft" | "approved", approved_by, approved_at,
  source: "human" | "ai" | "replay"
}
```
Assertion ops: `eq, neq, gt, gte, lt, lte, contains, matches, exists, not_exists, count, type, status` (node status success/error/no_output) and `shape` (output matches the node's contract). Every run in test mode also applies an implicit `shape` assertion to every node with a known contract.

### 5.2 Runner changes (`engine/workflow_runner.py`)
- `RunOptions{mode: normal|test, start_node, stop_at, mocks, network: allow|deny, seed}` passed through `run`.
- `stop_at`: do not queue beyond the given node.
- Mocks reuse the pinned-data skip path; a mocked error raises inside `_process_job` so retry and continue-on-fail behave as in production.
- `network=deny`: any node with `side_effects in (network, llm, write)` and no mock fails with `TEST_UNMOCKED_EFFECT`. This is the fail-closed rule.
- Time and randomness come from the context (`seed`, frozen `now`) so tests are repeatable.

### 5.3 API
- `POST /projects/{p}/workflows/{id}/nodes/{name}/test` `{input, mocks}` returns `{output, error, metrics, assertions, execution_id}`.
- `POST /projects/{p}/workflows/{id}/run-to/{name}` (real or test mode).
- `POST /projects/{p}/workflows/{id}/tests/run` `{ids?}` returns per-test results plus coverage (`nodes_with_tests`, `branches_exercised`).
- `POST .../tests/{test_id}/approve` (builder role; audited).
- Test executions are persisted with `mode="test"` for debugging, hidden from Runs by default, retention 7 days.
- Release check `workflow_tests_pass`: all approved tests pass against the snapshot; draft tests are reported but not required.

### 5.4 Tests
- Unit: assertion evaluator (every op, paths into arrays, type edge cases); mock injection; fail-closed effect table for every node type.
- Integration: single-node test, run-to-node, tests/run, approval audit row, release blocked by a failing approved test, test runs excluded from Runs and retention-cleaned.
- Determinism: run each fixture's tests 20 times; results must be identical.
- **Exit:** any node in any workflow can be tested alone, offline, with assertions; a release fails when an approved test fails.

## 6. Phase B3: durable execution

Start with a **3-day spike** comparing (a) the design below on our Postgres and (b) DBOS (a Python library on Postgres). Temporal is out of scope for now: it is extra infrastructure the bank would need to approve. The spike's deliverable is the kill-the-worker test in 6.6 passing on one prototype.

### 6.1 Model
Migration adds to `executions`: `lease_owner text, lease_expires_at timestamptz, attempt int default 0, checkpoint jsonb`. New statuses: `queued` (plus existing running, success, failed, cancelled, waiting).
New table `execution_waits(id, execution_id, node_name, run_index, kind: timer|human|webhook|subworkflow, resume_at, token_hash, form jsonb, assignees jsonb, status: open|resolved|expired|cancelled, resolution jsonb, resolved_by, resolved_at, created_at)`.

### 6.2 Worker
- Starting a run inserts the execution as `queued`. A worker loop (N per process, configurable) claims work with `SELECT ... WHERE status='queued' OR (status='waiting' AND resume_at <= now() AND <wait resolved or timer>) FOR UPDATE SKIP LOCKED LIMIT 1`, sets `running`, `lease_owner`, `lease_expires_at = now() + 30s`, and renews the lease every 10 s.
- Synchronous webhooks (`Respond` node) still wait for the result: the API awaits completion over `pg_event_bus` with the existing timeout.
- `execution_registry` stays for in-process cancel; cancel also sets a DB flag that the worker checks between batches, so cancel works across processes.

### 6.3 Checkpoints
After each batch, in one transaction: write the batch's `node_outputs` (exists), then `checkpoint = {queue: [jobs], executed: [...], run_indexes, iteration, waiting_inputs}`. Node data is not copied into the checkpoint; it is rebuilt from `node_outputs`. Resuming = load checkpoint, rebuild `node_states`, continue the loop.

### 6.4 Side effects on recovery
Recovery is at-least-once: a node interrupted mid-execute runs again. Therefore:
- Every node gets `context.idempotency_key = f"{execution_id}:{node}:{run_index}:{attempt-agnostic}"`. HttpRequest sends it as `Idempotency-Key` (opt-out per node); DataTable insert dedupes on it; Postgres/Mongo writes document it.
- Nodes with `idempotent=False` and no key support are flagged by the checker (WF010, warning) and listed in the evidence pack.

### 6.5 Features built on it
- **Suspend:** a node returns `NodeExecutionResult(suspend=Suspend(kind, resume_at, form, assignees))`; the runner writes the wait row and checkpoint, sets `waiting`, and releases the lease.
- **Wait node:** timer waits of any length (removes the 300 s cap).
- **Retry from failure:** copy successful `node_outputs`, rebuild the checkpoint with only failed jobs queued, enqueue. Fixes the re-run-everything bug.
- **Error workflows:** on terminal failure, if `settings.error_workflow_id` is set, enqueue it with an ErrorTrigger payload (execution id, failed node, error, input summary).
- **Stale reaper:** `running` with an expired lease goes back to `queued` with `attempt+1`, up to `max_attempts` (default 3), then `failed`. `waiting` is healthy.

### 6.6 Tests
- Unit: checkpoint serialise/rebuild round trip for every runner state (branches, merge waiting for inputs, loop, sub-workflow).
- Integration: suspend and resume; timer wait of 2 s through the worker; retry from failure re-runs only failed nodes (count node executions); cancel across two workers.
- **Chaos test (the gate):** start 50 runs of a 10-node workflow, kill the worker process at random points 20 times, restart; every run finishes exactly once with correct outputs; each idempotent write appears once.
- Load: 1,000 queued runs drain with 4 workers, no double claims (assert by `node_outputs` uniqueness).
- **Exit:** chaos and load tests pass in CI (nightly), unit and integration on every commit.

## 7. Phase B4: interfaces and human tasks (backend for Form, Chat, Custom UI, Approval)

### 7.1 Interface model
`workflow.settings.interface = {kind: form|chat|custom, slug, allowed_roles, title, app_id?}`. Served under `/i/{project_slug}/{slug}` behind SSO, published by releases like apps.

### 7.2 Form
- `GET /i/{p}/{slug}/schema`: generated from the trigger's declared input contract (field type, required, enum, format, description; labels drive masking hints).
- `POST /i/{p}/{slug}/submit`: validates against the contract server side, starts a run, returns `execution_id`. `GET /i/.../runs/{id}/events` (SSE) streams status and the final output.

### 7.3 Chat
- Tables `chat_sessions(id, project_id, workflow_id, user_id, created_at)` and `chat_messages(id, session_id, role, content, execution_id, created_at)`.
- `POST /i/{p}/{slug}/chat/{session}/messages` starts a run with `{message, history (last N), session_id}` through the ChatInput trigger; the answer streams over SSE. AI nodes get the session as memory (existing memory nodes).

### 7.4 Custom UI
- An app with `kind="workflow_interface"` and `workflow_id`, generated by `app_builder_ai_service` with a fixed interface contract instead of free routes.
- The generated client (`client_codegen`) exposes: `startRun(input)`, `getRun(id)`, `subscribe(id, onEvent)`, `listTasks()`, `getTask(id)`, `resolveTask(id, data)`, all typed from the workflow's contracts.
- "Promote to app" converts it to a normal app that keeps the workflow binding.

### 7.5 Human tasks (Approval node)
- Parameters: `assignees` (users or roles), `title`, `context` (expressions shown to the approver), `form` (fields; default Approve/Reject plus comment), `due`, `on_timeout: approve|reject|escalate:<role>`, `four_eyes` (default true: the run's initiator cannot resolve).
- Creates an `execution_waits` row with `kind=human`. Output ports: `approved`, `rejected`, `timed_out`; the item carries `{decision, comment, form_data, decided_by, decided_at}`.
- API: `GET /tasks?assigned=me&status=open`, `GET /tasks/{id}` (context and form), `POST /tasks/{id}/resolve` (role check, four-eyes check, form validated against its contract, audited, idempotent on double submit).
- Signed links in notifications point to the task page; they still require SSO.

### 7.6 Tests
- Integration: form schema from contract (every type); submit validation errors; SSE stream to completion; chat session history passed to the run; custom-UI client generated and type-checked (`tsc` in the test); approval approve/reject/timeout paths; four-eyes refusal; double resolve returns the first decision; a task survives an engine restart (with B3).
- **Exit:** the refund triage example has a form trigger, an approval with a custom review screen, and a chat bot, all driven through the API in one journey test.

## 8. Phase B5: spec-first workflow generation (`services/workflow_generator.py`)

Mirrors `module_generator.py` (lock per project and actor, deadline, secret scrubbing via `_scrub`, SSE events, fake-LLM scripts).

1. **Spec:** `POST /projects/{p}/workflows/generate/spec {prompt, workflow_id?}`. One LLM call that never sees a workflow returns `{summary, rules: [plain English], tests: [test cases with status draft], interface_suggestion}`. Stored in `generation_runs`.
2. **User edits and approves the spec** (`POST .../spec/{id}/approve`). Approved tests become the oracle.
3. **Build:** `POST .../generate/build {spec_id}`. Prompt grounding: node catalogue with property schemas and contracts, project facts (tables with columns, secrets by name, routes, modules, egress allowlist), expression rules, 2-3 worked examples. The model must call `emit_workflow {nodes, connections, positions, contracts}`.
4. **Validate:** static checker (B1) plus property validation. Errors go back as a repair turn.
5. **Self-test:** run approved tests in test mode with mocks; failures go back as a repair turn. At most 3 repair turns. **The repair may change the workflow, never an approved test.** If it proposes a test change, it is returned as a separate suggestion for the user.
6. **Draft:** result stored in `generation_runs.result` with checker findings, test results and a diff against the current draft. Nothing touches the workflow.
7. **Keep / Discard:** Keep writes `draft_definition`, records audit with model name, prompt hash and spec id. Undo restores the previous draft (kept in the generation run).

Table `generation_runs(id, project_id, actor_id, kind: spec|build|modify, prompt, spec jsonb, result jsonb, status, model, llm_calls, created_at)` is also the AI provenance source for the evidence pack.

The current `/api/ai/chat` stops saving directly: its "modify" path calls the same build loop with `workflow_id`, and it becomes project scoped.

**Tests:** fake-LLM scripts for valid first try, repairable checker error, repairable test failure, unrepairable (3 turns then a clear failure), attempted test change (refused and surfaced), secret scrubbing (assert no secret value in any outgoing message), lock contention, deadline. A live opt-in scenario in `tests/live/` with 5 prompts from the bank use cases, reporting call count and pass rate.
**Exit:** "triage refunds over $500 to an approver and notify the requester" yields a checked workflow whose approved tests pass, with nothing saved before Keep.

## 9. Phase B6: governance

- **Four-eyes releases:** release states `draft -> pending_approval -> approved -> promoted`. `POST /releases/{id}/approve` needs `approver` and refuses anyone who authored a change in the release (authors come from audit events since the last promoted release).
- **Evidence pack:** `GET /releases/{id}/evidence` (JSON) and `.../evidence.html` (printable). Contents: diff against the previous release, every check and test result, approvals with timestamps, AI provenance (generation runs, models, prompt hashes), side-effects inventory (egress hosts, tables written, secrets referenced by name, non-idempotent nodes), data labels crossing boundaries, and a sha256 of the whole pack stored on the release.
- **Shadow replay:** `POST /releases/{id}/shadow {sample: 200}` re-runs the candidate on recent real inputs in test mode, with egress mocked from the outputs recorded in `node_outputs` for the original run; returns per-run output diffs. Runs whose external calls differ from the recording are reported as "not replayable". Needs `node_outputs` retention long enough (configurable per project).
- **Data labels:** `data_tables.columns[].labels` and `x-labels` on declared contracts; labels propagate through derived contracts. Project policy `settings.data_policy = {label: {allowed_hosts, llm_allowed: bool}}`. Checker code WF011 (error) when a labelled field reaches a disallowed host or LLM; also a release check.
- **AI node evals:** tests with `kind: eval` on AI nodes: fixed inputs, deterministic checks (schema, contains, enum) plus an optional LLM-judge rubric. The model id is pinned in node params; a release check fails if the model changed since the evals last passed.

**Tests:** author cannot approve; approval audit; evidence pack snapshot test (stable ordering, hash verifies); shadow replay on fixtures with a deliberately changed branch shows exactly that diff; WF011 propagation through Set/Merge/Filter; eval re-run required after a model change.
**Exit:** a release of the refund example produces an evidence pack a reviewer can read end to end, and cannot be promoted by its author.

## 10. Phase B7: reuse

- `ExecuteWorkflow.version = draft | latest | pinned:<n>`; release snapshots follow references and pin children; cycle detection at save (WF012); child contract = its trigger's input schema plus a new `Return` node's output schema; release check flags a parent whose pinned child changed its contract incompatibly.
- Templates: versioned JSON bundles in the repo (`templates/<name>/`: workflow, tables, interface, tests). `POST /projects/{p}/templates/{name}/instantiate`. Each template's tests run in CI.

**Tests:** pinning in releases, cycle detection, contract compatibility, each template instantiates and passes its own tests.

## 11. Phase B8: connectors

- One-file node scaffold: a node module registers itself (type, description, contract, side effects, egress hosts, mock fixture). The registry list, exports, trigger list (`services/workflow_service.py:442`) and SDK exposure read from the registration.
- Order follows the pilot: likely Teams, Outlook/Exchange, ServiceNow, SFTP, SQL Server/Oracle, SharePoint. `SendEmail` is finished or hidden.
- Each connector ships: contract, side effects and idempotency, secrets through `$vars` only, egress entry, a mock fixture for test mode, an example workflow, unit tests with a recorded HTTP fixture, and one integration test against a local fake server.

## 12. Testing strategy (all phases)

| Layer | Tool | Runs | Notes |
|---|---|---|---|
| Unit | pytest `tests/unit` | every commit (~2 s today; keep under 10 s) | Pure functions: contracts, checker, assertions, checkpoint codec, role matrix |
| Golden fixtures | pytest snapshots | every commit | Checker output and evidence packs on `tests/fixtures/workflows` |
| Integration | pytest + Postgres :5433 | every commit | One file per phase: `test_b0_identity.py` ... `test_b8_connectors.py` |
| Journeys | `tests/integration/journeys` | every commit | One end-to-end API journey per phase, using the refund triage example |
| Chaos and load | pytest marker `chaos` | nightly | B3 kill-the-worker and 1,000-run drain |
| Generator | fake LLM scripts | every commit | Deterministic loop behaviour |
| Live | `tests/live/*` | opt-in, billable | Real LLM; report call counts |
| E2E UI | Playwright | when the phase's UI lands | Existing stack; one run at a time under `flock` |

Rules:
- A phase is done only when its exit criteria pass, the full engine suite and existing e2e stay green, and lint is no worse.
- Every bug fixed gets a regression test in the same commit.
- Every migration has a test that applies it to a copy of the previous schema with seed data, and a downgrade note.
- New endpoints are added to the route-enumeration auth test (B0) automatically.
