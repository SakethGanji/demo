- `defs.tsx`: `<ArtDefs id/>` (brand gradient, fade, glow, dot pattern, radial mask). Use `useId()` so ids are unique per instance; the mockup hard-codes `sys`/`thumb`/`rel` ids, which collide if two arts render.
- `pulse.ts`: a port of `LunaArt.pulse(path, {color: 'brand'|'warn'|'secret', delay, duration, r})`. It uses rAF + `getPointAtLength`, takes its easing from `--ease-io` via the bezier solver, rate-limits each path with a 280ms gap, cleans up within D+120ms, and on reduced motion flashes the stroke once.
- `useArtPulse(rootRef)` returns `pulseWire(name, opts)` for `[data-wire=name]` inside the root (replaces `pulseWire('system','post')`).
- `art.css` (or `@layer components`): the `.a-wire .a-hot .a-warn .a-solid .a-card .a-label .a-mono .a-strong .a-pulse` styles. All colours are tokens.

**`LunaArt.pulse` → an event-driven hook.** Packets mean "a real event happened", never decoration. Add a tiny bus, `shared/lib/studioEvents.ts` (zustand or `EventTarget`): `emit('run', {routeId, method, appId, status})`, `emit('row-write', {table})`, `emit('secret-set', {key, env})`. Sources:
1. Mutation `onSuccess` (route test Send, `useInsertRow`, `useCreateSecret`/`useUpdateSecret`, release promote).
2. A polling diff: when `useRecentRuns`/`useProjectSummary` refetches, new run ids since the last fetch emit `run`.
3. `useExecutionStream` node events in the workflow editor.

`useStudioEvent(type, handler)` in each art component calls `pulseWire(...)`. The "hello" pulses on arrival run in a mount effect. `secretAdded` (dashed amber wire turns solid with an amber → green packet) should be **state-derived**: the wire is solid when the secret isn't missing, and the packet fires on the missing → set transition (`usePrevious`). The cross-page `cs:secret-added` CustomEvent then disappears; the query invalidation handles the sidebar tail and the overview at once.

**Other motion:** a page-enter fade + 2px rise on `main > *` (`motion.css:12`); new rows `m-new` (height 0fr → 1fr, a flash); button `scale(.98)`; `m-swap` copy → check icon. Use the `--d-*`/`--ease-*` tokens everywhere. `motion` (the library) is fine for `layoutId` pills and thumbs, but always respect `prefers-reduced-motion` (`useReducedMotion`).

**Edges** (`edges.js`) → `shared/components/edges/`: `<GutterMarks/>` (registration `+` marks where gutters cross, measured from the panels with a ResizeObserver, mounted in `WorkspaceLayout`), `useEdgeField(hostRef, fromRef, opts)` (grid + ruler in the empty space below the content, hidden when under 40px), `<Leader/>` and `<RegMark/>`. All are `aria-hidden` with `pointer-events:none`.

## 6. Risks and gotchas

1. **Global syntax classes `.k .s .n .f .c .d`** (`ui-redo/assets/components.css:193`), plus `.sep` and `.empty`. Don't port them. Real code uses CodeMirror (`ui/code-editor.tsx` reads `--syn-*` and rebuilds on a `class` MutationObserver) or `json-viewer.tsx`. If hand-highlighting is needed, scope it (`.syn-k`). The mockup's other global names also collide with Tailwind utilities: **`.table`** (= `display:table`), `.grid`, `.hidden`, `.truncate`, `.collapse` (= `visibility:collapse`). Translate them into cva/Tailwind; never paste the mockup CSS.
2. **`@property --kit-lap` and masks.** `@property` must live outside `@layer` in `index.css`. `.vx-edge` relies on `mask-composite: exclude` / `-webkit-mask-composite: xor`. Tailwind v4 runs Lightning CSS, which may rewrite or prefix the `mask` shorthands, so check the built CSS in Chromium and WebKit. The beam needs a ResizeObserver; guard it against "ResizeObserver loop" errors (batch in rAF).
3. **Tooltips.** Today there is no provider, a different look (arrow, `px-3`) and the default BUI delay. The mockup is a single tooltip with a 500ms delay and a 300ms warm window, placed below when the trigger is within 70px of the top. The `Tip` wrapper plus `TooltipProvider` covers that. Don't nest `TooltipTrigger` around Popover or Menu triggers without `render` composition (UI-DESIGN §1.1 "nested-trigger" note).
4. **E2E (`apps/workflow-studio/e2e`)**: 7 specs, **43 tests** (01:4, 02:10, 03:12, 04:5, 05:5, 06:5, 07:2), **174 distinct `getByTestId` ids**. The most used are `test-send` (16), `test-response`/`status-pill` (12), `code-editor` (9), `run-row` (6), `composer-result` (6), `test-route-picker` (5), `req-body` (5), `composer` (5), `trace` (4), `overview-panel` (4), `data-row` (4), `run-sheet` (3), `outline-overview` (3), `theme-toggle` (2), and the `outline-*`/`setup-*`/`composer-*`/`publish-*` families. Attribute and class couplings:
   - `status-pill` `data-status` **and `toHaveClass(/text-warning-text/)`** (`02-backend-manual.spec.ts:27`).
   - `[data-method]` (MethodBadge).
   - `[data-kind="auth_loosened"]`.
   - `data-pressed` (BUI Toggle), `data-checked`, `data-state`, `data-done`, `data-viewing`, `data-passed/total`.
   - CodeMirror classes `.cm-content`, `.cm-line`, `.cm-tooltip-autocomplete`, `.cm-lint-marker-error`.
   - Toast text via `getByText`.
   - **T44 (`01-shell.spec.ts:107`) hard-codes the dark body `rgb(17,17,17)` and `overview-panel` `rgb(28,28,28)`.** Graphite changes both, so update the test with the tokens. If the overview becomes a bento, `overview-panel` must stay on the scrolling container.
   - Moving the run detail inline must keep the `/runs/$executionId` route and the `run-sheet` testid (or update 3 call sites).
5. **Layout policy** (`e2e/fixtures/layout.ts`, run after every UI test and at 1280 and 1024 in T45). Every `[data-testid$="-panel"]` must not scroll horizontally, and its buttons and tabs must be at least 90% inside it. Absolute decorations (`.vx-beam` is 720px wide, edge fields, gutter marks, beam overflow) must be clipped (`overflow:hidden` or `contain: paint`) or sit outside `*-panel` elements. Don't name new wrappers `*-panel` by accident.
6. **Console policy**: any `console.error`/`warn`, `pageerror` or React "Warning:" fails a test. `e2e/console-allow.ts` is empty and must stay empty. Watch for:
   - Missing `key`s in mapped art.
   - BUI `nativeButton` warnings when `render` swaps the element (`button.tsx` already handles this).
   - motion warnings about animating non-animatable values.
   - Duplicate SVG ids from art defs.
7. **`contrast.test.ts`** (`src/shared/theme/__tests__/`) parses the literal `:root {` and `.dark {` blocks in `index.css` and requires hex values for `card`, `method-*`, `warning(-text)`, `success(-text)`, `ai`, `ai-text`, `syn-*`, `code-bg`, `code-gutter`, with `ai-soft` as a `color-mix(… N% …)`. It must stay green: put the final light values in `:root` itself, **not** `html:not(.dark)` as `paper.css` does, and keep those tokens as hex, not `rgb(var(--ink)/α)`. Re-check the minimums with the new indigo method-post (`#4b55c4` in light).
8. **Data the backend lacks** (raise it before building): 30-day daily counts; a runs time range; anything over the 100-run retention; per-project 24h buckets on the home page; column aggregates and sums; route→table read/write mapping; bulk insert for CSV; per-step AI I/O and token streaming; sandbox start time for the waterfall; a structured traceback; a push channel for new runs.
9. **The mockup's demo timers** (`setTimeout(send, 1500)`, the auto-AI run after 2s, `liveRun` at 1.4/2.8s in `motion.js`) are demos only. Don't port them.
